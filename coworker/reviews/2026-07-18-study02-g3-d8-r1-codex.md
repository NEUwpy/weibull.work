## 阻塞发现

### 1. 真实冻结矩阵的 placeholder 无法解析

当前 resolver 仅支持 `selected:<exact decision_id>`，测试也只使用 `selected:architecture:A-E1:F2:n10` 这类合成 exact id。真实矩阵使用：

- `selected_top_1..4`
- `selected:A-E1_loss` / `selected:A-E1_architecture` / `selected:A-E1_optimizer`
- `selected:F2_or_V`
- 下游 `selected:A-E3_*` / `selected:A-E3_baseline` 等

而现有 A-E1 trace 只包含 route-specific `architecture:*` 与 `stage2:*` 决策，没有 `A-E1_loss` 或 `F2_or_V` exact decision。执行者已正确 fail-closed，但这意味着真实矩阵仍不可运行，未达到本棒 Goal。

### 2. 缺少 staged selection 与派生决策

冻结依赖要求：stage1 architecture ranking -> `selected_top_1..4` -> stage2 architecture/optimizer selection -> winner retrain -> F2-vs-V `global_better_rule` baseline。当前没有 production staged orchestration、不可变 stage resolution 记录或 baseline-input 派生决策；仅增加通用 resolver 不能生成这些权威结果。

### 3. deferred reconstruction 仍不是可训练 spec

`reconstruct_deferred_specs` 只复刻 scheduler 已有的 unresolved `study02-formal-deferred-dataset-v1` cache-key 绑定，返回的 route 仍可为 `selected:F2_or_V`，且没有调用 `build_training_spec`/`build_validation_spec` 生成 concrete `FormalDatasetSpec`。`frozen` 参数未参与重建。它验证了“占位计划没有漂移”，但不能执行 A-E3/A-E2。

### 4. 没有生产调用点

三个新增入口目前仅由测试调用；runner/scheduler/CLI/run_module 均未接线。`build_module_pre_unseal_bundle` 也没有真实生产调用点。因此报告中的“production wiring completed”不成立。
