本研究保留两个问题：报告1解释高形状参数下的估计偏移，报告2解释小样本中的明显异常估计。两者可以共享机制，但分别组织论证。

当前保留13个参数组合；每组n=7、15、30各50份样本，共1,950份样本、15,600条估计（MDM三个δ与其余五类方法）。每组结果为1份工作簿和11张PNG；报告所用补充实验、过程数据和图片分别在交付内的“报告1”“报告2”目录。

原8组沿用不同历史种子及各自补充的n=30；新增5组使用20261004种子，同一n和组号跨β、η共用潜在指数变量。13组属于历史案例集合，不能把跨批差异解释为统一配对实验，也不合并不同抽样协议的有解率。有解率沿用工作簿的有限成功展示规则，另行保留支持边界诊断。

## 方法口径与统一方案

统一的判断依据是**所选原文的具体方法分支、现有方法文档和实际Python实现三者相符**。出现冲突，先核对原文公式、参数范围和构造，再区分公式错误、不同方法分支和数值实现差异；不以任一现有文档或程序自动压过原文。报告引用方法定义，研究该过程怎样影响估计结果。

本轮已查清版本和主要差异；MLE、WMLE的条件诊断已统一调用[方法系统函数](../../python/methods/conditional_profiles.py)，并更新两份报告、相应过程数据及三张MLE图（第四张核验后保持原字节）。共享联合估计器和13组的原估计保持原身份；其余方法的诊断仍待统一。

| 方法与文档 | 报告实际使用的口径 | 原文入口与统一判断 |
|---|---|---|
| [MDM](../../src/content/algorithms/mdm.md) | 同一程序；报告1主用δ=0.10，报告2保存0.10/0.15/0.20，机制重点为0.20 | [182-046原文](../../src/content/182-046-pdf原文.md)。固定γ下先最小化伪尺度标准差，再按条件最小标准差的梯度与δ定位，η为伪尺度均值；不能概括成β、γ联合最小化。原文精确中位秩与当前默认Bernard近似、形状搜索域及差分规则须明确区分。右端回退不等同于找到梯度交点，“始终有解”需要修正。 |
| [LSE](../../src/content/algorithms/lse.md) | 两报告及当前共享程序相同 | [182-104原文](../../src/content/182-104-pdf原文.md)。White对数顺序统计量期望加Soman–Misra三参数F比定位；回归ln(x−γ)=a+bz，β=1/b、η=exp(a)。 |
| [LRE](../../src/content/algorithms/lre.md) | 报告1主分析及原8组为Bernard；新增5组为Park；当前共享程序为Park | [Park原文](https://doi.org/10.23055/ijietap.2017.24.4.2848)。参考坐标由绘图位置得到，回归z=a+b·ln(x−γ)，β=b、η=exp(−a/b)。历史Bernard是已采用的分支；新计算可明确选Park，原结果不改名冒充Park。 |
| [MLE](../../src/content/algorithms/mle.md) | 两报告及共享程序相同：标准似然、多初值联合搜索，收敛且β≥1的候选才接受 | [182-105原文](../../src/content/182-105-pdf原文.md)是数值基准；不声称复现完整Hirose流程。本批接受β≥1、η>0、0≤γ<x₍₁₎；两报告的条件曲线保留β=1边界并重算η。当前联合搜索仍是搜索后剔除β<1；诊断不冒充正式受约束求解。 |
| [WMLE](../../src/content/algorithms/wmle.md) | 同一Cousineau加权方程、J1/J2/J3表及求解程序 | [182-088原文](../../src/content/182-088-pdf原文.md)。条件诊断统一0<β<10与同一权重函数，无T1零点则留空。J3在β>5沿用端点是本批工程近似，不能视为原文大形状权重；条件T1零线不替代联合求解轨迹。 |
| [MMLE](../../src/content/algorithms/mmle.md) | 报告2为Kundu–Raqab单样本形式；报告1未纳入；13组与共享程序相同 | [Kundu–Raqab原文](https://doi.org/10.1016/j.spl.2009.05.026)。已存在，无须重新建设估计器。γ取原最小值并删除一个最小观测，保留距离上迭代β、按n−1恢复η；支持检查用保留样本的x₂。旧mmle_ch是另一个构造。 |

**MDM的差别**：δ不同是实验配置差异；原文与程序的秩近似、差分、搜索范围和边界回退是实现差异；两报告各自编写的条件曲线则属于诊断层差异。三种差异不能混成“方法公式不同”。MDM/LSE/MLE/WMLE/MMLE冻结文件与当前共享文件逐字节一致；LRE保留两个明确的版本身份。

后续统一按以下顺序开展，避免把不一致的公式简单写进方法文档：

1. 对上述冲突核对原文，并在现有方法定义中确定正确公式、变体及实现差异；公式符号、计算流程、过程量名称和图轴含义一起确定。
2. 已在`python/methods/conditional_profiles.py`合并MLE、WMLE条件诊断；后续再提取其余准则评价函数及对接求解器、过程记录。新估计继续走`registry → run_method()`。固定候选评价、条件最优剖面和真实搜索轨迹分别输出。
3. 方法文档连接原文和函数，报告连接方法文档；图轴与符号读取同一方法定义。补MMLE步骤标注、LRE实际trace、生效配置及支持检查等现有缺口。
4. 用当前冻结样本及过程数据对拍后再改两份报告；涉及方法规则变化时另算对应结果，历史数据保留原身份。

## 复现入口

[运行交付.py](交付/程序/运行交付.py)默认只核对，不生成样本或估计。13组的路径、版本与矩阵哈希集中在[13组合取数.json](交付/程序/跨参数对比/13组合取数.json)；每组保留生成所需的输入、增量缓存、配置和方法快照。各组`运行本组.ps1`提供对应参数的独立入口。

在项目根目录执行：

```powershell
python/.venv/Scripts/python.exe -B Research/00-方法对比/交付/程序/运行交付.py verify
python/.venv/Scripts/python.exe -B Research/00-方法对比/交付/程序/运行交付.py generate --group W2,1000,3000
python/.venv/Scripts/python.exe -B Research/00-方法对比/交付/程序/运行交付.py report1
python/.venv/Scripts/python.exe -B Research/00-方法对比/交付/程序/运行交付.py report2
python/.venv/Scripts/python.exe -B Research/00-方法对比/交付/程序/运行交付.py cross
```

`generate`复用冻结输入和已有缓存，重建对应工作簿及分布图；估计通过原批次runner调用冻结Python方法。保留缓存时不重抽样、不重新拟合。报告绘图使用已保存的样本、估计及条件过程数据，不替换估计。程序所需的数据已收进交付，不再读取被删除的批次目录；本机Python/Node依赖路径在`共用.py`和入口中。`R00_OUTPUT_DIR`可指定另一个结果目录，试运行前先复制当前结果作为诊断数据及已有九张梯度图的输入。

报告2的MDM图15、16以γ—条件η替换c、f，逐个γ取原程序的条件最优β及伪尺度均值；[本次脚本](交付/程序/报告2/20261010-MDM条件尺度图.py)可独立运行，也已接入`report2`入口。曲线数据和核验记录与脚本同目录，原样本与估计保留。
