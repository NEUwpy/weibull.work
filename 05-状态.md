| 第一层 | `backend`（后端算法）、`tests`（算法测试）、`calculator`（计算器接入）、`theory`（公式及原理）、`process`（程序流程） | 方法可信可用的最低门槛 |
| 第二层 | `calculation`（计算过程）、`analysis`（结果分析） | 详情页交互与解读 |
| 第三层 | `applicability`（适用范围证据）、`verification`（可信性验证） | 适用范围的实验覆盖与论文复现 |

专项论文（`paper`）与第一层五项并列，是第一层闭合的必要条件。

`applicability` 记录方法的适用范围证据。相关展示归入[结果分析](docs/建设规范/02-参数估计方法/04-结果分析.md)。

## 自动层级推导

总体层级不得人工填写，由 `scripts/lib/method-status.mjs` 按原子状态连续推导：

1. `layer1_complete`：专项论文与第一层五项全部完成；
2. 计算器公开严格等于第一层完成（`calculatorEnabled`）；
3. `layer2_complete`：第一层完成且第二层两项完成；
4. `closed_loop`：前两层完成且第三层两项完成；
5. 后续层可提前施工，但总体成熟度不跨过未闭合的前置层；
6. 全部原子项为 `todo` 时显示 `not_started`，否则未闭合第一层的方法显示 `layer1_in_progress`。

「方法对比」是平台级能力，不参与单方法闭环。

## 证据要求

- `done` 必须列出真实存在的文件或目录路径（仓库相对路径）；外置论文使用 `/library/<编号>` 阅读路由，题录保留在本表；外置结果使用已实现的分片或结果API，构建只检查受限路由及其实现，实际资料由运行数据目录提供；
- 声明后端完成的方法必须能通过 `run_method` 返回估计值，注册占位（`NotImplementedError`）与纯别名不算实现；
- 共享核心（`shared_core`）必须指向真实核心模块，且本方法仍需独立执行分支和独立测试；
- 181-004（`/library/181-004`）只作分类与文献线索，不单独充当任何方法的专项论文。

## 论文交接

缺少合格专项论文时，在 `paper.reason` 中记录 `PAPER_NEEDED` 并保持 `blocked`，同时在执行报告中提交论文请求（方法、需要的论文类型、已知线索、用途、仍可继续的工作）。论文材料由用户处理，不得以综述、博客或 181-004 替代。

## 生成缓存

```powershell
npm run generate:method-status   # 从本文档生成 src/data/method-status.generated.json
npm run check:method-status      # 校验缓存与本文档一致（prebuild 自动执行）
npm run test:method-status       # 解析与推导单元测试
```

`src/data/method-status.generated.json` 是只读生成物，禁止人工编辑；页面组件只读取该缓存，不得另行维护状态数组。
