# 机制图的公式与字体规范

本规范适用于报告上篇 v2.0 当前使用的全部图：五张机制细图、五张信息处理流程图和一张完整机理地图。后续新增或修改的图继续遵守；历史归档保留原貌。

## 图像表达与画幅

以下为2026-10-23确认的总图与分路线图要求，适用于当前11张图及后续制图。

1. **图面专注机制表达。** 用数据点、曲线、分布、坐标、变换、公式、箭头及必要的节点标识讲清“输入什么—怎样转换—得到什么”；方法差异落在相应环节，方法联系用有方向或有类型的线表达。
2. **去掉防御性备注和赘余文字。** 图题放在正文图注；总图的箭头线型、颜色及比较实现标记说明也放在图注，图内只保留各路线的区域名称。图内不放“仅作示意”“不是某种方法”“不代表某项结论”“仍须另行核验”等解释段落，也不放来源段落、制作说明、审阅提示或重复标题。必要的解释、出处、数值示例背景和适用边界移至正文、图注或本目录的核验说明。
3. **保留读图所必需的文字。** 方法名、简短动作、输入输出、坐标与单位、公式、公式成立的必要条件，以及直接对应对象的短标签属于图本身；总图统一图例置于图外。删备注不能把科学条件删成无条件结论；复杂条件在图上用简短条件式标出，并在图注完整解释。
4. **统一横向画幅，高∶宽以7∶16为宜。** 默认宽3200、高1400；内容较多的总图可等比例增大。主流程从左到右，分支沿对应环节展开。通过重排、删冗余和调整分区获得画幅，不把竖图压扁、不拉伸字形，也不靠大面积空白凑比例。
5. **以图形承担解释。** 总图突出五条路线、跨路线估计过程和有依据的方法关系；分路线原理图突出机制连续过程，方法细图突出具体构造与改动位置。图内不写整段讲稿，不把图变成文字表格。
6. **源图与审阅一致。** 同步可编辑draw.io与矢量SVG，正文直接嵌图；公式继续使用LaTeX标准排版，英文及拉丁数学字形使用Times New Roman，中文使用微软雅黑。逐张检查遮挡、连线、公式、画幅和缩放后的可读性。

### 总图的浅色路线分区

总图用五种低饱和浅色背景划出路线范围，背景覆盖共同机制及完整采用该机制的方法，区域间留出清楚的白色间隔。颜色通过连续区域表达路线归属，不只涂标题条或方法边框。

跨路线估计方法放在区域之间，或按实际阶段连接不同浅色区域。Cohen–Whitten、Park Proposed+MLE2、Yang迭代、Mixed、初始失效期迭代及LSPF的组合步骤须分别辨认；完整过程不能被一个色块包入。LPF的V联合似然估计及后续似然方程仍体现似然机制；GM–SVR属于当前样本的变换回归；贝叶斯后验中的似然是该框架的组成部分。MVLE-H扩展对WMLE的临时形状策略借鉴以借用线表达，不据此新增似然估计阶段。PSO／SA／DE放在路线区域之外，连接其服务的具体目标。

## 每条路线的两图结构

首图只讲图像化核心机理；第二图顶部为同一机理的精简横向步骤，底下以小图说明各方法的实际构造及差别。回归方向、概率间距、分布曲线面积、矩差、秩权重、点列标准化、密度峰、组合权重等优先用图形表达；必要公式随图，不做公式墙。总图仅承担路线、方法位置与方法联系的导航。方法标识与年份、作者口径统一使用[方法名称与年份口径](方法名称与年份口径.md)。

## 路线与方法的关系

2026-10-22起，按“参数估计方法的路线图”组织图示。五条路线解释估计机制，不要求每个方法只有一个主要归属。单一路线方法可以集中展示；跨路线方法按统计量构造、参数消除、分阶段估计或组合准则展开，标明各步的信息、确定原则与参数输出，再连接相应路线。

方法内部的阶段连接、方法间历史沿袭、数学联系和局部借用分别标明，不把跨区域连线一律解释为继承。LSPF须区分W不变统计量构造、W联合密度最大化、位置修正与尺度恢复，避免“使用统计量就归入统计关系路线”的误读。可以突出解释核心创新的机制，但不把选出唯一类别作为制图前提。

v2.0在保留有效公式、样例与渲染管线的基础上落实上述图示调整。五条路线的完整定义与正文安排以[方法分类README](../README.md)为准。

## 流程阅读顺序

信息处理流程按从左到右的单行顺序展开，按实际内容使用三步、四步或五步，并依次排列①→②→③→④→⑤。相邻步骤用水平箭头衔接，避免将步骤排成左一、右一、左二、右二的两行顺序。同一步内的图像、公式与短说明可上下安排；调整画幅和局部内容时保留足够字号，不通过压缩整图把横排硬塞进原框。

## 原理与实现的层次

每条路线的图先表达其核心估计机制，再从对应环节引出具体方法。检查图是否讲清：构造了什么统计对象，哪个准则或理论关系决定估计值，各步之间怎样转化。流程框和箭头本身不能代替这些内容。代表性原型与路线共同机制分别说明，主图、机制细图和总图沿用一致的机制标识；方法间沿袭线另外依据原文标注。

原理主图应解释这条路线怎样把样本信息转成估计值。似然路线以整体函数 $L(\beta,\eta,\gamma;D)$ 为主体：固定数据后，三个参数作为坐标，似然值作为颜色或等值面编码的第四个量，展示联合目标的变化及最大化。密度乘积交代函数构造，不占据主图的大部分；具体求根、剖面或优化算法留在细图或支撑说明。

多参数函数的三维可视化应明确：固定的样本、各参数轴及缩放、显示的有限参数窗、函数值如何由颜色或等值面编码、数值极大点的范围和实际迭代轨迹。对数或相对似然重标须给出定义并保留极值位置；使用真实联合函数采样生成等值面，注明网格插值近似。等值面不是自动得到的置信域或后验概率。固定部分参数的截面可以作辅助，不能替代展示整体三参数函数的主图。

参数场三角面采用draw.io原生内联stencil，保留可编辑的矢量图形；生成程序与SVG预览使用相同的投影顶点和透明度。格式依据见[draw.io Shapes and Stencils](https://github.com/jgraph/drawio/wiki/Shapes-and-Stencils)。

## 公式

所有公式和数学变量使用 LaTeX 或等效的标准数学排版。draw.io 开启数学排版，源文本中的公式写为 `\(...\)`；独立数学段也可使用 `$$...$$`。分式、上下标、求和、连乘、积分、偏导、帽号、条件概率及优化下标应由排版器生成，不能用普通文字拼出类似公式的外观，也不能让 LaTeX 指令直接出现在预览中。

例如，尺度估计写成 `\(\hat{\eta}=[\frac{1}{n}\sum_{i=1}^{n}(x_i-\gamma)^\beta]^{1/\beta}\)`；参数下标、估计帽号和分式均须实际渲染。方法简称 MLE、WMLE、MAP 等仍作为普通英文名称。

只改变排版时应保持公式的数学含义、适用条件、变量定义及方法关系。分式或上下标增高后，优先增加局部公式框的留白，再检查流程与连线，避免靠缩小全部文字挤入原框。

## 字体

图中的英文、数字及拉丁数学变量使用 **Times New Roman**；数学变量按惯例使用斜体，函数名、运算符及方法简称使用正体。中文使用微软雅黑。大运算符等 Times New Roman 缺少的专用数学字形可使用数学字体补充，不能因此将整段英文换成其他字体。

字体要求同时作用于 draw.io 源、生成程序与静态预览。不能只修改字体声明而保留错误渲染。SVG 交付时将实际排好的字形保存为矢量轮廓，防止另一台电脑缺字体而改变显示；需要编辑文字或公式时回到 draw.io 源和对应生成程序。

## 生成与核验

在项目根目录运行本目录的 `生成机制图.ps1`。该入口依次生成 11 张 draw.io，再运行 `生成预览图.py`。环境需要 Python 的 PyMuPDF、Node.js 的 KaTeX 与 Playwright，以及可用的 Chromium 和本机 Times New Roman 字体；当前脚本兼容 Codex 捆绑的 Node 依赖目录。

渲染链为：显式 LaTeX → KaTeX 编译 MathML → Chromium 标准数学布局 → 矢量 PDF → SVG 字形轮廓。PDF 仅用于临时中间步骤；正式文件仍为可编辑 draw.io 和可直接嵌入报告的 SVG。`数学排版.py`提供数学段识别和遗漏检查，`渲染数学标签.cjs`负责标准数学布局及字体，`生成预览图.py`保留图形结构并输出预览。

每次生成后检查：

1. 全部公式解析成功，图中没有原样显示的 LaTeX、文字式上下标或未排版等式。
2. 逐图检查分式、求和上下限、根号、估计帽号和条件符号；检查边界、文字遮挡和连线标签。
3. `预览/排版核验.json`记录每图数学段数、实际嵌入 PDF 的字体以及异常缩小的标签。确认英文字形使用 Times New Roman，并逐一处理 `small_labels`，不能把字体声明当作实际使用证据。
4. 核对 11 个 draw.io 的节点 ID、连线端点、画幅和报告引用；完整地图保留原30项证据ID，区分28项方法间关系、2项方法内部机制说明及新增机制骨架。
5. 将全部 SVG 同步到原 HTML 审阅任务的 `assets/`，在页面直接嵌入，检查图片加载和放大阅读。同名图片替换后刷新原审阅标签，并核对实际显示的新布局与图片尺寸；轮次文字已更新不代表浏览器已重新加载图片。源文件、预览、核验记录与说明一并纳入 Git。

脚本检查不替代看图。排版核验通过后仍须逐图查看预览，特别是含有多层分式和求和的区域。
