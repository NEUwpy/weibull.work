# 03 论文骨架

> 本文件不是章节目录，而是论文的论证合同。
> 它回答三件事：整篇论文如何建立论证；每章要达到什么逻辑效果；每章用什么证据或叙述手段把问题推向下一章。
> 实验细节看 `02-实验协议.md`；证据状态看 `01-证据索引.md`。

## 工作题目

三参数 Weibull MDM 偏移量的层级优化与样本自适应选择

## 一句话论证

本文接续 MDM 前两篇工作，把经验 offset `delta = 0.1` 从一个有效但经验性的设置，推进为一个可分层定义、可量化评估、可讨论部署边界的决策问题；正式 E1/E2 先证明简单可部署层级难以系统超越 `0.1`，再定位 oracle 层级中的真实改进空间，后续 E3/E4 检验样本可观测信息能否在部署条件下逼近这种空间。

## 总体论证链

```text
三参数 Weibull 小样本估计困难
  -> MDM 已由前两篇工作提出，且第二篇引入 delta = 0.1 的 offset 判据
  -> 但前作只证明 0.1 有效，没有系统回答 delta 的最优性
  -> “最优 delta”不能脱离信息条件，必须先定义信息层级
  -> E1 检验最简单可部署层级：全局常数 L1 与按 n 查表 L2
  -> E1 若显示 L1/L2 收益极小，则说明 0.1 是强基线，同时把问题推向更高层级
  -> E2 检验 L3-L6 oracle / hindsight 层级，定位真正改进空间和边际递减点
  -> E3 检验真参数不可见时，样本可观测特征能否逼近 oracle 参照
  -> E4 说明边界、稳健性、失败处理和部署成本
  -> 论文给出固定 0.1、简单查表、样本自适应三种使用层级的实践含义
```

## 章节串联原则

每一章都必须完成一个局部逻辑功能：

1. **目的**：本章要准确建立什么判断，或完成什么逻辑功能。
2. **手段**：通过什么叙述、证明、实验、图或表支撑这个判断或功能。
3. **递交给下一章**：本章结尾留下什么必然问题，使下一章不是并列出现，而是被前一章推出。

章节不能只写“本章介绍什么”。如果一章不能明确递交给下一章，它就应该被合并、移动或改写。

## 章节论证合同

### Ch1 Introduction

**目的**：

准确建立：本文不是重新比较 MDM 与 MLE/LSE，也不是一篇以 NN 为中心的机器学习论文；本文的核心缺口是 MDM 第二篇工作留下的 offset 选择问题。

**手段**：

- 先建立三参数 Weibull 小样本估计的应用背景和估计困难，点到为止，不展开一般方法史。
- 公平交代 MDM 前两篇工作：第一篇提出 minimum discrepancy method，第二篇用 `delta = 0.1` 改善 `gamma` 搜索稳定性。
- 引出关键空白：`0.1` 是经验值，且原文承认更适当偏移值可能与分布特征和样本大小有关。
- 用本文主问题收束：`delta` 是否存在最优值，最优值在哪个信息层级上定义，不同层级能改善多少，部署时如何接近更优值。

**递交给下一章**：

读者已经知道 offset 是一个未完成问题，但还不知道 offset 在 MDM 内部到底作用于什么环节。下一章必须解释 MDM 和 `y = delta` 判据，证明这个问题不是外部调参，而是 MDM 搜索判据本身的后续发展。

### Ch2 MDM and the Offset Question

**目的**：

准确建立：研究 `delta` 的最优性是 MDM 方法内部的自然延伸，而不是对原方法的任意附加优化。

**手段**：

- 简明说明三参数 Weibull、伪尺度估计量、最小差异搜索和 `gamma` profile 搜索。
- 对比 `y = 0` 与 `y = delta`：前作用小正偏移改变搜索判据，以避开有限样本下局部平坦谷底附近的不稳定。
- 明确边界：本章不重新证明 MDM 整体优于其他估计方法，只说明 offset 判据为什么值得被系统研究。
- 引用 182-030 和 182-046 核对术语、公式和原文语境。

**递交给下一章**：

既然 `delta` 是搜索判据中的决策量，下一步不能直接问“最佳数值是多少”，而必须先问“在什么信息条件下最佳”。下一章因此定义 L1-L6 信息层级和正式实验协议。

### Ch3 Experimental Design

**目的**：

准确建立：本文所谓“最优 `delta`”不是单一概念，而是随可用信息层级变化的决策问题；只有先定义层级，后续结果才有可比性。

**手段**：

- 提出 Default / L1-L6 信息层级，从固定 `0.1`、全局常数、按 `n` 查表，到按真参数 oracle 和逐样本 hindsight。
- 定义正式实验映射：E1 对应 Default/L1/L2，E2 对应 L3-L6，E3 对应样本自适应，E4 对应边界与稳健性。
- 说明主指标 J1、参数网格、`delta` 网格、E1/E2 共用 MC 扫描数据、manifest 和输出产物要求。
- 用 Table 1 承接参数网格和指标合同；用 Figure 1 展示 offset 判据或 L1-L6 框架。

**递交给下一章**：

层级定义完成后，最自然的第一问是：在最简单、最可部署的信息层级上，经验值 `delta = 0.1` 是否已经足够好。下一章从 L1/L2 开始回答。

### Ch4 Is `delta = 0.1` Optimal? L1 and L2

**目的**：

准确建立：在全局常数和按 `n` 查表这两个简单可部署层级上，`delta = 0.1` 是一个很强的基线；改进空间不可能靠另一个简单常数系统解决。

**手段**：

- 用 Formal E1 的全局 `delta` risk 曲线证明 `0.06-0.12` 附近风险很平坦，`0.1` 落在全局低风险平台。
- 用 Table 2 比较 Default、L1 和 L2 的 J1，报告 L1/L2 相比 Default 的极小边际收益。
- 用分 `beta` 结果解释全局近似最优的原因：不同 `beta` 条件下最优 `delta` 方向相反，聚合后互相抵消。
- 把按 `n` 查表定位为有解释价值但收益有限的可部署层级，而不是主要改进路线。

**递交给下一章**：

如果 L1/L2 难以系统超越 `0.1`，论文不能停在“找另一个固定偏移量”。真正的问题变成：更高信息层级是否存在明确改进空间，尤其是真参数相关层级能带来多少收益。下一章进入 L3-L6。

### Ch5 The Oracle Hierarchy: L3 to L6

**目的**：

准确建立：offset 的真实改进空间主要存在于更高信息层级，尤其与 `beta` 相关；但这些层级本身大多不可直接部署，只能作为参照边界。

**手段**：

- 用 Formal E2 的 L3-L6 阶梯表展示从按真 `beta`、按 `beta+n`、按 `beta+gamma/eta+n` 到逐样本 hindsight 的 J1 变化。
- 用 Figure 3 展示阶梯收益和边际递减点，避免只用表格堆数字。
- 用 Figure 4 展示 L6 逐样本 `delta*` 分布，说明 hindsight 空间存在但不等于可部署目标。
- 明确 L4/L5 与 L6 的角色差异：L4/L5 可作为 E3 标签候选，L6 主要是扫描网格内上限参照和诊断工具。

**递交给下一章**：

E2 找到了 oracle 参照空间，但真参数在部署时不可见。下一章必须把问题从“知道真参数时最优”转成“只看样本时能否接近”。

### Ch6 Sample-Adaptive Offset Selection

**目的**：

准确建立：样本自适应 `delta` 选择是从 oracle 发现走向实际部署的必要桥梁；NN 只是实现桥梁的一种候选工具，而不是论文的目的。

**手段**：

- 从 E2 的结论出发，说明为什么标签应优先考虑 L4/L5，而不是直接追逐 L6 hindsight。
- 严格定义输入约束：只能使用样本值和样本量 `n` 导出的可观测特征，禁止真参数、配置 ID 或任何泄漏信息。
- 用多 seed 结果比较样本自适应方法相对 Default、L1、L2 和 oracle 参照的差距。
- 报告按 `n` 分层、失败率、预测 `delta` 分布和必要消融；若收益不足，保留负结果并回到实践推荐。

**递交给下一章**：

即使样本自适应方法有效，也必须说明它在哪些参数范围、样本量和成本条件下可靠。下一章检查边界，而不是继续扩大主张。

### Ch7 Boundaries and Robustness

**目的**：

准确建立：本文的部署建议是有边界的，不能把 Study 网格内的结果泛化成无条件结论。

**手段**：

- 检查跨 `beta`、跨 `n`、跨 `gamma/eta` 的稳定性，尤其关注 E3 是否只在某些层级或参数区间有效。
- 报告极小样本、边界参数、失败样本处理和计算成本。
- 把失败率作为 gate 条件，而不是把 valid-only 结果包装成全样本优势。
- 若 E4 尚未完成，本章在骨架中保留为待证章节，不提前写成确定结论。

**递交给下一章**：

边界明确后，论文可以回到方法意义：`delta = 0.1` 为什么仍重要，L1-L6 框架改变了什么，实际使用者应如何选择层级。下一章进入 Discussion。

### Ch8 Discussion

**目的**：

准确建立：本文的贡献不是替换 `delta = 0.1`，而是解释它为何强、何处受限、以及在更高信息层级上如何理解和逼近更优 offset。

**手段**：

- 解释 `delta = 0.1` 的双重意义：简单可部署层级的强基线，同时不是所有条件下的局部最优。
- 讨论 L1-L6 框架的概念贡献：把“最优 offset”从单数值问题变成信息层级问题。
- 给出实践分层建议：低成本使用固定 `0.1`，需要透明可部署规则时考虑 L2，追求更高精度时才考虑样本自适应。
- 对照前两篇 MDM 工作，说明本文是第三步推进，而非重新包装原方法或转向单纯 ML 论文。

**递交给下一章**：

Discussion 已解释结果意义和边界，Conclusion 只需收束贡献、证据和适用范围，不再引入新结果。

### Ch9 Conclusion

**目的**：

准确建立一个清晰结论：MDM offset 已从经验设置被推进为可分层评估、可解释边界、可部署讨论的方法组成部分。

**手段**：

- 用 3-4 句话收束：问题、框架、正式证据、部署含义。
- 明确区分已由 E1/E2 支撑的结论与仍需 E3/E4 完成的部署结论。
- 不引入新图表、新机制或新比较。

**递交给下一步**：

论文写作层面进入摘要、题目和投稿版本；研究层面进入 E3/E4 的正式证据生成和复核。

## 骨架自检

写正文或派给 agent 之前，逐章检查：

1. 本章是否有明确目的，而不只是“介绍某内容”。
2. 本章手段是否对应正式证据或明确的文献来源。
3. 本章结尾是否自然推出下一章。
4. E1/E2 已有正式证据的结论是否和 `artifacts/formal/` 对齐。
5. E3/E4 尚未生成的部分是否保持待证口吻。
6. 是否把 NN 写成候选工具，而不是论文主题。
7. 是否把旧 `docs/research` 结果误写成投稿正文证据。
