## 1. 科学合同（P–Q 控制变量）

### 1.1 输出网络（P、Q 相同）

- 输入：升序排序原始样本 \(X_n=\mathrm{sort}(x_1,\dots,x_n)\)（有量纲，不除均值），
  经仅训练折拟合的逐位置 StandardScaler 标准化。
- 网络：`MLP(输入维=n) → 256 ReLU → 128 ReLU → 64 ReLU → 3 输出`。
- 参数合法化（输出变换，P、Q 共用同一函数）：
  \[
  \hat\beta=\mathrm{softplus}(o_1)+\varepsilon,\quad
  \hat\eta=\mathrm{softplus}(o_2)+\varepsilon,\quad
  \hat\gamma=o_3,\quad \varepsilon=10^{-6}
  \]
- 初始化：`torch.manual_seed(seed)` 后按 PyTorch 默认 Kaiming 初始化构建模型。

### 1.2 P 损失（参数精度）

\[
L_P
=
\operatorname{mean}_i
\left[
\left(\frac{\hat\beta_i-\beta_i}{\beta_i}\right)^2
+
\left(\frac{\hat\eta_i-\eta_i}{\eta_i}\right)^2
+
\left(\frac{\hat\gamma_i-\gamma_i}{\eta_i}\right)^2
\right]
\]

（与 Study01 统一评价准则 J1 逐样本项同形；γ 误差以 η 归一，避免小 γ 放大。）

### 1.3 Q 损失（目标分位点）

\[
L_Q
=
\operatorname{mean}_i
\left[
\left(\frac{\hat{x}_{0.95,i}-x_{0.95,i}}{x_{0.95,i}}\right)^2
\right],
\qquad
\hat{x}_{0.95,i}
=
\hat\gamma_i+\hat\eta_i\,[-\ln(0.95)]^{1/\hat\beta_i}
\]

梯度经 Weibull 公式（含 softplus 变换）由 \(\hat{x}_{0.95}\) 传播到三个输出。

### 1.4 除 loss 外严格相同的控制变量（P/Q 配对）

对每个 `(n, fold, seed)` 的 P/Q 配对，保存或验证：

| # | 控制量 | 验证方式 | 预期 |
|---|---|---|---|
| 1 | 初始参数张量 | 拟合前对 P/Q 相同结构模型做参数张量 SHA256 | P==Q |
| 2 | 训练行 ID | 相同 fold 训练集样本键 SHA | P==Q |
| 3 | validation 行 ID | 确定性 (n, fold) 切分（§5.3），与训练 seed/route 无关 | P==Q |
| 4 | held-out 行 ID | 相同 fold 测试集样本键 SHA | P==Q |
| 5 | scaler | 相同训练折拟合的逐位置 StandardScaler 参数 SHA | P==Q |
| 6 | batch 顺序 | 相同 seed 初始化的 DataLoader 采样序列 SHA | P==Q |
| 7 | 网络结构 | 结构签名（层宽/激活/输出变换）SHA | P==Q |
| 8 | 优化器/预算 | 相同 Adam(lr=1e-3, wd=1e-4)、epoch 预算、early stopping 规则 | P==Q |

唯一预期差异为 **loss route**（P 损失 vs Q 损失）。

## 2. 数据

### 2.1 样本生成（确定性契约）

- 逐 `(beta, eta, gamma, n, repeat_id)` 调用
  `generate_sample(beta, eta, gamma, n, repeat_id, seed="study01_nrmc_v1")`。
- 每次 `generate_sample` 结果与 `np.sort` 一致（升序）。
- 样本键：`(beta, gamma_over_eta, n, repeat_id)`；eta=1000 恒等。
- 每键重建原始样本后，对全表样本字节流计算 SHA256 记录于 manifest。

### 2.2 规模自检

- 组合数 = 8×5×4 = 160；样本总数 = 160×300 = 48,000。
- 每个 `(beta, gamma_over_eta, n)` 300 repeats。
- 必须包含 `(beta, eta, gamma) = (2, 1000, 1000)`。

## 3. 划分

### 3.1 五折留出（沿用 Study01 封存折）

- combos = `product(beta, gamma_over_eta, n)`，`combo_idx % 5 == fold_idx` 为该折测试组合。
- 对每个 `(n, fold)`：测试 = 该折下 n 对应的 1 个 γ/η 水平 × 8 beta × 300 repeats
  = 2,400 样本；训练 = 其余 4 个 γ/η 水平 × 8 beta × 300 repeats = 9,600 样本。
- 测试折**不参与** scaler 拟合、训练、early stopping 或 checkpoint 选择。

### 3.2 训练折内部 validation 切分

- 对每个 `(n, fold)`：取训练折样本键（排序），用固定盐
  `int(sha256(f"pq_val|{n}|{fold}")[:8], 16)` 播种 `numpy.default_rng`，shuffle 后取
  后 15%（1,440 行）为 validation；其余 8,160 行为训练。
- validation 行是 `(n, fold)` 的确定性函数，**与训练 seed 和 route 无关**，故 P/Q 在
  同一 `(n, fold)` 下（对所有 seed）使用完全相同的 validation 行。
- validation 只用于 early stopping 与 checkpoint 选择；不进入 held-out 评价。

## 4. 训练合同（PyTorch，P/Q 同一实现）

| 项 | 值 |
|---|---|
| 框架 | PyTorch（CPU；P 与 Q 使用同一实现与版本） |
| 优化器 | Adam，lr = 1e-3，weight decay = 1e-4 |
| 损失 | P：`L_P`；Q：`L_Q`（共享模型与数据管线） |
| batch size | 256 |
| max epochs | 300 |
| early stopping | 每 epoch 记录 validation loss；patience = 20（连续 20 个 epoch 无改善则停） |
| checkpoint 选择 | 选择 validation loss 最低的 epoch 的模型状态（同一规则，各路线用各自 val loss） |
| 确定性 | 每个 fit 开始 `torch.manual_seed(seed)`；DataLoader shuffle 用 `Generator(seed)`；记录初始参数 SHA 与 batch 顺序 SHA |
| 数值 | `torch.set_num_threads(1)` 固定；CPU 运算记录；遇到 NaN 训练损失按失败记录并保留现场 |

## 5. 正式实验规模与执行顺序

### 5.1 规模

- 4 个 n × 5 folds × 2 路线 × 3 个训练随机种子 = **120 个 fold-model fits**。
- 无另外的最终开发模型（本次只做折评价）。

### 5.2 执行顺序（冻结）

1. 微型非证据数据 smoke（`code/study02pq/smoke.py`）；
2. 冻结协议、配置与 SHA（本文件 + `configs/pq-protocol-v1.json` + 代码 SHA）；
3. 正式运行 **seed 42** 的 40 个 fits；
4. 输出 seed 42 临时方向报告（明确标为 **provisional**）；
5. **不改变协议**，继续 seed 2026 与 3407 的 80 个 fits；
6. 用三个 seed 配对结果替换临时数字。

- 若 seed 42 与后两个 seed 方向不一致：如实报告，不挑选种子。
- 若看见 seed 42 后确需修改实现：受影响的所有 seed 必须重跑，并完整记录。

### 5.3 fit 标识

`pq_{n}nf{fold}fs{seed}r{P|Q}`，如 `pq_n7_f1_s42_P`。

## 6. 正式评价

### 6.1 主指标

- 每 fit 的 held-out \(x_{0.95}\) 相对 RMSE：
  \[
  \mathrm{rRMSE}=\sqrt{\tfrac{1}{N}\sum_i\left(\frac{\hat{x}_{0.95,i}-x_{0.95,i}}{x_{0.95,i}}\right)^2}
  \]
  对固定 `(n, fold, seed)`：P 与 Q 在**完全相同**的 2,400 个 held-out 样本上计算。
- P 与 Q 的**配对差值**：逐样本 `(Q 相对误差 − P 相对误差)`；配对 bootstrap（按样本
  重采样）给出差值 CI。
- **相对改善比例**：`(Q_rRMSE − P_rRMSE) / P_rRMSE`（负值 = Q 更优）。

### 6.2 报告层级

至少报告：

- 每个 n；
- 每个 seed；
- 每个 fold；
- 三 seed 合并（pooled，各样本等权）；
- P/Q 配对方向；
- 配对重采样 CI（95%）；
- 失败模型、非法输出、非有限值数量。

**加权规则**：所有样本与参数组合按预定方式等权。因目录顺序、缺失结果或样本数量改变权重
是禁止的；失败项不得静默删除（保留并报告）。

### 6.3 诊断（非成功标准）

- 参数误差（β/η/γ 相对 Bias、RMSE）仅用于诊断 Q 如何达到分位点结果。
- 参数合法率（β>0、η>0、γ 有限）与支撑集违规率（γ̂ ≥ min X）作为诊断报告。

## 7. 停止条件（遇到即保留现场、提交已完成安全工作并停止报告）

1. 最新 main 缺少 Study01 权威配置、样本或 fold 契约；
2. P/Q 无法做到除 loss 外的严格配对；
3. 必须改变本协议定义的科学问题或参数空间；
4. Study01 共享数据与配置哈希不一致；
5. 需要移动或重写不可变历史证据；
6. seed 42 后发现必须修改科学协议；
7. 正式结果出现无法解释的缺失、非有限值或系统性失败；
8. 需要新建通用基础设施才能继续；
9. 需要删除或覆盖用户材料；
10. 发现未授权的 test leakage（测试折信息进入 scaler / early stopping / checkpoint 选择）。

普通实现 bug 可在既定范围内修复并重跑受影响部分，但必须完整记录。

## 8. 工程边界

允许：简单配置、确定性训练脚本、checkpoint、manifest、SHA256、必要单元测试/配对测试/
production-path smoke、可恢复的逐 fit 输出。

禁止：通用 scheduler、authority/control-plane/lease/unseal/consumer 系统、多层
receipt/journal 框架、通用实验平台扩展、大规模攻击测试套件、为旧 D 兼容继续增加
基础设施、新增连续参数空间/压力测试/污染测试/其他分位点/尺度泛化研究、修改 Study01
封存结果、删除历史材料、触碰无关用户文件。

P–Q 使用窄而清晰的专用入口 `code/study02pq/`，不接入旧 formal 控制面。
