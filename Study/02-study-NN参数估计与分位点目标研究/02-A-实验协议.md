## 一、协议目标

本协议服务于前置研究 A 的 19 个必答问题。当前先冻结研究边界、证据原则和实验模块，具体数值配置必须经过后续逐项讨论后才能升级为正式协议。

## 二、已冻结边界

- 分布：三参数 Weibull。
- 样本：完整、独立同分布的小样本。
- 任务：由寿命样本估计 \((\beta,\eta,\gamma)\)。
- 数据角色：仿真数据检验统计性质，真实寿命数据检验工程可用性。
- 排除：删失、截断；计算速度不作为独立研究问题。
- 所有比较必须说明参数空间、样本量和数据条件，禁止无边界地宣称某方法更优。

## 三、统一证据规则

1. **防止泄漏**：所有标准化、特征选择、调参和模型选择只能使用训练集与验证集信息。
2. **组合留出**：泛化评价不能只随机拆分同一参数组合下的 MC 重复样本，必须包含完整参数组合留出。
3. **独立测试**：正式测试集不参与模型或超参数选择。
4. **多次训练**：NN 结论不得来自单次随机初始化或单次训练数据抽样。
5. **成对比较**：不同方法尽可能在同一批 MC 样本上比较，并保留逐样本结果。
6. **边界报告**：总体指标之外，必须按参数区域和样本量报告结果。
7. **失败透明**：无效输出、求解失败、异常预测和边界外推不得静默删除。
8. **证据分层**：pilot 只用于调整设计，formal 结果才可支持研究结论。
9. **可复现性**：正式实验保存配置、随机种子、代码版本、数据来源和运行清单。
10. **严格预注册**：formal 启动前冻结协议版本、配置文件哈希、冻结提交、主要/次要指标、停止条件和排除规则。
11. **四角色数据与测试集一次启封**：training 用于拟合；validation 用于超参数和模型选择；calibration 只用于 A12 的可信度/不确定性校准，不参与模型或超参数选择；独立 test 在方案冻结后一次启封。若数据规模不允许固定四分割，必须在 G2 预先定义提供等价隔离的嵌套交叉拟合。
12. **模块级测试边界**：每个 formal 实验模块拥有独立、预冻结且一次启封的 test 边界。某模块已启封的 test 不得在后续 G3-G5 中回流为训练、validation、calibration 或设计选择依据；需要继续开发时必须使用新的预注册 test。
13. **主比较口径**：Study/02 主研究允许参数路线和直接分位点路线在相同搜索资源预算下分别优化；相同输入和骨干的严格受控比较只作补充归因。

## 四、实验模块与问题映射

| 模块 | 目的 | 对应问题 |
|------|------|----------|
| A-E1 输入表示与特征 | 比较样本值、样本特征及候选特征的作用 | A1、A4 |
| A-E2 训练数据与参数空间 | 研究训练数据量、参数空间和隐含先验 | A5、A6、A13 |
| A-E3 训练目标与模型形式 | 研究参数平衡、网络结构、联合/独立输出和跨样本量建模 | A7、A8、A17、A18 |
| A-E4 方法表现与泛化 | 比较传统方法，检查未见条件、训练稳定性和样本量趋势 | A2、A3、A9、A19 |
| A-E5 合法性与稳健性 | 检查有效参数、单位缩放、位置平移和异常值敏感性 | A10、A14、A15、A16 |
| A-E6 可信度与真实数据 | 表达单次估计可信度并验证真实数据可用性 | A11、A12 |

模块内部依赖不是表格顺序的简单并行：A-E1 先确定候选输入，A-E3 先冻结参数目标与候选结构，A-E2 才能在固定基线下回答训练量/参数空间问题；A9 的多次训练稳定性检查贯穿所有进入候选集和最终入选的 NN，不是一次性独立实验。

## 六、正式产物约定

正式实验启动后，每个模块至少应保存：

- `manifest.json`：实验配置、数据范围、随机种子和代码版本。
- `results.csv` 或等价逐样本结果：保留方法、参数条件、样本量和失败状态。
- `summary.json`：预先定义指标的汇总结果。
- `run_log.txt`：运行状态、警告和失败记录。
- 模块报告：逐项回答对应研究问题，并区分支持、不支持和边界性结果。

目录结构参考 Study/01，但不继承其结论、参数网格或实验结果：

```text
code/
artifacts/
  pilot/
  formal/
01-A-研究问题.md
02-A-实验协议.md
03-A-实验计划.md
04-A-文献与复现审计.md
05-A-证据索引.md
06-A-研究报告.md
```

每次运行还必须向不可覆盖的 `artifacts/run_ledger.jsonl` 追加一条记录，至少包含 run ID、命令、开始/结束时间、退出码、代码提交、配置哈希、随机种子、产物路径与校验和、失败状态及被哪个后续 run 替代。禁止重写或删除旧行来隐藏失败。

研究 A 的最终交付必须包含：

- 一份完整研究报告和问题—证据矩阵。
- 生成全部正式结果的代码及必要测试。
- 正式数据表、汇总表和可追溯源数据。
- 论文级图像及其源数据、绘图脚本和导出包。

论文图统一使用 `nature-figure` 的 Python 后端。从第一幅正式图开始，每幅图在绘制前必须定义核心结论、证据链、图形类型、审稿风险和导出合同，并保存 Python 脚本、源数据、图像合同和视觉 QA 记录；绘制、预览、导出与视觉 QA 全部使用 Python，不得用 R 交叉渲染。

产物路径和字段结构将在首个 formal 模块启动前冻结。

## 七、协议升级规则

1. 任何具体实验数值先经讨论并记录决策来源。
2. pilot 后允许修订协议，但修订必须发生在 formal 运行前。
3. formal 启动后如需改变主指标、数据划分或参数空间，必须新建修订版本并说明旧结果是否作废。
4. `03-A-实验计划.md` 只引用本协议，不复制协议定义。
5. 所有正式操作、失败、重跑、协议偏离和结果替换必须留痕，不得只保留最终成功版本。
6. formal 预注册包至少包含协议快照、机器可读配置、配置 SHA-256、冻结 Git 提交和测试集启封状态。
