# 方法页面开发说明

本文件保留原规范中的实现与验收细节。建设理念分别见[程序流程规范](../建设规范/02-参数估计方法/02-程序流程.md)和[计算过程规范](../建设规范/02-参数估计方法/03-计算过程.md)；共同的算法维护规则见[开发规则](../../02-规则.md#24-方法页面与实现维护)。

## 页面说明的呈现（2026-11-03）

方法原理展示正文、公式和文献，不渲染`implementation.summary`及引用关系备注。程序流程主栏展示步骤、源码、公式与输入输出，页头不重复渲染`flow.description`概要；实现摘要、依据、备注及哈希合并到“来源与实现说明”。计算过程的呈现遵循[建设规范](../建设规范/02-参数估计方法/03-计算过程.md)。算法文档中的历史与核验资料保存在`implementation_notes`，不混入原理正文。

过程图不重复朗读坐标轴、图例及已有公式。曲线依据用短句说明，图例用短标签，判据与结果合并；逐样本推导和工程备注留在详情或文档。

## 过程图的当前实现（2026-11-05）

计算过程Tab内的`AnalysisCard`直接调用`MethodPage.handleCalculate`，请求携带`trace: true`，结果在卡片下方显示；按钮通过`calculationActionLabel`在此处标为“计算并展示过程”。空样本不覆盖默认生成数量，生成样本使用参数栏同一份`displayResult`，不依赖已有估计结果。其他入口仍使用默认“参数估计”按钮。

`CalculationProcessViewer`通过`MethodCalculationSteps`展示各方法的两至三个求参阶段，`CalculationSteps`负责切换；对应程序流程的ID由`src/lib/calculation-steps.ts`维护并校验。链接保留样本等查询参数，以`step`定位`VariableFlowViewer`的对应步骤。`ProcessChart`直接展示坐标、曲线依据及取值判据，为采纳点添加虚线辅助读数。数值与公式由后端同次记录给出，额外函数采样不参与估计规则或称作迭代。

MLE按条件形状、尺度回代、位置似然比较阅读；WMLE按形状方程、位置方程及尺度回代阅读。`PowerScaleCalculation`的简洁模式只显示必要的尺度公式和本次汇总代入，逐样本散点与完整计算在详情中。`LikelihoodProcessViewer`的联动、权重及方程操作数作为展开细节保留。LSE/LRE主线只保留位置判据与最终回归求参两步，原始概率图对照、逐样本变换及最小二乘汇总量在详情中；LRE靠近边界时保留原位置变换的距离精度。MM分为面积求矩、显式求参、位置检查三步。

MDM单独调用`MDMVisualizer`，分为形状寻优、梯度判据定位、伪尺度均值求尺度三步，复用原两图并增加取点辅助线。切换位置只查看同次已计算的条件曲线；改偏移量时当前步骤保留，判据线立即跟随、后端自动重算并采纳最后请求，不清空参数或弹出计算提示。右端外推的虚拟梯度不作真实交点。`MDMScaleCalculation`简洁模式显示伪尺度公式和本次均值代入，逐样本散点及完整数值在详情中；位移、概率变换、分母与总和直接读取同次后端记录。

曲线与计算点分别读取来源。MDM在参数选定后，用同一标准差/梯度函数加密全域及选中点附近采样；采样前冻结求解记录，`display_sample`仅连成细线，原网格、实际求根和形状搜索值叠为实心点，采纳值单独突出。`process-data.ts`保留这些身份并合并坐标，不把外推目标放入真实函数值。MLE/WMLE的形状图以补充函数曲线叠加`selected_shape_evaluations`中的`solver`点；位置判据的全部实际求值均画点，不再因数量超过80而隐藏。MMLE主图叠全部实际迭代到达的形状，生存阶梯图标出样本节点并保持`stepAfter`。悬停显示实际坐标，有求值序号或迭代次数时同时显示；更换视窗仅影响可见范围。

MMLE计算页提供现行单样本构造的固定样本示例：从最小观测定位、删除一个观测和样本平移开始，修改剖面似然主图标记真实迭代到达的形状，联动本次迭代的汇总量、数值代入和停止判据，再由保留样本恢复尺度。示例来自`src/data/method-process-examples/mmle.json`，通过统一runner从同一组样本生成并绑定源码；不开放尚未完成专项验收的计算器。

| 方法 | 判据与参数确定 |
|---|---|
| MDM | 位置与形状双图联动，梯度偏移定位、条件标准差最小点定形状、伪尺度均值定尺度 |
| MLE | 位置似然与得分联动同位置形状方程，幂均值恢复尺度；形状下界另标，不称零点 |
| WMLE | 两个加权方程及候选形状对应的J₃联动，J₁加权恢复尺度；边界容差解另标 |
| LSE | F比和各位置White回归联动，斜率取倒数得到形状、截距取指数得到尺度 |
| LRE | 相关系数定位，原样本与平移后概率图对照，斜率和截距恢复形状及尺度 |
| MM | 阶梯面积与区间贡献形成三个Weibull矩，检查采纳性并逐值代入显式解，列出位置处理前后值 |
| MMLE | 最小值定位置并删除一个观测，修改剖面似然与真实迭代对应，再恢复尺度；固定样本示例 |

本轮沿用既有未审HTML的有效成果，按用户直接实施的决定进入正式页面，估计规则未变。验收与原文依据见[本轮记录](../../coworker/reports/2026-11-05-method-process-figures.md)。

## 计算过程验收

- 设计页面前，先对照原文和现行实现理清每个参数的计算关系，再选择图形；不能按已有绘图组件能显示什么来删减方法步骤。原文与实现的差异按开发规则处理。
- 用一组实际样本逐个走通β、η、γ，核对每个参数的输入、必要中间量、计算或选择依据及对应结果。回代、修正和平均步骤均须展示本次数值之间的关系。
- 完成记录分别说明数值核验、页面计算关系的完整性和与原文的对应范围。任一参数的主要计算关系缺失，`calculation`保持`in_progress`并注明具体缺口；构建、测试通过或已有若干图不代替这项验收。修复一个参数的遗漏后，同时检查其他现有方法是否有同类遗漏。
- 本次样本、有效配置、源码身份、关键求值、候选与选择结果一起由后端返回。trace开关不改变所选实现的输出；编辑输入或配置、切换方法后旧记录失效，慢响应不得覆盖新请求。
- 图表沿用论文或真实计算量的坐标和符号，展示决定结果的极值、交点、方程残差或采纳性判据；最终点与输出参数逐值对应。
- 浏览器逐步检查默认仅呈现当前阶段的主图或回代，坐标和取值辅助线与采纳点对应；程序流程链接定位到配置引用的步骤，保留原样本。展开细节不影响主线结果。
- 核对实心点来自求解或样本记录，曲线补充采样不冒充求解点；转折附近逐值核对同一函数，估计结果和判据不因绘图加密改变。
- 求值次序、实际迭代、候选比较及辅助函数采样各用其真实含义。辅助采样须计算同一真实函数并说明来源；禁止人为乘系数补点、经验公式拼曲面、将候选连成收敛路径或把插值预测称为已执行求解。
- 切换函数范围时，核对数值与原始记录一致。
- 失败及未满足的判据如实显示，不用其他方法或虚构参数替代。原文公式实现、数值补足及真实过程图分别核验，不能由页面验收推断完整复刻。

## 程序流程完成条件

1. 覆盖预处理、核心方程、形状/尺度/位置求解、候选选择、边界与失败、最终输出；按真实方法组织，不强套相同步骤数。
2. 每步提供目的、公式或明确判定条件、符号与代码变量映射、输入、输出、依据和重要边界。公式必须与所展示代码一致，不用伪代码或函数名代替核心实现。
3. 沿用原有“左侧步骤—中间源码—右侧公式及变量”的三栏和逐步切换，步骤使用普通单层编号。只修正计算顺序及源码、公式的对应，不把函数调用树、层级编号和调用标签搬进界面，也不因辅助函数数量机械增加步骤。判断条件及循环范围放在对应说明中，不能把源码来源做成同一步的多个可选项，也不能把函数定义位置当作计算发生次序。
4. 来源标明仓库相对路径、原始行号及文件SHA-256。展示时从现行Python文件读取，说明文件不保存一份可编辑Python代码副本。
5. 原论文构造、数值求解策略、项目工程限制、诊断输出要分别说明。不能将MLE候选点说成优化迭代，把零边界近似说成精确根，或把历史冻结算法当作当前算法。
6. 符号遵循全站β=形状、η=尺度、γ=位置；原论文使用不同符号时明确映射。R²须对应实际概率图计算，不能把变换后残差写成原始CDF残差。
7. 零步骤、缺失核心源码、失效定位、仅含注释的范围、缺失公式/输入/输出/依据均不算完成。发生读取或定位错误时显示明确错误，不能显示其他方法或旧代码代替。
8. 浏览器验收桌面三栏联动、半屏和手机；主要文字至少16px，源码和辅助信息至少14px。步骤切换应定位当前代码，不能引起整页跳动；方法切换及慢请求不能混入上一方法数据。

## 文件职责

| 内容 | 唯一维护位置 |
|---|---|
| 科学算法与数值行为 | `python/methods/*.py`及`python/base.py` |
| 流程说明、顺序、公式、输入输出和源码定位 | `src/data/method_flows/{methodId}.json`，schemaVersion=2；不保存代码正文 |
| 解析与定位校验 | `src/lib/server/method-flow.mjs` |
| 只读接口 | `/api/method-flow/{methodId}` |
| 统一三栏呈现 | `src/components/methods/VariableFlowViewer.tsx` |
| 方法建设状态 | `05-状态.md`；生成缓存不手改 |
| 理论、论文引用作用及实现范围 | `src/content/algorithms/{methodId}.md` |

Python中的既有`@step`注释可作为稳定定位锚点，不再由接口自动推断完整教学流程。旧JSON中的代码副本退役；现行schema只维护说明和对现行源码的引用。

## 源码定位

每个引用指定`file`，可通过限定作用域的`symbol`定位类/函数（例如`MLE.run`、`solve_mle_profile`）；可附`from`、`until`或`through`精确定位语句段。`until`不包含结束行，`through`包含结束行；锚点必须唯一匹配，不能用手填行号作唯一依据。所有路径限制在允许的Python源码目录并检查真实路径，拒绝穿越及符号链接逃逸。

每步`sources`可按计算顺序引用多段真实源码，包括必要的辅助函数；中栏将它们直接接续显示，不提供来源选择按钮，也不把每个函数拆成新的导航步骤。`depth/context/kind`仅兼容旧定位元数据，不决定页面层级；界面统一显示1、2、3的普通步骤。`after`可先定位前序语句，再用`from`定位其后的片段；不用不确定的行号或模糊匹配补位置。完整源文件与哈希作为次要核对入口，不打断主流程。

关键表格等依赖在`artifacts`记录位置、字节数和SHA-256，算法规则及插值函数仍必须能查看；不能用一个数据文件名替代算法说明。

## 验收与维护

`process: done`必须通过实际流程配置、源码定位和必需字段校验，再完成浏览器验收；仅文件存在或写了步骤注释不算验收。修改辅助函数、求解边界或公式时同时核对相应源码引用、说明、测试和方法状态。定位失效应使检查失败，促使维护同步。

`calculation: done`须按[计算过程验收](#计算过程验收)走通全部参数；程序流程已完成不等于计算过程展示已完成。

静态流程展示通过只证明说明与源码对应；算法行为修改须按开发规则先讨论并另行验证，流程页通过不等于论文完整复现，也不自动开放计算过程、蒙特卡洛或计算器。当前方法与历史冻结结果按源码、配置及数据身份区分，不增加算法版本选择。
