# 方法页面开发说明

本文件保留原规范中的实现与验收细节。建设理念分别见[程序流程规范](../建设规范/02-参数估计方法/02-程序流程.md)和[计算过程规范](../建设规范/02-参数估计方法/03-计算过程.md)；共同的算法维护规则见[开发规则](../../02-规则.md#24-方法页面与实现维护)。

## 页面说明的呈现（2026-11-03）

方法原理展示正文、公式和文献，不渲染`implementation.summary`及引用关系备注。程序流程主栏展示步骤、源码、公式与输入输出，页头不重复渲染`flow.description`概要；实现摘要、依据、备注及哈希合并到“来源与实现说明”。计算过程显示图、判据公式和参数恢复，图的补充描述随标题悬停或原始记录查看，不另列重复结论；失败、近似及过期结果仍直接标明。算法文档中的历史与核验资料保存在`implementation_notes`，不混入原理正文。

## 过程图的当前实现（2026-11-02）

计算过程Tab内的`AnalysisCard`直接调用`MethodPage.handleCalculate`，请求携带`trace: true`，结果在卡片下方显示；按钮通过`calculationActionLabel`在此处标为“计算并展示过程”。空样本不覆盖默认生成数量，生成样本使用参数栏同一份`displayResult`，不依赖已有估计结果。其他入口仍使用默认“参数估计”按钮。

`CalculationProcessViewer`复用绘图外框，消费各方法返回的`charts`和`recovery`。图内公式与图下参数恢复值随本次记录返回，不由前端另写估计公式或计算参数。MLE/WMLE保留既有条件形状求根的实际求值，另在返回形状附近以同一得分函数辅助采样作主曲线，区分记录来源；MM经验生存函数使用`stepAfter`，不是光滑拟合。WMLE候选残差用紧凑表展示，避免单点占据整幅图。

| 方法 | 判据与参数确定 |
|---|---|
| MLE | 剖面对数似然与位置得分、固定选中位置的形状得分、幂均值恢复尺度；形状下界另标，不称零点 |
| WMLE | 条件形状方程、位置方程及接受候选比较、J₁加权尺度恢复；边界容差解另标 |
| LSE | F比确定位置，White回归斜率取倒数得到形状、截距取指数得到尺度 |
| LRE | 相关系数确定位置，Park概率图的斜率和截距恢复形状及尺度 |
| MM | 经验生存函数幂次的面积形成三个Weibull矩，检查可采纳性后显式求参，列出位置处理前后值 |
| MMLE | 最小值定位置、删除一个最小观测后的真实不动点迭代与停止判据、保留样本恢复尺度；未开放计算器 |

本次只补运行记录与展示，没有修改这些方法的估计规则。MDM保留已有确认，原双图恢复仍单独跟进。验收证据见[本次记录](../../coworker/reports/2026-11-02-criterion-figures.md)。

## 计算过程验收

- 本次样本、有效配置、源码身份、关键求值、候选与选择结果一起由后端返回。trace开关不改变所选实现的输出；编辑输入或配置、切换方法后旧记录失效，慢响应不得覆盖新请求。
- 图表沿用论文或真实计算量的坐标和符号，展示决定结果的极值、交点、方程残差或采纳性判据；最终点与输出参数逐值对应。
- 求值次序、实际迭代、候选比较及辅助函数采样各用其真实含义。辅助采样须计算同一真实函数并说明来源；禁止人为乘系数补点、经验公式拼曲面、将候选连成收敛路径或把插值预测称为已执行求解。
- 主界面先讲清算法如何选出本次结果，完整数值、源码哈希等按需展开。函数范围切换只改变视窗，不改数值；原始记录保持完整。原始图未提供时按算法本身组织，不为了统一外观强造迭代曲线。
- 失败及未满足的判据如实显示，不用其他方法或虚构参数替代。原文公式实现、数值补足及真实过程图分别核验，不能由测试总数或图表存在推断完整复刻。

## 完成条件

1. 覆盖预处理、核心方程、形状/尺度/位置求解、候选选择、边界与失败、最终输出；按真实方法组织，不强套相同步骤数。
2. 每步提供目的、公式或明确判定条件、符号与代码变量映射、输入、输出、依据和重要边界。公式必须与所展示代码一致，不用伪代码或函数名代替核心实现。
3. 沿用原有“左侧步骤—中间源码—右侧公式及变量”的三栏和逐步切换，步骤使用普通单层编号。只修正计算顺序及源码、公式的对应，不把函数调用树、层级编号和调用标签搬进界面，也不因辅助函数数量机械增加步骤。判断条件及循环范围放在对应说明中，不能把源码来源做成同一步的多个可选项，也不能把函数定义位置当作计算发生次序。
4. 来源标明仓库相对路径、原始行号及文件SHA-256。展示时从现行Python文件读取，说明文件不保存一份可编辑Python代码副本。
5. 原论文构造、数值求解策略、项目工程限制、诊断输出要分别说明。不能将MLE候选点说成优化迭代，把零边界近似说成精确根，或把历史冻结算法当作当前算法。
6. 符号遵循全站β=形状、η=尺度、γ=位置；原论文使用不同符号时明确映射。R²须对应实际概率图计算，不能把变换后残差写成原始CDF残差。
7. 零步骤、缺失核心源码、失效定位、仅含注释的范围、缺失公式/输入/输出/依据均不算完成。发生读取或定位错误时显示明确错误，不能显示其他方法或旧代码代替。
8. 浏览器验收桌面三栏联动、半屏和手机；主要文字至少16px，源码和辅助信息至少14px。步骤切换应定位当前代码，不能引起整页跳动；方法切换及慢请求不能混入上一方法数据。

## 文件职责

| 内容 | 唯一维护位置 |
|---|---|
| 科学算法与数值行为 | `python/methods/*.py`及`python/base.py` |
| 流程说明、顺序、公式、输入输出和源码定位 | `src/data/method_flows/{methodId}.json`，schemaVersion=2；不保存代码正文 |
| 解析与定位校验 | `src/lib/server/method-flow.mjs` |
| 只读接口 | `/api/method-flow/{methodId}` |
| 统一三栏呈现 | `src/components/methods/VariableFlowViewer.tsx` |
| 方法建设状态 | `05-状态.md`；生成缓存不手改 |
| 理论、论文引用作用及实现范围 | `src/content/algorithms/{methodId}.md` |

Python中的既有`@step`注释可作为稳定定位锚点，不再由接口自动推断完整教学流程。旧JSON中的代码副本退役；现行schema只维护说明和对现行源码的引用。

## 源码定位

每个引用指定`file`，可通过限定作用域的`symbol`定位类/函数（例如`MLE.run`、`solve_mle_profile`）；可附`from`、`until`或`through`精确定位语句段。`until`不包含结束行，`through`包含结束行；锚点必须唯一匹配，不能用手填行号作唯一依据。所有路径限制在允许的Python源码目录并检查真实路径，拒绝穿越及符号链接逃逸。

每步`sources`可按计算顺序引用多段真实源码，包括必要的辅助函数；中栏将它们直接接续显示，不提供来源选择按钮，也不把每个函数拆成新的导航步骤。`depth/context/kind`仅兼容旧定位元数据，不决定页面层级；界面统一显示1、2、3的普通步骤。`after`可先定位前序语句，再用`from`定位其后的片段；不用不确定的行号或模糊匹配补位置。完整源文件与哈希作为次要核对入口，不打断主流程。

关键表格等依赖在`artifacts`记录位置、字节数和SHA-256，算法规则及插值函数仍必须能查看；不能用一个数据文件名替代算法说明。

## 验收与维护

`process: done`必须通过实际流程配置、源码定位和必需字段校验，再完成浏览器验收；仅文件存在或写了步骤注释不算验收。修改辅助函数、求解边界或公式时同时核对相应源码引用、说明、测试和方法状态。定位失效应使检查失败，促使维护同步。

静态流程展示通过只证明说明与源码对应；算法行为修改须按开发规则先讨论并另行验证，流程页通过不等于论文完整复现，也不自动开放计算过程、蒙特卡洛或计算器。当前方法与历史冻结结果按源码、配置及数据身份区分，不增加算法版本选择。
