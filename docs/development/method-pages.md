# 方法页面开发说明

本文件维护方法页面的实现与验收细节。建设准则见[计算过程规范](../建设规范/02-参数估计方法/03-计算过程.md)，算法维护规则见[开发规则](../../02-规则.md#24-方法页面与实现维护)。

## 后续建设流程

当前 MDM 是用户确认的计算过程建设示例。后续新增、补建或重构方法页时，按以下顺序落实；步骤粒度和界面准则只维护在[计算过程规范](../建设规范/02-参数估计方法/03-计算过程.md)，不从其他旧页面反推新标准。

1. **核对方法关系**：对照原文的流程图、公式与现行算法，理清输入、全部参数的确定关系和实际分支；原文依据与差异写入该方法审定记录。算法行为变化按开发规则讨论，不能借页面重构改求解路线。
2. **在 Python 声明步骤**：按规范划分求参阶段，将目的、判据、公式、符号、输入输出、流程结构及源码引用写入方法文件的`@method-flow`注释。一个判据内的细操作保留在本步源码中；以稳定步号关联全部视角。
3. **补齐本次运行记录**：由现行后端返回输入、有效配置、源码身份、实际求值、分支、采纳值和必要操作数。前端可排版数值代入、选择视窗及排列已记录点，不另跑参数估计，也不为绘图新增求值。
4. **复用渲染再补方法特有内容**：复用 MDM 已验证的视角切换、流程导航、公式与源码渲染、数值表等能力；按本方法判据组织专用图。现有方法迁移时保留有效图和计算关系，删除被替代的步骤定义及旧入口引用，避免并存两份现行说明。
5. **逐参数验收并记录边界**：按下文检查数值、来源、页面与交互，通过后更新`05-状态.md`的对应能力与证据。记录已迁移范围；其他方法的兼容页面不因此自动通过新版验收。

## 页面说明的呈现（2026-11-03）

方法原理展示正文、公式和文献。历史与核验资料保存在`implementation_notes`。源码面板内的「来源与实现说明」提供实现摘要、依据、备注及哈希。

页面内容取舍与说明层次按[计算过程规范](../建设规范/02-参数估计方法/03-计算过程.md#页面与交互)执行。

## 过程图的当前实现（2026-11-05）

本节持续更新至2026-11-10，保留原标题以兼容既有引用；下列未迁移方法描述现状，后续建设按前述流程执行。

计算过程Tab内的`AnalysisCard`直接调用`MethodPage.handleCalculate`，请求携带`trace: true`，结果在卡片下方显示；按钮通过`calculationActionLabel`在此处标为“计算并展示过程”。空样本不覆盖默认生成数量，生成样本使用参数栏同一份`displayResult`，不依赖已有估计结果。其他入口仍使用默认“参数估计”按钮。

多组过程的样本图统一使用 `src/components/shared/charts/ProcessSampleChart.tsx`。页面传入重复编号、实际观测和可用的真实位置参数，点选时组件返回重复编号。展示规则见[多组样本的计算过程](../建设规范/02-参数估计方法/03-计算过程.md#多组样本的计算过程)。

卡片叠层共用 `calculator-batch.ts` 的生成、顺序估计和工作簿导入。`AnalysisCard` 管理当前组与表格视图，各入口保留整批状态并使旧请求失效。`CalculationBatch` 提供同一批记录，`CalculationWorkspace` 保留方法的全部步骤；MDM 直接适配实际梯度、形状求值与伪尺度，MLE 的条件形状比较取各组实际试算帧。跨页优先复用内存中的完整记录，sessionStorage 只备份样本及来源；刷新后用相同观测补算记录。交互规则归属[计算器规范](../建设规范/01-威布尔计算器.md#批量生成与卡片叠放)。

MDM 是首个接入示例。`CalculationInputCard` 在顶部切换样本卡片与紧凑工作簿，`ArchivedMDMWorkspace` 复用 `CalculationWorkspace` 和 Python 声明的六步结构，各步骤定位到冻结源码，位置判据读取归档的 Brent 分支。组合改变或浏览器历史切换时清除旧组过程，切回样本卡片保留已输入的样本。试点数据及只读接口归属[数据说明](../data/README.md#research00-工作簿登记2026-11-02)。

未迁移方法的`src/lib/calculation-steps.ts`维护阶段及源码引用，`CalculationStageProvider`打开`VariableFlowViewer`；MDM与MLE直接读取 Python 流程声明。旧`/process?step=…`链接转到`/calculation?sourceStep=…`，保留样本、偏移量等查询参数并打开对应源码。`CalculationProcessViewer`用本次计算记录绘制判据图和采纳点。

WMLE按形状方程、位置方程及尺度回代阅读，`LikelihoodProcessViewer`的联动、权重及方程操作数作为展开细节保留。LSE/LRE主线只保留位置判据与最终回归求参两步，原始概率图对照、逐样本变换及最小二乘汇总量在详情中；LRE靠近边界时保留原位置变换的距离精度。MM分为面积求矩、显式求参、位置检查三步。

MDM与MLE共用`CalculationWorkspace`管理视角、步骤与侧栏状态；`useMethodFlow`读取一次流程，`MethodWorkflow`、`FlowStepCode`及`FlowStepDetails`共用其返回的步骤。各自的Visualizer只组织方法数据与图。滚动按所在行确定步骤，并排内容支持鼠标进入和键盘聚焦更新；切换视角或侧栏后重新定位当前步。对应的交互准则见[计算过程规范](../建设规范/02-参数估计方法/03-计算过程.md#页面与交互)。

Python 注释以`formula.equations`逐条声明公式，`formula.variants`选择本次绘图位置规则或位置采纳分支；接口派生兼容的`expression`，并校验数组与分支数量。`ProcessEquation`负责公式与数值代入排版，主公式编号由前序步骤的公式数量累计，避免各视角自行编号。

`CalculationWorkspace.module.css`按中栏容器宽度排列步骤，当前在1080px起排为两列，样本准备与结果表在图像视角占整行。`ProcessValueTable`观察实际容器尺寸，将连续记录均衡分为最多三组，按列保持读取次序。

切换位置读取同次已计算的条件曲线。偏移量变化时判据线立即更新，后端自动重算并采纳最后请求。右端外推按虚拟点标记。`MDMScaleValues`在中栏列出本次各样本反算的伪尺度，`MDMScaleCalculation`在右栏用求和、除以样本数的数值代入展示算术平均，逐样本的反算公式与操作数按需展开。

MDM 的步骤粒度示例见[建设规范](../建设规范/02-参数估计方法/03-计算过程.md#步骤怎样划分)。试算形状图和位置梯度图联动，回代形状图固定在采纳位置。位置图分开显示实际梯度求值和插值交点，端点坐标读取同次记录。回线表示梯度求值调用条件形状寻优。旧流程链接按 Python 流程配置中的旧步号映射定位。

MLE的`mle.py`声明六步条件剖面流程，`MLEVisualizer`读取同次所有实际条件求值，形状图只连接实际求根点。`_mle_solver_frames`按`normalized_gamma`关联原求值身份；记录构建不再调用额外的条件估计或补充采样。位置得分、似然曲线与候选表归入位置采纳，最终形状与尺度展示原候选已求得的关系。尺度表与代入复用`PowerScaleCalculation`的`table/details`视角。原文对应范围、粒度及本轮验收见[MLE自查记录](../method-reviews/mle.md)。

曲线与计算点分别读取来源。MDM 的`process-data.ts`按横坐标整理同次实际扫描、位置求值和形状搜索值，保留求值身份，排除旧`display_sample`和虚拟外推目标。未迁移的WMLE形状图仍以补充函数曲线叠加`selected_shape_evaluations`中的`solver`点，迁移时按现行规范核对其来源；位置判据显示全部实际求值。MMLE主图叠全部实际迭代到达的形状，生存阶梯图标出样本节点并保持`stepAfter`。

MMLE计算页提供现行单样本构造的固定样本示例：从最小观测定位、删除一个观测和样本平移开始，修改剖面似然主图标记真实迭代到达的形状，联动本次迭代的汇总量、数值代入和停止判据，再由保留样本恢复尺度。示例来自`src/data/method-process-examples/mmle.json`，通过统一runner从同一组样本生成并绑定源码；不开放尚未完成专项验收的计算器。

| 方法 | 判据与参数确定 |
|---|---|
| MDM | 位置与形状双图联动，梯度偏移定位、条件标准差最小点定形状、伪尺度均值定尺度 |
| MLE | 位置似然与得分联动同位置形状方程，幂均值恢复尺度；形状下界另标，不称零点 |
| WMLE | 两个加权方程及候选形状对应的J₃联动，J₁加权恢复尺度；边界容差解另标 |

## 计算过程验收

- **完整关系**：用一组实际样本走通全部待估参数，逐步核对[必备内容](../建设规范/02-参数估计方法/03-计算过程.md#每步必须讲清什么)，包括回代、修正和均值恢复；页面步骤与真实源码对应，原文范围及差异有依据。
- **数值与记录**：图中每个实际计算点、采纳点、表值及数值代入均可对上同次后端记录；核对关键极值、夹区间、插值或迭代停止处的操作数。区分真实求值、候选、拟合结果与虚拟目标，调整显示范围不改变原值。
- **分支与身份**：覆盖该方法已有的正常、边界、近似及失败分支；判据、参数与状态一致。核对trace开关不改变结果，配置或样本变化使旧记录失效，慢响应不覆盖最后请求。
- **交互与排版**：在桌面、半屏和手机走通流程定位、自然滚动、并排块的焦点、两种视角、侧栏显隐、分栏表、公式对齐与编号、详细代入及旧源码链接。切换后步骤和输入保留，公式不遮挡编号，页面无横向溢出。
- **多组过程**：页面接入整组数据时，核对步骤与同方法单组过程对应、散点逐值匹配真实观测，并抽查排序前后的重复编号与样本表、曲线和结果联动。
- **调参重算**：核对滑块与输入栏共用同一配置，判据线及最终结果按实际重算更新，等待期间可继续阅读，没有进度弹窗或旧结果冒充新结果。
- **完成记录**：分别记录数值核验、页面关系完整性、浏览器检查及原文对应范围。任一参数缺少主要关系，`calculation`保持`in_progress`并注明缺口；测试或构建通过不能替代内容验收。发现同类遗漏时同时核对其他现有方法并记录待补范围。

## 程序流程完成条件

1. 流程声明通过必需字段、步号、公式及分支、输入输出、依据、流程节点和连线端点校验；覆盖范围按建设规范核对。
2. 每步解析到现行可执行代码及核心辅助函数，保留实际调用与判断顺序。范围须唯一定位，只有注释、固定旧行号或失效引用均失败。
3. 展示仓库相对路径、真实行号及文件SHA-256，并与当前文件逐值核对；不存可编辑代码副本，读取失败不得回退到其他方法或旧代码。
4. 核对符号与代码变量映射，全站β=形状、η=尺度、γ=位置；原文异名有映射，R²对应实际概率图计算。原文构造、数值策略、工程限制和诊断各有来源。
5. 浏览器验收源码初始定位、视角切换后的当前步、焦点及方法请求隔离；未运行计算也能查看源码。主要文字至少16px，源码及辅助信息至少14px。

## 文件职责

| 内容 | 唯一维护位置 |
|---|---|
| 科学算法与数值行为 | `python/methods/*.py`及`python/base.py` |
| 新增及后续迁移方法的步骤说明、公式、输入输出、源码定位、流程图及图像入口 | `python/methods/{methodId}.py` 的 `@method-flow` 注释块，MDM与MLE已迁移；各视角共享接口返回的步骤 |
| 未迁移方法的既有流程及阶段引用 | `src/data/method_flows/{methodId}.json`与`src/lib/calculation-steps.ts`仅兼容现状；该方法迁移时改为Python同源声明并移除替代项 |
| 解析与定位校验 | `src/lib/server/method-flow.mjs` |
| 只读接口 | `/api/method-flow/{methodId}` |
| 源码与说明渲染 | `src/components/methods/CalculationSource.tsx`、`VariableFlowViewer.tsx`；公式与数值表分别复用`ProcessEquation`、`ProcessValueTable` |
| 方法建设状态 | `05-状态.md`；生成缓存不手改 |
| 理论、论文引用作用及实现范围 | `src/content/algorithms/{methodId}.md` |

后续沿用 MDM 的`schemaVersion: 2`，在`# @method-flow`与`# @end-method-flow`之间声明流程，`workflow`用步号引用步骤并声明节点与连线。接口解析 Python 注释并解析真实源码，前端不硬编码第二套步骤、判据及变量含义；本次操作数可在前端按对应公式排版代入。Python 注释与独立 JSON 对同一方法只能保留一个。既有`@step`仅作未迁移流程的定位兼容。

## 源码定位

每个引用指定`file`，可通过限定作用域的`symbol`定位类/函数（例如`MLE.run`、`solve_mle_profile`）；可附`from`、`until`或`through`精确定位语句段。`until`不包含结束行，`through`包含结束行；锚点必须唯一匹配，不能用手填行号作唯一依据。所有路径限制在允许的Python源码目录并检查真实路径，拒绝穿越及符号链接逃逸。

每步`sources`可按计算顺序引用多段真实源码，包括必要的辅助函数；中栏将它们直接接续显示，不提供来源选择按钮，也不把每个函数拆成新的导航步骤。`depth/context/kind`仅兼容旧定位元数据，不决定页面层级；界面统一显示1、2、3的普通步骤。`after`可先定位前序语句，再用`from`定位其后的片段；不用不确定的行号或模糊匹配补位置。完整源文件与哈希作为次要核对入口，不打断主流程。

关键表格等依赖在`artifacts`记录位置、字节数和SHA-256，算法规则及插值函数仍必须能查看；不能用一个数据文件名替代算法说明。

## 验收与维护

`process: done`必须通过实际流程配置、源码定位和必需字段校验，再完成浏览器验收；仅文件存在或写了步骤注释不算验收。修改辅助函数、求解边界或公式时同时核对相应源码引用、说明、测试和方法状态。定位失效应使检查失败，促使维护同步。

`calculation: done`须按[计算过程验收](#计算过程验收)走通全部参数；程序流程已完成不等于计算过程展示已完成。

静态流程展示通过只证明说明与源码对应；算法行为修改须按开发规则先讨论并另行验证，流程页通过不等于论文完整复现，也不自动开放计算过程、蒙特卡洛或计算器。当前方法与历史冻结结果按源码、配置及数据身份区分，不增加算法版本选择。
