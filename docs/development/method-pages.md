## 后续建设流程

建设示例、步骤粒度和界面准则见[计算过程规范](../建设规范/02-参数估计方法/03-计算过程.md#建设示例与适用范围)。新增、补建或重构方法页按以下顺序落实。

1. **核对方法关系**：对照原文的流程图、公式与现行算法，理清输入、全部参数的确定关系和实际分支；原文依据与差异写入该方法审定记录。算法行为变化按开发规则讨论，不能借页面重构改求解路线。
2. **在 Python 声明步骤**：按规范划分求参阶段，将目的、判据、公式、符号、输入输出和流程结构写入方法文件的 `@method-flow` 注释。按[源码定位](#源码定位)填写每步来源。
3. **补齐本次运行记录**：由现行后端返回输入、有效配置、源码身份、实际求值、分支、采纳值和必要操作数。前端可排版数值代入、选择视窗及排列已记录点，不另跑参数估计，也不为绘图新增求值。
4. **复用渲染再补方法特有内容**：复用[工作区组件](#文件职责)，按本方法判据组织专用图。迁移时保留有效图和计算关系，并更新已替代的步骤定义及入口引用。
5. **逐参数验收并记录边界**：按下文检查数值、来源、页面与交互，通过后更新`05-状态.md`的对应能力与证据。

## 过程图的当前实现（2026-11-05）

2026-11-16，七种已建设方法使用同一计算过程工作区，左右输入输出及图的关键量改为引用各方法的统一变量定义。已有图、求参关系和算法保留；科学表述与步骤粒度仍待用户审阅。

计算过程 Tab 的卡片通过 `calculationActionLabel` 显示「计算并展示过程」。单组请求由 `MethodPage.handleCalculate` 发起，批量请求由 `handleBatchCalculate` 发起，均携带 `trace: true`，结果在卡片下方显示。卡片状态与请求交接见[共享计算卡片](../../src/components/calculator/README.md)。

多组过程的样本图统一使用 `src/components/shared/charts/ProcessSampleChart.tsx`。页面传入重复编号、实际观测和可用的真实位置参数，点选时组件返回重复编号。展示规则见[多组样本的计算过程](../建设规范/02-参数估计方法/03-计算过程.md#多组样本的计算过程)。

`CalculationBatch` 把整批运行记录交给 `CalculationWorkspace` 展示方法的全部步骤。MDM 直接适配实际梯度、形状求值与伪尺度，MLE 的条件形状比较取各组实际试算帧。

MDM 是首个接入示例。`CalculationInputCard` 在顶部切换样本卡片与紧凑工作簿，过程通过独立的计算记录编号读取。实时与已保存记录共用 `MDMBatchWorkspace`、`CalculationWorkspace` 和六步结构；源码和求解器按该次记录的算法身份展示。组合改变或浏览器历史切换时清除旧组过程，切回样本卡片保留已输入的样本。记录格式、生成和读取入口唯一归属[计算记录规范](../data/README.md#计算记录)。

WMLE、LSE、LRE、MM 和 MMLE 通过 `RecordedCalculationProcess` 将运行记录的图表和数值接入步骤。现有权重与方程代入、位置与回归比较、逐样本变换、矩面积区间联动、形状迭代和尺度回代继续使用原组件。主图及展开的回归、似然图共用工作区绘图区和坐标标注。

`recorded-process-data.ts`读取同次记录中的条件帧、回归视图与迭代，向每步输入输出提供实际值。`CalculationWorkspace.values`可按步骤返回数值映射，`input.`与`output.`前缀区分同名变量处理前后的值。试算位置和迭代索引由适配组件统一持有，图、右栏及手机说明同步；最终回归始终读取采纳位置。切换计算记录时重置查看索引，保留工作区当前步骤。

`@method-flow.variables`唯一声明关键量的名称、符号、含义、取值键和可用的坐标标题；`steps.inputs/outputs`引用变量 ID，`extraInputs/extraOutputs`供右栏“设置与补充量”展开。`steps.flow`声明节点动作和判据，`steps.portGroups`选取本步变量组成左侧摘要。`workflow`仅维护结构、端口分组引用与连线；加载器生成显示名称和数学标签，拒绝端口另写名称、符号，以及引用本步范围外的变量。左右展示层次归属[统一口径规范](../建设规范/02-参数估计方法/03-计算过程.md#左右两侧与图的统一口径)。

`chartBindings`将图的横纵坐标绑定到变量 ID，`ProcessDefinitionContext`向已有图组件提供统一坐标标题，保留同次记录的曲线、计算点及采纳值。`MethodWorkflow`和表头共用`MathText`，左侧不注入运行数值；步骤完整名称用于内容标题和无障碍命名。`ProcessValueTable`继续呈现操作数，MMLE 按`i=1…q`对应`t₍ᵢ₊₁₎`和`yᵢ`。

流程图尺寸统一由`CalculationWorkspace.module.css`和`MethodWorkflow`控制。每个`layout: module`分组包含一个步骤框和本步的输入、输出端口；端口最小高度72px，宽度在同一画布内一致，随栏宽变化并以116px为上限，内容换行时自然增高。端口与计算框共用16px附着距离，计算框按动作和判据自然增高，模块间共用40px间距，不使用方法专用尺寸。`workflow.connections`只声明真实的跨模块传递或试算调用，外部输入通过`external`标记；加载时检查端口归属、输入来源和模块连通，模块内部归属关系不画成箭头。

`workflow-relations.ts`从节点所属步骤与既有连线生成展示：相邻步骤的正向传递画短折线，其余关系在接收端框内按“②中的参数”生成来源说明。`portSourceGroups`通过完整步骤输出与输入变量ID对应来源，同源量可合并，混合来源分别排列；单一依赖下的派生量沿用该条已声明关系，不重新推断算法。七种方法共58条关系对应30条短线和28个来源标记；已移除旧侧路布线代码及方法声明中的侧路提示。点击来源步号保留该关系并定位来源，选中端口显示其直接来源或接收步骤，顶栏步号支持双向定位，清除按钮和Escape退出高亮。全部标记、定位与高亮共用这一份关系，字体或栏宽变化时按实际节点边界重算短线。阅读规则见[图和数值表达规范](../建设规范/02-参数估计方法/03-计算过程.md#图和数值怎样表达)。

七种方法共用`CalculationWorkspace`管理视角、步骤与侧栏状态；`useMethodFlow`读取一次流程，`MethodWorkflow`、`FlowStepCode`及`FlowStepDetails`共用其返回的步骤。方法内容组件负责组织运行数据和图。滚动按所在行确定步骤，并排内容支持鼠标移动和键盘聚焦更新；切换视角或侧栏后重新定位当前步。对应的交互准则见[计算过程规范](../建设规范/02-参数估计方法/03-计算过程.md#页面与交互)。

Python 注释以`formula.equations`逐条声明公式，`formula.variants`选择本次绘图位置规则或位置采纳分支；接口校验主公式和分支公式的数量。`ProcessEquation`负责公式与数值代入排版，主公式编号由前序步骤的公式数量累计，避免各视角自行编号。

`CalculationWorkspace.module.css`按中栏容器宽度排列步骤，当前在1080px起排为两列，样本准备与结果表在图像视角占整行。`ProcessValueTable`观察实际容器尺寸，将连续记录均衡分为最多三组，按列保持读取次序。

同一步中的多个过程图按各自可用宽度排列，空间不足时纵向阅读；不使用整窗断点把三栏中间的图再次挤成窄列。

切换位置读取同次已计算的条件曲线。偏移量变化时判据线立即更新，后端自动重算并采纳最后请求。右端外推按虚拟点标记。`MDMScaleValues`在中栏列出本次各样本反算的伪尺度，`MDMScaleCalculation`在右栏用求和、除以样本数的数值代入展示算术平均，逐样本的反算公式与操作数按需展开。

MDM 的步骤粒度示例见[建设规范](../建设规范/02-参数估计方法/03-计算过程.md#步骤怎样划分)。试算形状图和位置梯度图联动，回代形状图固定在采纳位置。位置图分开显示实际梯度求值和插值交点，端点坐标读取同次记录。回线表示梯度求值调用条件形状寻优。

MLE的`mle.py`声明六步条件剖面流程，`MLEVisualizer`读取同次所有实际条件求值，形状图只连接实际求根点。`_mle_solver_frames`按`normalized_gamma`关联原求值身份；记录构建不再调用额外的条件估计或补充采样。位置得分、似然曲线与候选表归入位置采纳，最终形状与尺度展示原候选已求得的关系。尺度表与代入复用`PowerScaleCalculation`的`table/details`视角。原文对应范围、粒度及本轮验收见[MLE自查记录](../method-reviews/mle.md)。

曲线与计算点分别读取来源。MDM 的`process-data.ts`按横坐标整理同次实际扫描、位置求值和形状搜索值，保留求值身份，排除旧`display_sample`和虚拟外推目标。WMLE形状图沿用补充函数曲线叠加`selected_shape_evaluations`中的`solver`点，补充曲线与实际求解点分别标注；位置判据显示全部实际求值。MMLE主图叠全部实际迭代到达的形状。MM 生存阶梯图标出样本节点并保持`stepAfter`。

MMLE计算页提供现行单样本构造的固定样本示例：从最小观测定位、删除一个观测和样本平移开始，修改剖面似然主图标记真实迭代到达的形状，联动本次迭代的汇总量、数值代入和停止判据，再由保留样本恢复尺度。示例来自`src/data/method-process-examples/mmle.json`，通过统一runner从同一组样本生成并绑定源码；不开放尚未完成专项验收的计算器。

## 计算过程验收

- **完整关系**：用一组实际样本走通全部待估参数，逐步核对[必备内容](../建设规范/02-参数估计方法/03-计算过程.md#每步必须讲清什么)，包括回代、修正和均值恢复；页面步骤与真实源码对应，原文范围及差异有依据。
- **数值与记录**：图中每个实际计算点、采纳点、表值及数值代入均可对上同次后端记录；核对关键极值、夹区间、插值或迭代停止处的操作数。区分真实求值、候选、拟合结果与虚拟目标，调整显示范围不改变原值。
- **分支与身份**：覆盖该方法已有的正常、边界、近似及失败分支；判据、参数与状态一致。核对trace开关不改变结果，配置或样本变化使旧记录失效，慢响应不覆盖最后请求。
- **交互与排版**：在桌面、半屏和手机走通流程定位、自然滚动、并排块的焦点、两种视角、侧栏显隐、分栏表、公式对齐与编号、详细代入。切换后步骤和输入保留，公式不遮挡编号，页面无横向溢出。
- **多组过程**：页面接入整组数据时，核对步骤与同方法单组过程对应、散点逐值匹配真实观测，并抽查排序前后的重复编号与样本表、曲线和结果联动。
- **调参重算**：核对滑块与输入栏共用同一配置，判据线及最终结果按实际重算更新，等待期间可继续阅读，没有进度弹窗或旧结果冒充新结果。
- **完成记录**：分别记录数值核验、页面关系完整性、浏览器检查及原文对应范围。任一参数缺少主要关系，`calculation`保持`in_progress`并注明缺口；测试或构建通过不能替代内容验收。发现同类遗漏时同时核对其他现有方法并记录待补范围。

## 程序流程完成条件

1. 流程声明通过必需字段、步号、公式及分支、输入输出、依据、流程节点和连线端点校验；覆盖范围按建设规范核对。
2. 每步解析到现行可执行代码及核心辅助函数，保留实际调用与判断顺序。范围须唯一定位，只有注释、固定旧行号或失效引用均失败。
3. 展示仓库相对路径、真实行号及文件SHA-256，并与当前文件逐值核对；不存可编辑代码副本，读取失败不得回退到其他方法或旧代码。
4. 核对符号与代码变量映射，全站β=形状、η=尺度、γ=位置；原文异名有映射，R²对应实际概率图计算。原文构造、数值策略、工程限制和诊断各有来源。
5. 浏览器验收源码初始定位、视角切换后的当前步、焦点及方法请求隔离。未运行计算时也能查看源码。文字大小按[方法页准则](../建设规范/02-参数估计方法/README.md#准则)验收。

## 文件职责

| 内容 | 唯一维护位置 |
|---|---|
| 科学算法与数值行为 | `python/methods/*.py`及`python/base.py` |
| 各方法的步骤说明、公式、输入输出、源码定位、流程图及图像入口 | `python/methods/{methodId}.py` 的 `@method-flow` 注释块；各视角共享接口返回的步骤 |
| 解析与定位校验 | `src/lib/server/method-flow.mjs` |
| 只读接口 | `/api/method-flow/{methodId}` |
| 工作区、源码与说明渲染 | `CalculationWorkspace`、`MethodWorkflow`、`FlowStepContent`、`ProcessEquation`、`ProcessValueTable` |
| 方法建设状态 | `05-状态.md`；生成缓存不手改 |
| 理论、论文引用作用及实现范围 | `src/content/algorithms/{methodId}.md` |

流程采用`schemaVersion: 2`，在`# @method-flow`与`# @end-method-flow`之间声明流程，`workflow`用步号引用步骤并声明节点与连线。接口解析 Python 注释并解析真实源码，前端不硬编码第二套步骤、判据及变量含义；本次操作数可在前端按对应公式排版代入。

## 源码定位

每个引用指定`file`，可通过限定作用域的`symbol`定位类/函数（例如`MLE.run`、`solve_mle_profile`）；可附`from`、`until`或`through`精确定位语句段。`until`不包含结束行，`through`包含结束行；锚点必须唯一匹配，不能用手填行号作唯一依据。所有路径限制在允许的Python源码目录并检查真实路径，拒绝穿越及符号链接逃逸。

每步`sources`可按计算顺序引用多段真实源码，包括必要的辅助函数；中栏将它们直接接续显示，不提供来源选择按钮，也不把每个函数拆成新的导航步骤。界面按步骤 ID 编号。`after`可先定位前序语句，再用`from`定位其后的片段；不用不确定的行号或模糊匹配补位置。完整源文件与哈希作为次要核对入口，不打断主流程。

关键表格等依赖在`artifacts`记录位置、字节数和SHA-256，算法规则及插值函数仍必须能查看；不能用一个数据文件名替代算法说明。

## 验收与维护

`process: done`必须通过实际流程配置、源码定位和必需字段校验，再完成浏览器验收；仅文件存在或写了步骤注释不算验收。修改辅助函数、求解边界或公式时同时核对相应源码引用、说明、测试和方法状态。定位失效应使检查失败，促使维护同步。

`calculation: done`须按[计算过程验收](#计算过程验收)走通全部参数；程序流程已完成不等于计算过程展示已完成。

静态流程展示通过只证明说明与源码对应；算法行为修改须按开发规则先讨论并另行验证，流程页通过不等于论文完整复现，也不自动开放计算过程、蒙特卡洛或计算器。当前方法与历史冻结结果按源码、配置及数据身份区分，不增加算法版本选择。
