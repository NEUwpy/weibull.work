# 性能优化分析与规划

> 创建时间: 2026-02-21
> 状态: 分析阶段

## 1. 当前性能问题诊断

### 1.1 观察到的现象

- 首页加载有明显延迟
- 打开方法详情页时卡顿
- 公式渲染存在超时风险（已加 5 秒保护）
- 代码中存在渲染计数检测，说明曾遇到无限循环问题

### 1.2 性能瓶颈分析

| 问题类型 | 具体表现 | 严重程度 |
|---------|---------|---------|
| **依赖体积** | node_modules 695M，含 Recharts/Framer Motion/KaTeX/Plotly 等重型库 | 高 |
| **重复渲染** | 组件未使用 memo，父组件更新导致子组件全部重渲染 | 高 |
| **公式渲染** | KaTeX 每次重新解析，大量公式时明显卡顿 | 中 |
| **数据加载** | 每次打开页面都 fetch，无缓存机制 | 中 |
| **代码分割** | 可视化组件未做懒加载，首屏体积大 | 低 |

### 1.3 潜在风险（内容增长后）

- 更多方法 → 更多公式 → KaTeX 压力增大
- 更多案例 → 更多数据文件 → 加载时间增长
- 更复杂的可视化 → 渲染开销增加

## 2. 优化方向

### 2.1 短期优化（投入小，见效快）

#### 2.1.1 组件记忆化
```tsx
// 给重型组件添加 React.memo
const AnalysisCard = React.memo(function AnalysisCard(props) { ... })
const MethodDetailContent = React.memo(function MethodDetailContent(props) { ... })
```

**预期效果**: 减少 50%+ 不必要的渲染

#### 2.1.2 useMemo 优化计算
```tsx
// 图表数据生成使用 useMemo
const chartData = useMemo(() => generatePDFPoints(result, 100), [result])
```

**预期效果**: 避免每次渲染都重新计算图表坐标

#### 2.1.3 useCallback 优化回调
```tsx
// 事件处理函数使用 useCallback
const handleCalculate = useCallback(async () => { ... }, [deps])
```

**预期效果**: 避免子组件因回调引用变化而重渲染

### 2.2 中期优化（需要一定重构）

#### 2.2.1 动态导入可视化组件
```tsx
// 使用 next/dynamic 懒加载
const MDMVisualizer = dynamic(() => import('@/components/visualizers/MDMVisualizer'), {
  loading: () => <LoadingSpinner />,
  ssr: false
})
```

**预期效果**: 首屏 JS 体积减少 30-50%

#### 2.2.2 KaTeX 结果缓存
```tsx
// 使用 Map 缓存已渲染的公式
const latexCache = new Map<string, string>()
```

**预期效果**: 公式不重复渲染，页面切换更流畅

#### 2.2.3 API 响应缓存
```tsx
// 使用 SWR 或 React Query
const { data } = useSWR(`/api/algorithms?slug=${slug}`, fetcher)
```

**预期效果**: 减少重复请求，提升二次访问速度

### 2.3 长期优化（架构级）

#### 2.3.1 Markdown 静态预渲染
- 构建时将 MD + LaTeX 转为 HTML
- 运行时直接渲染静态 HTML

**预期效果**: 消除运行时解析开销

#### 2.3.2 虚拟滚动（如需展示大量内容）
- 使用 react-window 或 react-virtualized
- 只渲染可视区域内容

**预期效果**: 支持超大列表无卡顿

#### 2.3.3 Web Worker 计算
- 将复杂计算移到 Web Worker
- 主线程只负责渲染

**预期效果**: 计算不阻塞 UI

## 3. 优化优先级排序

| 优先级 | 优化项 | 预期收益 | 实现难度 | 建议时机 |
|-------|-------|---------|---------|---------|
| P0 | React.memo 组件记忆化 | 高 | 低 | 立即 |
| P0 | useMemo 优化计算 | 高 | 低 | 立即 |
| P1 | useCallback 优化回调 | 中 | 低 | 立即 |
| P1 | 动态导入可视化组件 | 高 | 中 | 下次迭代 |
| P2 | KaTeX 缓存 | 中 | 中 | 有性能问题再处理 |
| P2 | API 缓存 (SWR) | 中 | 低 | 下次迭代 |
| P3 | Markdown 预渲染 | 高 | 高 | 内容很多时考虑 |
| P3 | Web Worker | 中 | 高 | 计算密集时考虑 |

## 5. 结论

当前性能问题主要集中在 **重复渲染** 和 **重型依赖** 两方面。

**建议策略**: 先做低成本的 memo 优化，观察效果后再决定是否进行架构级重构。不必过度优化，保持代码可维护性。

> "Premature optimization is the root of all evil." — Donald Knuth
