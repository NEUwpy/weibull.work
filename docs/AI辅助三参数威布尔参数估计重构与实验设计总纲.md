# AI 辅助三参数威布尔参数估计重构与实验设计总纲

> 目的：给后续 Claude Code 或其他 AI Coding 工具提供清晰的研究与重构方向。
> 定位：这是“重构与实验设计总纲”，不是最终代码设计文档。
> 原则：说明为什么要改、改成什么结构、每一步目标是什么、如何验收；不提前写死具体函数名、类结构和文件布局。

---

## 1. 项目背景

当前项目是一个三参数威布尔分布参数估计平台，已有基础包括：

- 传统威布尔参数估计算法；
- 蒙特卡洛模拟；
- 可视化展示；
- 初步 AI 参数估计模块；
- 面向方法验证、适用范围分析和结果展示的旧平台框架。

但旧 AI 模块和实验体系存在几个关键问题：

1. **AI 模块边界不清晰**  
   原来的 M1/M2/M3 划分较粗，M1 中混合了过程量预测、误差修正等不同逻辑，导致研究问题和实验结果难以解释。

2. **评价指标不统一**  
   传统方法、AI 方法、不同蒙特卡洛实验和可视化页面使用的指标口径不一致，无法进行可靠横向比较。

3. **训练损失函数缺少系统验证**  
   旧 AI 模型使用的 loss 没有经过统一对比，不清楚它更适合参数估计、工程寿命分位点估计，还是只是适合某个原型实验。

4. **蒙特卡洛流程重复且臃肿**  
   每新增一个方法或实验，容易重新写一套样本生成、方法调用、结果保存和指标统计流程。

5. **规划文档过度细化**  
   旧规划文档过早规定了大量字段名、函数名、文件名和实现路径，反而限制后续 AI Coding 工具根据真实代码结构灵活落地。

本次重构的目标不是推翻旧平台，而是在旧平台已有传统算法、数据生成和可视化能力基础上，重新整理 AI 模块、评价体系、损失函数实验和蒙特卡洛调度框架。

本阶段默认研究对象是**完全观测失效数据**。右删失、区间删失等可靠性工程中常见的数据形态暂不进入第一版重构主线，后续可作为扩展方向单独规划。

旧 M1/M3 模型、训练结果和页面展示保留为历史原型资料。新研究结论必须基于新统一评价体系和新统一蒙特卡洛框架重新训练或重新评估，不能直接沿用旧结果作为正式结论。

---

## 2. 重构总目标

本阶段的核心目标是建立一条可复用、可比较、可解释的研究链路：

```text
统一参数空间
→ 统一样本生成
→ 统一方法调用
→ 统一结果保存
→ 统一评价指标
→ 统一横向比较
→ 论文或组会结果表格与可视化
```

重构完成后，应能回答：

1. 传统方法、AI 辅助方法、AI 直接方法和智能优化方法能否在同一测试集上比较？
2. 不同方法在参数估计上谁更准？
3. 不同方法在工程可靠度寿命分位点上谁更准？
4. 不同训练 loss 对 AI 模型有什么影响？
5. AI 方法改善的是参数精度、分位点精度、稳定性、失败率，还是运行时间？
6. 哪些方法适合哪些样本量和参数空间？

## 3. AI 模块重新划分

本次重构将 AI 模块划分为 M1、M2、M3、M4 四类。四类模块应能接入同一套蒙特卡洛和评价体系。

### 3.1 M1：AI 预测过程量

M1 的逻辑是：

```text
样本特征 → AI 预测过程量 → 传统估计方法 → 参数估计结果
```

这里的“过程量”指传统估计方法运行过程中需要选择或调节的量，例如：

- 最小差异法中的偏移量；
- 初始值；
- 搜索区间；
- 权重；
- 迭代控制参数；
- 传统方法内部的候选策略选择。

M1 的研究问题是：

- AI 是否能学习传统方法中过程量的选择规律？
- AI 预测的过程量代入传统方法后，是否提升最终参数估计或分位点估计？
- 改善来自精度、稳定性、成功率，还是运行时间？

注意：M1 的主评价对象不是过程量本身，而是过程量代入传统方法后的最终估计效果。

### 3.2 M2：AI 误差修正 / 偏差纠正

M2 的逻辑是：

```text
样本特征 + 传统估计结果 → AI 预测估计误差 → 修正传统估计结果
```

M2 保留传统方法作为基础估计器，AI 只学习传统方法的系统偏差或残差。

M2 的研究问题是：

- 传统方法在哪些参数空间或样本量下存在系统偏差？
- AI 是否能纠正这些偏差？
- 修正后参数误差是否下降？
- 修正后工程分位点误差是否下降？
- 修正后是否引入更大波动、边界病态或更重尾的误差分布？

M2 需要同时关注方向偏差、波动和尾部风险。如果方向偏差降低但尾部风险增大，不能简单认为方法更优。

### 3.3 M3：AI 直接估计

M3 的逻辑是：

```text
样本特征 → AI 模型 → beta_hat, eta_hat, gamma_hat
```

M3 直接从样本或样本特征预测三参数威布尔分布的参数。

M3 的研究问题是：

- AI 是否能直接学习从样本到参数的映射？
- 直接估计在小样本下是否稳定？
- 不同输入表示对结果有什么影响？
- 参数导向 loss 和分位点导向 loss 对 M3 的影响是什么？

#### M3 的分类扩展

导师提出，三参数威布尔分布参数估计也可以理解为“从一组样本判断其所属母体分布”。如果参数空间是离散设定的，可以将问题转化为分类问题。

分类方法不作为替代所有估计方法的主线，而作为 M3 的子方向。

可考虑三种形式：

1. **整体参数组合分类**  
   将每一个参数组合 `(beta, eta, gamma/eta)` 作为一个类别。  
   例如在建议参数空间中共有 `6 × 3 × 4 = 72` 类。

2. **分参数分类**  
   分别预测 `beta` 类别、`eta` 类别和 `gamma/eta` 类别，用于分析不同参数的可识别性。

3. **分类辅助回归**  
   先判断样本所属参数区域，再在该区域内进行连续参数回归。  
   这是最推荐的分类扩展形式，因为它既利用分类思想，又保留连续参数估计能力。

分类方法的优点：

- 适合参数空间有限、工程母体类型有限的应用场景；
- 可以验证小样本条件下样本所属母体是否可识别；
- 可以作为直接估计方法的补充。

分类方法的局限：

- 参数估计本质上是连续问题，纯分类会带来离散化误差；
- 对未见过参数组合的泛化能力较弱；
- 不宜完全替代连续参数估计方法。

因此建议将分类方向放入 M3，例如：

- M3-a：连续参数直接回归；
- M3-b：参数组合分类；
- M3-c：分类辅助回归。

### 3.4 M4：智能优化算法

M4 指使用智能优化算法辅助传统方法的搜索、迭代或目标函数求解过程。

可包括：

- 遗传算法；
- 粒子群算法；
- 贝叶斯优化；
- 模拟退火；
- 差分进化；
- 其他全局优化或启发式搜索方法。

M4 的研究问题是：

- 智能优化是否能改善传统方法的收敛性？
- 是否能减少无解、局部最优或搜索失败？
- 是否能提高精度或稳定性？
- 代价是否是更长运行时间？

M4 与 M1 的区别是：M1 用 AI 预测过程量，M4 用优化算法搜索或改进求解过程。

复合方法按主要贡献来源归类。例如，AI 直接预测传统方法所需的数值过程量，归入 M1；AI 只调度或选择搜索算法，而主要改进来自优化过程，归入 M4；若二者同时存在，应在实验命名中说明为复合方法，并在结果表中保留其主要归属。

## 4. S2R 统一评价体系

所有传统方法、M1、M2、M3、M4 必须使用同一套 S2R 评价体系。S2R 的核心原则是：先看误差分布，再从分布中提取准确性、方向、稳定性、尾部和有效性。

评价体系保留三种视角：

1. 参数估计视角；
2. 工程应用分位点视角；
3. 方法可用性视角。

### 4.1 参数估计视角

参数误差指标回答：

```text
beta、eta、gamma 三个参数本身估得准不准？
```

每个有效样本先计算带符号相对误差：

```text
e_beta  = (beta_hat  - beta)  / beta
e_eta   = (eta_hat   - eta)   / eta
e_gamma = (gamma_hat - gamma) / eta
```

`gamma` 可能为 0，且工程上与寿命尺度同量纲，因此统一用 `eta` 归一化。

对每个参数分别汇总同一组分布指标：

- MdAPE：`median(|e|)`，回答典型误差幅度；
- MedRel：`median(e)`，回答系统高估或低估方向；
- P25/P75 与 RelIQR，回答中间 50% 的稳定性；
- P5/P95 与 P95(|e|)，回答尾部风险；
- 必要时增加 P99(|e|)，观察极端尾部。

不再用单个综合标量作为主排序依据。方法比较时必须同时看典型误差、方向偏差和尾部风险。

### 4.2 工程应用分位点视角

三参数威布尔参数估计在工程中往往不是直接使用 `beta, eta, gamma`，而是使用给定可靠度水平下的寿命分位点。

建议可靠度水平：

```text
R ∈ {0.50, 0.90, 0.95, 0.99, 0.999}
```

真实分位点：

```text
x_R = gamma + eta * (-ln(R))^(1 / beta)
```

估计分位点：

```text
x_hat_R = gamma_hat + eta_hat * (-ln(R))^(1 / beta_hat)
```

每个 R 水平计算带符号相对误差：

```text
e_R = (x_hat_R - x_R) / x_R
```

随后使用与参数视角完全相同的分布指标：MdAPE、MedRel、P25/P75、RelIQR、P5/P95、P95(|e|)，必要时 P99(|e|)。

需要特别注意：某些方法可能参数估计不是最优，但关键可靠度分位点估计更好。因此不能只根据参数误差给出最终方法排名。

### 4.3 方法可用性视角

除了精度，还要评价方法是否可用。

建议记录：

- Valid Rate；
- Failure Rate；
- 运行时间均值或分位数；
- 失败原因分布；
- 是否存在明显不稳定区间；
- 是否存在边界病态或数值病态。

失败样本不能简单删除。它们必须进入 Failure Rate 的分母，否则会高估方法表现。

### 4.4 成功和失败的统一口径

所有方法结果统一落入两类状态：

- `success`：方法给出了数值有效、物理可解释、未触发边界病态规则的估计结果；
- `failure`：方法没有给出可用估计结果，例如不收敛、异常中断、无解、输出非有限值、`beta_hat <= 0`、`eta_hat <= 0`，或 `gamma_hat` 贴到样本最小值等边界病态。

误差很大但数值有效的结果不应提前剔除。它必须进入尾部分位统计，由 P95(|e|)、P99(|e|) 和分层分析体现风险。

### 4.5 横向比较的统计原则

所有方法必须在**共享样本**上比较。也就是说，同一个参数组合、样本量和随机重复编号生成的一份样本，应被所有待比较方法共同使用。

共享样本的好处是可以做配对比较，减少蒙特卡洛随机波动对方法排名的影响。

主要指标不应只报告单个均值。横向比较时建议至少报告：

- MdAPE；
- MedRel；
- RelIQR；
- P95(|e|)，必要时 P99(|e|)；
- Valid Rate 与 Failure Rate；
- 必要时的配对统计检验或 bootstrap 比较。

最终结论应避免只根据很小的均值差异判断某方法“显著更优”。

## 5. 损失函数验证实验

在正式重训或扩展 AI 模块前，应先做一个前置损失函数验证实验。

该实验的目的不是追求某一个 AI 模型最强，而是判断不同训练 loss 更适合什么研究目标。

### 5.1 实验对象

先使用一个简单的 M3 直接估计模型作为测试对象。

原因：

- M3 结构最直接；
- 训练目标清晰；
- 可以快速比较 loss 对 `beta_hat, eta_hat, gamma_hat` 和分位点估计的影响；
- 不需要先处理传统方法依赖。

后续 M1、M2 训练时，可以参考该实验结论选择更合理的 loss。

### 5.2 候选损失函数

候选 loss 包括：

1. **原始参数 MSE**  
   直接对 `beta, eta, gamma` 做 MSE。  
   用作旧方法或最基础 baseline。

2. **S2R 参数相对误差 MSE**
   对 `e_beta`、`e_eta`、`e_gamma` 计算 MSE，其中 `gamma` 使用 `eta` 归一化。

3. **S2R 参数 Huber Loss**
   对带符号相对误差使用 Huber 损失，用于降低极端样本对训练的影响。

4. **S2R Quantile-Loss**
   直接优化关键可靠度分位点：

   ```text
   Loss_Q = mean over R [
       ((x_hat_R - x_R) / x_R)^2
   ]
   ```

   其中：

   ```text
   R ∈ {0.50, 0.90, 0.95, 0.99, 0.999}
   ```

5. **Hybrid-Loss**
   同时考虑参数估计和分位点估计：

   ```text
   Loss_total = alpha * Loss_param_rel + (1 - alpha) * Loss_quantile_rel
   ```

   第一版建议使用：

   ```text
   alpha ∈ {0, 0.25, 0.5, 0.75, 1.0}
   ```

   其中 `alpha=0` 表示纯分位点导向，`alpha=1` 表示纯参数导向。这样可以用一组实验同时观察参数导向、分位点导向和折中方案。

### 5.3 实验要回答的问题

损失函数验证实验要回答：

1. 参数导向 loss 是否更适合提高 `beta, eta, gamma` 的估计精度？
2. 分位点导向 loss 是否更适合提高关键可靠度寿命分位点的估计精度？
3. 混合 loss 是否能在参数精度和分位点精度之间取得平衡？
4. 某些 loss 是否更容易产生数值失败、边界病态或更重尾的误差分布？
5. 不同 loss 在小样本和大样本下是否表现不同？

### 5.4 选择标准

选择推荐 loss 时，优先看：

- 参数视角的 MdAPE、MedRel、RelIQR、P95(|e|)；
- 工程分位点视角的 MdAPE、MedRel、RelIQR、P95(|e|)；
- Valid Rate；
- Failure Rate；
- 失败原因分布；
- 按 gamma/eta、n、beta 分层后的方向偏差和尾部风险。

不要只看训练 loss 本身，也不要只看单一平均误差。

### 5.5 实验控制原则

损失函数对比实验中，除 loss 外的因素应尽量固定。

至少应控制：

- 模型结构；
- 输入特征；
- 训练集、验证集和测试集；
- 优化器；
- 学习率；
- batch size；
- 训练轮数或早停规则；
- 随机种子策略。

每种 loss 建议重复训练若干次，报告均值和方差。这样可以区分“loss 本身带来的差异”和“单次训练随机性带来的差异”。

## 6. 统一蒙特卡洛调度框架

旧平台中每新增一个方法就容易重新写一套蒙特卡洛流程。重构目标是建立统一调度框架。

### 6.1 框架职责

统一蒙特卡洛框架应负责：

1. 参数空间遍历；
2. 样本生成；
3. 重复模拟；
4. 调用估计方法；
5. 记录参数估计结果；
6. 记录成功、失败、失败原因和运行时间；
7. 统一保存结果；
8. 调用统一评价指标生成汇总。

所有蒙特卡洛样本必须可复现。给定参数组合、样本量和重复编号，应能确定生成同一份样本。这样后续方法扩展、结果复核和配对统计比较才有基础。

### 6.2 方法接入原则

各种估计方法，包括传统方法和 AI 方法，都应通过统一接口接入。

每个方法至少应能返回：

- 参数估计值；
- 是否成功；
- 失败、边界病态或数值病态说明；
- 运行时间；
- 方法特有的额外信息。

统一框架只关心“方法输入样本后输出结果”，不应把每个方法的内部实现写死在蒙特卡洛流程中。

### 6.3 方法接入契约

这里的“统一接口”不是要求提前规定具体函数名，而是要求所有方法遵守同一类输入输出契约。

输入侧应满足：

- 所有方法接收同一份样本；
- 普通估计方法不应读取真实参数；
- 用于训练标签生成或 oracle 对照的方法如果使用真实参数，必须在实验说明中标注。

输出侧应满足：

- 必须返回三参数估计结果，或明确说明未能返回；
- 必须返回求解状态；
- 必须返回运行时间；
- 必须保留足够解释方法行为的额外信息。

对于 M1 和 M4，额外信息尤其重要。例如：

- M1 应记录 AI 预测了什么过程量；
- M4 应记录优化算法的收敛状态、迭代次数或内部策略；
- M2 应记录使用的基础传统方法和修正前结果；
- M3 应记录输入表示和模型方案。

这些信息不要求在总纲中写死字段名，但必须在后续实现中被保留下来，否则结果无法解释。

### 6.4 结果保存原则

所有方法结果应保存为统一结构，方便后续指标计算和可视化。

结果中应至少能追溯：

- 样本来自哪个参数组合；
- 样本量；
- 随机重复编号或随机种子；
- 使用了哪个方法；
- 使用了哪个方法方案；
- 是否成功；
- 参数估计结果；
- 运行时间；
- 额外诊断信息。

不要把失败样本写成 `0` 或静默删除。失败和有效但误差很大的样本都是方法表现的一部分。

### 6.5 与旧代码的关系

重构应尽量复用旧平台中已经可用的传统方法、样本生成逻辑、可视化组件和结果展示能力。

不要为了新框架而无必要地大规模推翻旧代码。只要旧代码能在新统一接口下产出与重写版本数值一致的结果，就优先包装而不是重写。

优先做：

- 包装旧方法；
- 统一结果结构；
- 提取重复蒙特卡洛逻辑；
- 保留可复用的可视化和数据展示能力。

## 7. 建议实验参数空间

建议第一版实验使用适中的参数空间：

```text
beta ∈ {0.8, 1.2, 1.5, 2.0, 3.0, 5.0}
eta ∈ {50, 100, 200}
gamma / eta ∈ {0, 0.05, 0.10, 0.20}
n ∈ {10, 20, 30, 50, 100}
```

该参数空间覆盖：

- 不同分布形态；
- 不同尺度；
- 不同位置参数比例；
- 不同样本量；
- `gamma=0` 与非零位置参数场景。

参数空间不宜一开始过大。第一版目标是验证统一框架、指标和实验逻辑，而不是追求最大规模。

需要注意，三参数威布尔在 `eta` 和 `gamma` 上存在尺度效应。如果所有样本按 `eta` 缩放，很多方法在理论上应表现出相近规律。因此多个 `eta` 值主要用于检查数值稳定性和实现是否具备尺度一致性，而不是增加新的分布形态。

如果实验预算有限，主实验可以先固定 `eta=100`，把 `eta ∈ {50, 100, 200}` 作为数值稳定性扩展实验。

该参数空间完整展开为 `6 × 3 × 4 × 5 = 360` 个组合。若每组重复 1000 次，则每个方法需要约 36 万次估计。后续实现时应考虑缓存样本、复用结果和必要的并行执行。

## 8. 推荐实验顺序

### 阶段 1：整理旧平台

目标：

- 梳理已有传统方法；
- 梳理已有 AI 模块；
- 梳理已有蒙特卡洛脚本；
- 梳理已有评价指标；
- 梳理已有可视化功能。

产出：

- 当前能力清单；
- 可复用代码清单；
- 需要重构的重复流程清单。

### 阶段 2：建立统一评价指标体系

目标：

- 明确参数估计视角指标；
- 明确工程分位点视角指标；
- 明确有效率、失败率、尾部风险和时间指标；
- 明确所有方法统一评价方式。

产出：

- 统一指标说明；
- 指标计算口径；
- 后续可复用的指标计算入口。

### 阶段 3：做损失函数对比实验

目标：

- 使用简单 M3 模型比较不同 loss；
- 判断参数导向、分位点导向和混合导向 loss 的差异；
- 为后续 M1、M2、M3 训练提供依据。

产出：

- loss 对比表；
- 参数视角分布指标对比；
- 分位点视角分布指标对比；
- 每种 loss 的多次重复均值和方差；
- 推荐 loss 或推荐 loss 使用场景。

### 阶段 4：重构统一蒙特卡洛调度框架

目标：

- 用同一套流程生成样本、调用方法、保存结果、计算指标；
- 传统方法和 AI 方法都能接入；
- 避免每新增方法就重写一套流程。

产出：

- 可复用蒙特卡洛调度流程；
- 统一结果结构；
- 最小传统方法与 AI 方法接入示例；
- 样本共享、状态判定和失败原因记录规则。

### 阶段 5：整理和实现 M1、M2、M3、M4

目标：

- 将 AI 模块按新定义整理；
- 明确每类模块的输入、输出和研究问题；
- 将模块接入统一蒙特卡洛框架。

产出：

- M1 过程量预测实验；
- M2 误差修正实验；
- M3 直接估计与分类扩展实验；
- M4 智能优化实验。

### 阶段 6：统一横向比较

目标：

- 在同一参数空间、同一样本生成规则、同一评价指标下比较所有方法；
- 同时比较参数精度和工程分位点精度；
- 记录有效率、失败率、尾部风险和运行时间。

产出：

- 传统方法、M1、M2、M3、M4 的统一比较表；
- 分样本量、分参数区间的结果分析；
- 主要指标的均值、方差或置信区间；
- 方法优势和风险总结。

### 阶段 7：生成论文或组会结果

目标：

- 将统一结果转化为论文或组会可用表格和图；
- 明确说明实验设置、评价指标和结论边界。

产出：

- 结果表格；
- 可视化图；
- 方法比较结论；
- 后续研究方向。

## 9. 阶段验收标准

### 阶段 1 验收

- 已梳理旧平台中可复用的传统方法、AI 模块、蒙特卡洛脚本和可视化能力；
- 明确哪些内容保留、包装、整理，哪些内容不再作为正式研究结论；
- 没有无必要大规模推翻旧代码。

### 阶段 2 验收

- 所有方法都能使用同一套参数相对误差分布指标；
- 所有方法都能使用同一套可靠度分位点相对误差分布指标；
- Valid Rate、Failure Rate、Time 的统计口径明确；
- success、failure 的判定责任明确；
- 指标能解释“参数估计准不准”和“工程寿命估计准不准”两个问题。

### 阶段 3 验收

- 损失函数对比实验能输出清晰表格；
- 至少比较原始 MSE、S2R 参数相对误差 MSE、S2R 参数 Huber、S2R Quantile-Loss 和 Hybrid-Loss；
- 能说明不同 loss 对参数精度和分位点精度的影响；
- 除 loss 外的主要训练超参保持一致；
- 每种 loss 至少有重复实验，并报告结果波动；
- 能给出后续 AI 模块训练的推荐 loss 或推荐选择原则。

### 阶段 4 验收

- 同一个蒙特卡洛框架能调用传统方法和 AI 方法；
- 所有方法使用共享样本进行配对比较；
- 所有方法都能输出统一结构结果；
- 失败样本被保留，有效但误差很大的样本进入尾部统计；
- 不需要为每个新方法重写完整蒙特卡洛流程。

### 阶段 5 验收

- M1、M2、M3、M4 模块边界清晰；
- 每个模块都能说明输入、输出和研究问题；
- 至少有代表性方案能接入统一蒙特卡洛框架；
- M3 分类扩展被作为子方向处理，而不是替代连续估计主线。

### 阶段 6 验收

- 传统方法、M1、M2、M3、M4 能在同一结果表中横向比较；
- 结果同时包含参数视角和分位点视角；
- 能按样本量和参数空间分析方法表现；
- 主要结论有方差、置信区间或配对比较依据；
- 能说明不同方法的优势、失败场景和适用范围。

### 阶段 7 验收

- 结果表格和可视化图能用于论文或组会汇报；
- 图表和结论能追溯到统一实验设置；
- 关键结果能追溯到实验配置、随机种子策略和代码版本；
- 结论不夸大 AI 效果；
- 能清楚说明实验限制和下一步方向。

## 10. 文档边界与后续执行原则

本文档不是最终软件工程设计说明书，也不是代码实现计划。

后续 AI Coding 工具执行时应遵守：

1. 不要直接照本文档发明复杂类结构；
2. 不要提前写死所有文件名和函数名；
3. 不要为了满足文档而推翻旧平台可用代码；
4. 应先读现有代码结构，再决定最小重构路径；
5. 应优先包装和复用已有传统方法；
6. 应优先统一评价和结果结构，再扩展模型；
7. 每一步都要能产生可验收的中间结果。

本次重构的成功标准不是文档数量变多，也不是模型数量变多，而是：

```text
传统方法、AI 辅助方法、AI 直接方法和智能优化方法
能在同一参数空间、同一蒙特卡洛框架、同一评价指标下
进行可信、可解释、可复现的横向比较。
```
