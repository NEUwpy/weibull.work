# 可靠性图书馆

当前本机仍使用 v1 副本库 `D:\weibull-data\literature`。Weibull 网站负责读取、展示和问答取材；资料与程序分别保存、备份。本文同时记录已确认的目标及尚未切换的部分。

AI 维护先读 [AGENTS.md](AGENTS.md)；Hermes 的 `upload-to-weibull` 适用于当前 v1 副本导入，源库对齐和 JSON 直读任务按本页执行，不套用复制发布流程。`process-inbox` 仍负责博士源库入库。

## 目标：JSON 书票与一份源正文

软件 Git 保存程序、规范、必要产品样例及轻量 JSON 书票。书票记录编号、公开题录和来源定位；新批量蒙特卡洛数据外置，不进入软件或科研 Git。

论文正文和图片统一在 `D:\博士阶段\100科研文献管理\100科研文献管理`，书籍另设资料位置（路径待定）。既有论文以当前网站已校对版为迁移基线，先将正文、公式、图片、引用和格式修订对齐回 100，链接还原为源库可用的相对路径；保留原始 PDF。对齐验收后，本地网站直接读取这一份源正文；线上使用下节自动生成的发布快照，不人工维护第二份全文库。网站题录在 JSON 维护；机器路径配置留在本机，不提交凭证或私密笔记。

直读原型仅位于软件仓隔离分支 `codex/source-library-proof-20261028`，`WEIBULL_LIBRARY_ROOT` 指向包含 `library.json` 和 `references.json` 的配置目录。v2 示例：

```json
{
  "schema_version": 2,
  "mode": "source",
  "sources": [{
    "root": "D:/博士阶段/100科研文献管理/100科研文献管理",
    "papers": [{"id": "182-046", "metadata": {
      "title": "论文实际标题", "author": "实际作者", "year": 2025,
      "type": "期刊", "tags": ["参数估计"], "summary": "核实后的摘要"
    }}]
  }]
}
```

`metadata` 使用“网站字段、正文格式与 v1 示例”一节中的字段，优先于原译文 YAML 与笔记题录，未填字段兼容原资料；缺有效标题或年份会报错。源文件沿用 `<编号>-pdf原文.md`、`<编号>-pdf翻译.md`、`<编号>-图片/`，至少一份正文；只读选中编号及对应资源，历史目录不参与选篇，多个活动目录不猜版本。图片相对路径在读取时转换，私人笔记正文不公开。JSON 暂为文件编辑，尚无可视化表单。

**状态**：原型验证了7篇、13份原译文、105个配图地址，78项测试和构建通过，400个相关源文件哈希未变；正文质量差异仍待逐篇对齐。证据在 `D:\weibull-backups\source-library-prototype-20261028`。原型未合入日常 main，100 未批量回写，NAS 未切换，现有 v1 库及内置回退资料保留。上述原型及 v2 示例要求本地绝对源目录，不代表下节相对路径发布已实现；v2 不使用下文仅适用 v1 的 `import/check`。

## 线上：发布包内相对读取（已确认，待实现）

本机按 JSON 书票选择经核验的论文/书籍，将公开正文、配图、引用映射及网站必需的展示数据自动收集进发布包，再发送到 NAS。线上读取包内资料，不访问本机 D 盘或实时连接 100。目录关系示意如下，具体发布格式与打包器尚待实现：

```text
release/
├── app/                       网站运行文件
├── library/
│   ├── library.json            发布书票，资料定位用相对路径
│   ├── references.json
│   ├── content/                选用原译文
│   └── assets/                 对应配图与选用附件
└── data/                      网站实际使用的展示数据
```

书票内资料路径以书票文件所在目录为基准解析，不依赖终端的当前工作目录；浏览器图片网址仍由资源接口映射。发布包不包含源库绝对路径、私人笔记、凭证、OCR 中间文件或整套科研原始模拟数据；包及资料快照不进入软件 Git。打包时保存软件版本、选用编号与文件校验清单，用于核验和回退。

发布包是源库的生成快照，日常只编辑源库和 JSON 题录；资料更新后重新打包、验收并发布，不在线上手改快照。验收须把包复制到另一位置，从不同工作目录启动，核对题录、原译切换、公式、图片和引用，确认没有依赖本机源路径。该方向取代“NAS 挂载本机 100 源目录”的部署设想；当前并未执行打包或线上切换。

## 网站字段、正文格式与 v1 示例

使用 UTF-8 Markdown，顶部加 YAML 表头。以下示例需替换为真实信息；原译文的作者、年份等身份信息保持一致。

```markdown
---
title: "论文标题"
author: "作者"
year: 2024
type: "期刊"
tags: ["Weibull", "参数估计"]
summary: "论文摘要或简述"
---

# 论文标题

正文，引用示例 [1]。

![原论文图注](/182-046-图片/images/figure.jpg)

## 参考文献

[1] 按论文实际条目填写，保留与正文一致的编号。
```

`title` 必填；`type` 使用 `期刊`、`会议`、`书籍`，`tags` 为不重复的字符串数组。年份填实际发表年，缺失时列表会显示当前年；不猜测元数据。可另填字符串字段 `title_en`、`affiliation`、`publication`、`short_publication`，分别表示英文标题、作者单位、出版物全称及简称。公式使用 `$...$` 或独立成段的 `$$...$$`。

图片示例对应实际文件 `assets/182-046-图片/images/figure.jpg`。网址从 `/<编号>-图片/` 开始，用 `/`，保留真实文件名、大小写和子目录，空格可写 `%20`；支持 PNG、JPG/JPEG、GIF、WebP、SVG、AVIF。PDF 放在同一编号资源目录，用普通链接，如 `[PDF](/182-046-图片/paper.pdf)`，不会自动解析成正文。

参考文献放全文末尾，以 `## 参考文献` 或 `## References` 开始，每条一行，以 `[数字]` 开头。作者—年份制需核对对应关系后再转号，不能猜测。跨文章跳转写在库根 `references.json`，如 `{"182-046":{"1":"182-088"}}`，表示前者第 1 条引用指向已入库的后者；没有映射时条目仍可显示，不自动按题名或 DOI 匹配。

## 当前 v1 整理、导入与读取

从“博士阶段 100”选择确定版本，复制到独立批次目录，在副本上补表头、调整图片网址并核对正文；源文件不改。批次根直接放原文和/或译文及 `<编号>-图片/`，不套 `content/`、`assets/` 层，不混入历史副本或 OCR 中间文件。然后运行：

```powershell
node D:\weibull\scripts\library-data.mjs import --source-dir D:\incoming-papers --root D:\weibull-data\literature
node D:\weibull\scripts\library-data.mjs check --root D:\weibull-data\literature
```

导入只复制文件，不自动 OCR、翻译、补元数据或合并引用表；相同文件跳过，同名不同内容在复制前终止整批。修改已入库资料先备份。`check` 检查库结构、标题、标签类型和引用目标，图片、公式及原译文切换还需打开网页检查；刷新页面即可读取新增内容。

软件本地 `.env.local` 配置 `WEIBULL_LIBRARY_ROOT=D:/weibull-data/literature`，切换路径后重启前端；取消该配置及同名进程环境变量后重启则使用保留的内置库。NAS 使用其自身资料路径和软件的 `docker-compose.library.yml` 只读挂载，本机资料不会自动同步，线上尚未切换。

读取实现参照软件仓 `src/lib/server/literature.ts`，导入工具参照 `scripts/library-data.mjs`；本 README 与 AGENTS.md 的版本源为软件仓 `docs/library/`，两文件一起同步到资料库根。资料备份统一放 `D:\weibull-backups`，库内 `export-manifest.json` 仅记录初次导出，不代替后续备份。
