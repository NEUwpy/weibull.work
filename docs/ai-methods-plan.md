# 人工智能方法模块规划

> **状态**: 模块 1 原型完成
> **创建时间**: 2026-04-25
> **目标**: 为系统新增"人工智能方法"探索模块，与"参数估计方法"同级，探索 AI 辅助参数估计的效果与适用范围

---

## 一、模块定位

### 性质：探索平台，不是用户工具

本模块与"参数估计方法"（Methods）同级、同性质：
- **参数估计方法** = 探索传统统计方法（MDM、MLE、MMLE...），验证其正确性与适用范围
- **人工智能方法** = 探索 AI 如何辅助/替代这些传统方法，验证其效果与适用范围

两者最终会形成交叉：AI 方法可以作用于不同的传统方法。

### 在系统中的位置

```
导航（同级）:
  Calculator（计算器）        ← 用户工具
  Methods（参数估计方法）      ← 探索平台：传统方法
  ★ AI（人工智能方法）        ← 探索平台：AI 辅助方法（新增，紧跟 Methods 之后）
  Cases（案例数据库）
  Library（可靠性图书馆）

URL:
  /ai                        ← 总览页
  /ai/relationship           ← 关系建立（模块 1）
  /ai/optimization           ← 优化求解（模块 2，暂空）
  /ai/direct-estimation      ← 直接估计（模块 3）
```

### 三类用途划分

以 AI 介入参数估计的方式划分为三个子页面：

| 子页面 | 介入方式 | 本质 | 与传统方法的关系 |
|--------|---------|------|----------------|
| 关系建立 | AI 拟合复杂非线性关系 | 学习"样本 → 过程参数"的映射 | 替代人工选择过程参数 |
| 优化求解 | AI 辅助传统数值优化 | 仍走传统框架，AI 是辅助角色 | 增强传统方法 |
| 直接估计 | AI 端到端直接输出 | 完全绕过优化过程 | 替代传统方法 |

### 交叉矩阵视角

后续发展的目标是形成"AI 用途 × 传统方法"的交叉矩阵：

|  | MDM | MLE | MMLE | ... |
|--|-----|-----|------|-----|
| **关系建立** | δ 偏移量优化 ✓ | — | — | 待扩展 |
| **优化求解** | — | AI 辅助 MLE ✓ | — | 待扩展 |
| **直接估计** | — | — | — | 统一 |

✓ = 当前优先实现的项

## 二、子页面详细定义

> **模块 1 详细方案**: [ai-methods-module1-detail.md](ai-methods-module1-detail.md)

### 2.1 关系建立（Relationship）

**目的**: 探索 AI 建立"样本 → 最优过程参数"映射的效果与适用范围。

**当前实现**: MDM 偏移量 δ 优化
- 输入：样本数据（n 个值）+ 截尾形式
- 输出：最优偏移量 δ
- "最优"的评价标准：后续制定估计精度指标公式

**后续扩展**: 其他方法中也有类似的过程参数需要优化，接口预留。

**待确认问题**:
- [ ] 截尾形式如何编码为网络输入？（第二层级考虑）
- [ ] 样本量 n 是否作为显式输入？

---

### 2.2 优化求解（Optimization）

**目的**: 探索 AI 辅助传统数值优化方法（如 MLE 的 Nelder-Mead）的效果与适用范围。

**当前实现**: AI 辅助 MLE
- 仍走 MLE 框架（似然函数 → 数值优化 → β, η, γ）
- AI 的角色：辅助选择初始值 / 调整优化策略 / 其他
- 探索重点：AI 辅助后，求解质量是否优于传统方式

**后续扩展**: 其他方法的智能优化寻优。

**与模块 3 的本质区别**:
- 模块 2：传统优化框架 + AI 辅助 → 探索"AI 能不能让传统方法更好"
- 模块 3：无优化框架，神经网络直接前向传播 → 探索"AI 能不能直接替代求解过程"
- 这是两个不同的研究方向

**待确认问题**:
- [ ] AI 辅助的具体方式：初始值预测？优化步长调整？算法选择？
- [ ] 是否需要展示"有 AI 辅助 vs 无 AI 辅助"的对比？

---

### 2.3 直接估计（Direct Estimation）

**目的**: 探索神经网络端到端直接输出参数估计值的效果与适用范围。

**当前实现**: 样本 → β, η, γ
- 输入：样本数据（n 个值）+ 样本量 n
- 输出：β（形状参数）、η（尺度参数）、γ（位置参数）
- 无迭代优化，纯前向传播

**变长输入方案**: 按 n 分别训练独立模型（已确认）

**待确认问题**:
- [ ] 输入是否需要排序？
- [ ] 输出是否区分 2 参数（γ=0）和 3 参数模型？

## 三、AI 模型三要素

每个子页面的 AI 模型都需要明确以下三要素，且在系统页面中体现：

### 3.1 训练算法

| 要素 | 说明 |
|------|------|
| 网络结构 | 全连接？CNN？RNN？（取决于输入形式） |
| 损失函数 | 预测参数与真实参数的偏差度量 |
| 训练策略 | 学习率、批次大小、早停等 |

### 3.2 训练数据

- **来源**: 蒙特卡洛模拟生成（系统已有 studies/chunks 的基础）
- **生成方式**: 在系统外（Python 脚本）批量生成
- **数据规模**: 待确定（需覆盖不同 β、η、γ、n 的组合）
- **在系统中体现**: 训练数据的生成算法、参数范围、数据格式应在页面中记录

### 3.3 训练后的模型

- **形式**: 训练好的权重 / 推导出的公式
- **部署**: 放在后端 Python 中，前端调用 API
- **在系统中体现**: 模型的使用方式、输入输出格式、性能指标应在页面中展示

## 七、Tab 结构设计

参考 Methods 的多 Tab 结构，针对 AI 方法的特性调整：

### Methods 的 Tab（对照）

| Tab | Methods 含义 |
|-----|-------------|
| 原理文档 | 算法数学原理 |
| 程序流程 | 公式 → 代码映射 |
| 计算过程 | 迭代中间量可视化 |
| 结果分析 | 单次结果可信度评估 |
| 适用范围 | 蒙特卡洛系统性表现 |
| 可信性验证 | 论文复现 |
| 方法对比 | 横向对比 |

### AI Methods 的 Tab

| Tab | AI Methods 含义 | 与 Methods 的对应关系 |
|-----|----------------|---------------------|
| **原理说明** | AI 方法的原理、动机、与传统方法的关系 | ≈ 原理文档 |
| **训练算法** | 网络结构、损失函数、训练策略 | ≈ 程序流程（从"公式→代码"变为"数据→模型"） |
| **训练数据** | 数据生成方式、参数空间、样本量分布、数据规模 | 新增（AI 特有） |
| **在线使用** | 交互式输入样本 → 调用模型 → 输出结果 | ≈ 计算过程（从"展示中间量"变为"实际使用"） |
| **性能展示** | 准确度、与传统方法对比、适用范围分析 | ≈ 结果分析 + 适用范围 |
| **可信性验证** | 论文复现 / 已知参数验证 | ≈ 可信性验证 |
| **方法对比** | 不同 AI 方法的横向对比 | ≈ 方法对比 |

### Tab 详细说明

#### 1. 原理说明（Theory）
- 为什么需要 AI 辅助这个环节
- AI 方法与传统方法的关系
- 核心思路（如：为什么可以用神经网络学习偏移量）
- 相关文献

#### 2. 训练算法（Training）
- 网络结构图/描述
- 损失函数定义
- 超参数设置
- 训练过程描述（收敛曲线等）

#### 3. 训练数据（Data）
- 数据生成方式（蒙特卡洛模拟的参数设置）
- 参数空间（β、η、γ、n 的范围与步长）
- 样本量分布
- 数据规模（总样本数）
- 数据预处理方式

#### 4. 在线使用（Playground）
- 输入区域：样本数据输入（手动 / 案例库调用）
- 输出区域：模型预测结果（如最优 δ 或 β, η, γ）
- 与传统方法结果的即时对比

#### 5. 性能展示（Performance）
- 准确度指标（与真实参数的偏差）
- 与传统方法的对比（相同数据集上的表现）
- 适用范围分析（什么条件下好用 / 不好用）
- 可视化（热力图、箱型图等）

#### 6. 可信性验证（Verification）
- 已知参数的验证案例
- 与文献结果的对比
- 边界条件测试

#### 7. 方法对比（Compare）
- 不同 AI 方法在同一数据集上的对比
- （后续扩展）
