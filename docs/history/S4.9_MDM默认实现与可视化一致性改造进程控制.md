## 1. 背景

本阶段由最新研究稿触发：

`docs/research/对MDM方法有解性的证明/对MDM方法有解性的证明/full.md`

研究稿重新解释了当前系统 MDM 方法的 `no_intersection` 现象：

- MDM offset-root 在无约束可行域中几乎总存在；
- 当前系统的“无解”主要来自人为加入的 `gamma >= 0` 下界，把落在负半轴的根切掉；
- 少量“无解”来自离散均匀网格在靠近 `t_min` 处漏检；
- 若工程业务要求 `gamma >= 0`，负根应截断为 `gamma_hat = 0`，而不是判定方法失败；
- 若根在 `(0, t_min)` 内，应该用更能分辨靠近 `t_min` 区域的搜索方式定位。

这修正了 S4.5/S4.7 的旧说法。旧说法曾把 MDM failure 描述为 offset 判据的内点条件不满足或理论限制；现在应改为：

```text
MDM 本身并非固有无解。系统中的 no_intersection 主要是 gamma >= 0 约束切除和离散网格漏检造成的工程实现问题。
```

---

## 2. 与 182-046 原文的关系

182-046 原文强调的是“搜索-判断”的可见过程：

- 从最小样本值 `t_(1)` 开始逐步递减位置参数 `gamma_j`；
- 对每个 `gamma_j` 搜索一系列形状参数 `beta_k`；
- 得到条件最小标准差 `sigma_eta,min(gamma_j)`；
- 用该曲线关于位置参数的离散梯度判断极值点；
- 将极值判据从 `gradient = 0` 改为 `gradient = 0.1`，提升位置参数估计的稳健性。

当前系统已经与原文存在两处工程化差异：

| 项目 | 182-046 原文 | S4.9 实施前系统 |
|------|--------------|----------|
| gamma 搜索方向 | 从 `t_(1)` 开始向下搜索 | 在 `[0, t_min)` 内两段均匀网格搜索 |
| beta 搜索 | 离散扫描，如 0.10、0.11、... | `scipy.optimize.minimize_scalar` 连续有界优化 |

S4.9 不应进一步扩大“过程展示”和“实际求解”的差异。前端计算过程 Tab 的目的就是展示 MDM 的求解过程量，因此后端返回的 `grad_gamma_curve`、`sigma_beta_gamma`、`optimal_gamma` 必须与实际求解逻辑一致。

---

## 3. S4.9 目标

S4.9 的目标是形成一个好用、可解释、与最新研究一致的默认 MDM 方法：

1. 默认 MDM 不再因为 offset-root 在 `[0, t_min)` 内无交点而返回失败。
2. 保留 MDM 的“搜索-判断”过程语义，尽量贴近 182-046。
3. 前端可视化展示的过程量必须来自实际求解过程，而不是旧算法的残留曲线。
4. `gamma_steps` 继续有意义，但它应表示“搜索/可视化采样密度”，而不是失败与否的脆弱开关。
5. 历史研究变体可以迁移到归档位置，不再暴露为当前默认候选。

---

## 4. 非目标

S4.9 暂不做以下事情：

- 不训练 AI 模型；
- 不启动 S3 loss 对比实验；
- 不用旧 NE/NQE/outlier 口径重写结论；
- 不把 MDM 变成纯 Brent 黑箱求解器；
- 不保留“前端显示旧离散曲线、后端实际用另一套求解”的不一致状态。

## 5. 代码状态

生产 MDM 入口：

- `python/methods/mdm.py`

实施前行为：

- 在 `[0, 0.99*t_min]` 和 `[0.99*t_min, 0.999999*t_min]` 上做两段均匀网格；
- 每个 `gamma` 上用 `minimize_scalar` 搜 `beta*(gamma)`；
- 用 `np.gradient(sigma_mins, gammas)` 计算离散梯度；
- 若 `gradient - offset` 没有符号变化，返回 `(None, None, None, None, "no_intersection")`；
- trace 数据中的 `grad_gamma_curve` 和 `sigma_beta_gamma` 基于该旧网格生成。

- 方法详情页和计算器使用后端返回结果绘图；
- MDM 可视化组件依赖 `trace_data.grad_gamma_curve`、`trace_data.sigma_beta_gamma`、`trace_data.optimal_gamma`、`trace_data.optimal_beta`。

研究变体：

- `python/methods/mdm_variants.py`
- `python/tests/test_mdm_variants.py`
- `python/studies/s4_5_*`
- `python/studies/s4_7_*`

这些文件是 S4.5/S4.7 研究产物，不应继续作为当前默认 MDM 的生产候选来源。S4.9 已将它们迁移到 `_archive/S4.9_MDM研究变体已完成/`。

S4.9 实施后行为：

- 默认 MDM 使用 `geometric_from_tmin` 网格，从接近 `t_min` 的位置向 0 展开；
- `gamma_steps` 保留为外层离散搜索和过程可视化采样密度；
- 有 offset 交点时使用离散曲线线性插值得到 `gamma_hat`；
- 无交点且 `gamma=0` 处梯度仍高于 offset 时，返回 `gamma_hat = 0`，trace 写入 `solution_strategy = "truncated_at_zero"`；
- trace 新增 `search_strategy`、`solution_strategy`、`constraint`、`probe_gradient_at_zero`、`root_bracket`、`gamma_steps`；
- 前端主可视化和 offset 敏感性分析均读取后端 trace 的实际求解策略。

## 6. 推荐实现方向

推荐采用“离散搜索过程 + 约束边界规则 + 可选局部精修”的方案。

### 6.1 搜索网格

保留离散搜索过程，但替换当前两段均匀网格。

新的 gamma 搜索应更接近 182-046 的“从 `t_(1)` 向下搜索”：

- 搜索域仍按系统业务约束输出到 `[0, t_min)`；
- 采样应从贴近 `t_min` 的位置向 0 展开；
- 靠近 `t_min` 的区域使用几何加密，避免根贴近 `t_min` 时漏检；
- `gamma_steps` 继续作为采样密度参数，控制过程曲线点数和计算预算。

建议先用约 60 个过程点作为默认 trace 密度；如果后续发现可视化曲线过疏，再单独调高 trace 采样点，而不是改变方法语义。

### 6.2 offset-root 判定

在离散梯度曲线上寻找 `gradient = offset`：

- 如果存在符号变化，继续使用离散曲线插值确定 `gamma_hat`；
- 可选：在找到的相邻区间内用包络梯度或更细局部搜索精修，但 trace 中必须记录该精修来源；
- 如果全段 `gradient > offset`，按最新研究解释为“无约束根在 `gamma < 0`，被系统约束切除”，输出 `gamma_hat = 0`；
- 如果全段 `gradient < offset`，说明根可能贴近 `t_min` 或采样仍不足，应先通过靠近 `t_min` 的加密点恢复，不应直接返回失败。

### 6.3 trace 数据

trace 数据必须同步表达实际求解过程。

建议增加字段：

| 字段 | 含义 |
|------|------|
| `search_strategy` | 如 `geometric_from_tmin` |
| `solution_strategy` | `offset_root`、`truncated_at_zero`、`local_refined_root` |
| `constraint` | `gamma >= 0` |
| `probe_gradient_at_zero` | `gamma=0` 处梯度，用于解释截断 |
| `root_bracket` | 找到交点时的左右端点 |
| `gamma_steps` | 本次过程曲线采样密度 |

前端可视化应使用这些字段说明当前结果来自交点、截断还是局部精修。

## 11. S4.9.2 MDM 相关一致性审查

审查日期：2026-06-05

本节记录 S4.9 默认 MDM 改造完成后的全项目一致性检查结果。后续如果继续清理 MDM 相关页面、数据和脚本，应以本节作为整改入口。

### 11.1 审查边界

本轮只检查与默认 MDM 改造直接相关的内容，不处理泛化的历史资料清理。

纳入检查：

- 默认 MDM 后端调用链；
- MDM 方法页和相关可视化组件；
- AI 关系建立与直接估计页面中引用的 MDM 结果数据；
- MDM 曲线性质研究展示及数据生成脚本；
- 当前接手提示词、状态控制文档和更新日志；
- 仍留在当前源码目录中的旧 MDM 变体或 case-study 专用实现。

不纳入当前整改：

- `_archive/` 中的归档文件；
- `docs/history/` 中明确作为历史记录保存的旧文档；
- 最新研究稿本身及其背景资料；

### 11.2 总体结论

核心生产路径已经与 S4.9 一致：

- `python/methods/registry.py` 中默认 `mdm` 指向 `python/methods/mdm.py`；
- 计算器、3D surface、统一 runner 均会调用新版默认 `MDM`；
- 主过程可视化和 offset 敏感性分析已经读取 `solution_strategy`、`search_strategy` 等 trace 字段；
- `python -m pytest tests -q` 与 `npx tsc --noEmit` 已在 S4.9 实施后通过。
