## 1. 总体判断

**方向正确，结构骨架可以保留，但 V1 还不能直接进入实现。**

值得保留的部分：

- 三层结构（输入 / 结果 / 统计）划分清楚，能同时支撑 per-sample 重算、按子集切片、跨方法对比。
- 明确区分参数层 / 应用层 / 方法层，符合可靠性研究的层级关系。
- γ 不用普通 MRE、显式约定失败样本不进入误差但进入分母——这两个决定都对，论文/组会能站得住。
- 训练损失与评价指标分开陈述，没有把训练 loss 当成最终结论的口径，研究方法论上是干净的。

但是有 4 类问题必须在 V1 前修掉，否则 M1-B 几乎无法证伪、跨方法对比也站不住脚（详见第 2 节）：

1. 缺少**偏差/方差分解**，M1-B 的研究目标无法被它自己的指标衡量。
2. 缺少**共同成功集对比口径**，M1 与 baseline 的对比是带偏的。
3. B1/B5/B10 用 MRE 时**分母同样会爆炸**，需要和 γ 一样保护。
4. 缺少**outlier 与 success 的区分定义**，方法层成功率会高估稳健性。

## 2. 必须修改的问题

### 2.1 M1-B 必须显式报告偏差和方差，不能只看 MAE

M1-B 的研究假设是「传统方法存在**系统性偏差**，AI 学这个偏差」。如果只用 MAE，你无法证明 AI 真的在修正偏差，还是只是把噪声平均了。

V1 起就需要补：

```text
bias_beta_base       = mean(beta_hat_base - beta_true)
bias_beta_corrected  = mean(beta_hat_corrected - beta_true)
bias_log_beta_base       = mean(log(beta_hat_base) - log(beta_true))
bias_log_beta_corrected  = mean(log(beta_hat_corrected) - log(beta_true))
std_beta_base       = std(beta_hat_base - beta_true)
std_beta_corrected  = std(beta_hat_corrected - beta_true)
```

`bias_log_*` 对 β、η 比 `bias_*` 更稳，因为 β、η 跨多个量级。

对 γ：

```text
bias_gamma_scaled_base       = mean((gamma_hat_base - gamma_true) / eta_true)
bias_gamma_scaled_corrected  = mean((gamma_hat_corrected - gamma_true) / eta_true)
```

研究结论模板应该是：「M1-B 把 log η 的 bias 从 +0.12 降到 +0.01，std 从 0.18 降到 0.16」——而不是只说「MAE 降低 X%」。

### 2.2 跨方法比较必须有「共同成功集」口径

当前规则下：

- MLE 成功率 90%，AI 修正后成功率 95%。
- 双方在各自成功子集上算 MAE。
- 但这两个子集不是同一个集合，比较是带偏的（AI 救活的那 5% 通常是难样本，会把 AI 的 MAE 推高；反之也可能）。

必须再加一组指标：

```text
mae_beta_common      # 仅在两个方法都 success 的样本上计算
b10_mre_common
common_count         # 共同成功样本数
common_ratio         # common_count / total_count
```

强烈建议**主表用共同成功集**，分立成功集只作为附表。`/help/metrics` 页面也要说清楚这一点。

### 2.3 B1/B5/B10 用 MRE 的分母保护

你已经识别出 γ-MRE 在 γ_true→0 时爆炸。同样的事情在 B-life 上也会发生：

```text
B_p_true = gamma_true + eta_true * [-ln(1-p)]^(1/beta_true)
```

当 γ_true=0、β_true<1、p=0.01 时，B1_true 会比 η_true 小 3~4 个数量级。例如 η=1000、β=0.5、γ=0：

```text
B1_true = 1000 * (0.01005)^2 ≈ 0.10
```

任何方法在这个区域报 B1_hat ≈ 1.0，B1_MRE 就是 9。这种情况在 β∈[0.5, 1] 的训练分布里完全会发生。

V1 应该加一个 η 归一的版本，和 γ 口径对齐：

```text
B1_scaled_error  = abs(B1_hat - B1_true) / eta_true
B5_scaled_error  = abs(B5_hat - B5_true) / eta_true
B10_scaled_error = abs(B10_hat - B10_true) / eta_true
```

**主表用 scaled，MRE 只作为参考列**，并约定：

```text
B_p_mre 仅在 B_p_true > tau * eta_true 时计入聚合统计
tau 建议 1e-3，写进 /help/metrics
```

### 2.4 success / outlier / failure 三者必须分开

当前 `success_rate` 二分太粗。LSM/WLSM 经常返回「在数值上没崩、但 β_hat=50、η_hat=1e-6」这种垃圾结果，它会被算成 success，然后污染 MAE。

V1 建议三态：

```text
status ∈ {success, outlier, failed}

outlier 判定（满足任意一条）：
- abs(log(beta_hat / beta_true)) > log(10)         # 一个量级
- abs(log(eta_hat / eta_true))  > log(10)
- abs(gamma_hat - gamma_true) / eta_true > 1
- abs(B10_hat - B10_true) / eta_true > 5
```

聚合时：

```text
success_rate = success_count / total_count
outlier_rate = outlier_count / total_count
failure_rate = failed_count  / total_count
usable_rate  = success_count / total_count     # 仅 success 才算真正可用
robust_rate  = (success_count + outlier_count) / total_count  # 数值上没崩

参数层、应用层主指标：仅在 success 上计算
对照附表：在 success ∪ outlier 上计算（看异常如何拉高 MAE）
```

阈值需要在 `/help/metrics` 写死，并且**不要随论文调整**，否则口径就废了。

## 3. 建议补充的问题（V1 推荐加入）

### 3.1 误差分布的尾部统计

只看 mean 会掩盖尾风险。建议每个参数层和应用层主指标都加四件套：

```text
mean / median / P90 / P95 / max
```

这对 M3 特别重要——AI 容易在分布中央表现好但尾部失控。

### 3.2 按参数区间分层报告（stratification）

至少按以下维度做分层：

```text
by_beta_regime: beta_true ∈ {[0.5,1), [1,2), [2,3), [3,5], [5,10]}
by_n: n ∈ {10, 20, 50, 100, 200}
by_gamma_regime: gamma_true / eta_true ∈ {0, (0, 0.1], (0.1, 0.5], (0.5, 1.0]}
by_validation_type: organic / interpolation / extrapolation
```

研究结论里「M3 在小样本 + 大 β 区间相对 MLE 改善 30%」比「M3 整体 MRE 0.08」有信息量得多，导师/审稿人也吃这一套。

### 3.3 γ regime 识别指标

当 γ_true = 0 时，最重要的不是「γ_hat 多准」，而是「AI 有没有错误地预测一个正的 γ_hat」。建议：

```text
gamma_false_positive_rate  = P(gamma_hat > 0.05 * eta_true | gamma_true = 0)
gamma_false_negative_rate  = P(gamma_hat < 0.05 * eta_true | gamma_true > 0.1 * eta_true)
```

这是 γ 估计的「分类」面，和回归误差互补。

### 3.4 log-scale MAE（与 loss 口径对齐）

你训练 loss 用 `abs(log(β_hat) - log(β_true))`，评价却用 MAE/MRE，训练目标和评价指标在解释上略错位。建议补：

```text
mae_log_beta = mean(abs(log(beta_hat) - log(beta_true)))
mae_log_eta  = mean(abs(log(eta_hat)  - log(eta_true)))
```

它和 MRE 在小误差区近似相等，但在大误差区更稳；论文里画收敛曲线也是它。

### 3.5 B50 作为参考（中位寿命）

仅有下尾会让 AI 的「中央拟合好但尾差」无法暴露。建议加 B50：

```text
B50_life = Q_0.50 = gamma + eta * (ln 2)^(1/beta)
```

主表用 B1/B5/B10，B50 在附表，用来诊断 AI 是不是在「拟合中央而牺牲尾」。

## 4. 可以暂缓的问题（V2 或之后）

1. **CDF / KS / AD 分布层指标**——合成数据有 true θ，分布层冗余；上真实数据再加，V1 不必。
2. **总分（composite score）**——V1 风险大于收益。如果只是为了模型选择，可以在 `/help/metrics` 暂留一个非公开的 `model_selection_score` 给自己用，但**不进主表、不进论文**。
3. **端到端可微 M1-A**（differentiate through MDM）——研究上有趣，工程上代价高，V2 再说。
4. **bootstrap / 置信区间**——V1 给 mean 就够了，置信区间 V2 上。
5. **多模型 ensemble 指标**——M3 V1 跑通后再说。

## 5. 对 M1-A 的建议

1. **δ 误差不是主指标，只作为过程诊断**。你自己已经写对了，坚持这个立场。
2. **主指标 = AI-δ + MDM 的下游表现 vs baseline-δ + MDM 的下游表现**，在共同成功集上对比。
3. δ label 本身有噪声，建议每条样本带 `label_quality_flag ∈ {clean, noisy, fallback}`，并提供 `loss_delta | flag` 的分层统计。
4. **必须有「AI-δ 退化为常数 δ」的 ablation**，例如 AI-δ vs δ=0、AI-δ vs δ=最优常数 δ（在 train 上找的全局最优）。如果 AI-δ 打不过常数 δ，M1-A 就没有研究价值，要承认。
5. M1-A 的字段建议补：

```text
delta_baseline       # MDM 默认 δ
delta_constant_best  # train 上找的全局最优常数 δ
delta_hat            # AI 输出
beta_hat_delta_const, eta_hat_delta_const, gamma_hat_delta_const   # 用常数 δ 的 MDM 输出
```

这样三组对比（默认 / 常数最优 / AI）在一张表里直接读出来。

## 6. 对 M1-B 的建议

1. **V1 先做参数残差修正**（你目前的方案），但**评价必须同时报告 B1/B5/B10 的改善**。
2. **残差表示**要明确选 multiplicative vs additive：

```text
对 beta、eta：multiplicative 残差，r = log(theta_corrected) - log(theta_base)
              <=> theta_corrected = theta_base * exp(r)
对 gamma：    additive 残差，    r = gamma_corrected - gamma_base
              <=> gamma_corrected = gamma_base + r
```

理由：β、η 跨量级，加性残差在不同量级样本上方差不一致；γ 可以是 0，乘性会出问题。`docs/AI辅助参数估计指标定义方案草案.md` 里应该明确写这个约定，否则不同实现会发散。

3. **必须报告 bias 和 std 的变化**（见 2.1）。M1-B 的研究合法性完全建立在「降 bias、不显著抬 std」上。
4. **失败传染**：M1-B 依赖 traditional estimator 的输出。如果 traditional 失败，M1-B 也失败。要约定：

```text
M1-B 的 success ⊆ traditional 的 success
M1-B 的 success_rate 分母 = total，不是 traditional 的 success 数
```

否则 M1-B 看起来成功率很高，其实是「在传统方法已经成功的样本上又成功了一次」。

5. **B-life 不要在 V1 进 loss**，先纯参数残差训练，看 B-life 在评价上是否自动改善。如果不改善，V2 再加 B-life loss（你已经写了 alpha 组合形式，这个设计是对的）。

## 7. 对 M3 的建议

1. log β / log η 作为 target 合理，建议同时在 model output 上 clip：

```text
log_beta_hat  ∈ [log(0.1), log(20)]
log_eta_hat   ∈ [log(1),   log(1e6)]
gamma_hat     ∈ [0,        max_observed_t_min]   # 物理约束
```

避免 AI 在尾部产生荒唐数。

2. **输入表示**要并列实验，不要混在一起报：

```text
input_representation ∈ {raw_sample, padded_sample, mask_padded_sample, summary_features, hybrid}
```

每种都单独训一组，结果按这个维度分层报告，不要平均。

3. **顺序/排列等变性**：原始样本顺序对真实参数无关，但 MLP/Transformer 对顺序敏感。建议固定输入为「升序样本」，或在 `/help/metrics` 里写清「输入是否排序」。
4. **n 不固定**问题：训练集 n 分布要和测试集对齐。如果训练用 n=20~100 但测试 n=10，外推会很差，这是 M3 的固有弱点，**应该在 validation_type 中显式拆 n-extrapolation**：

```text
validation_type ∈ {organic, interpolation, parameter_extrapolation, n_extrapolation}
```

5. **不能只比 MLE/MDM**，至少要加一个朴素 baseline：

```text
naive_baseline: beta_hat = mean(beta_train), eta_hat = mean(eta_train), gamma_hat = 0
```

如果 M3 打不过这个，说明 AI 根本没学到信号——这件事必须先排除。

## 8. 对训练损失函数的建议

总体方向（log β、log η、scaled γ）正确，下面是细节：

### 8.1 M3

你的草案：

```text
loss_param = w_beta  * |log(beta_hat) - log(beta_true)|
           + w_eta   * |log(eta_hat)  - log(eta_true)|
           + w_gamma * |gamma_hat - gamma_true| / eta_true
```

建议改进：

1. 把 L1 换成 Huber（δ=0.1 量级）。Weibull 估计在 β<1 区间会有重尾误差，L1 易被尾样本拉飞。
2. `w_beta` / `w_eta` / `w_gamma` 不要拍脑袋，**用每个分量在训练集上各方法 baseline 的 std 反向加权**：

```text
w_i = 1 / std_i(baseline_error)
```

让三项 loss 在数量级上接近，再手调微调。

3. `loss_life` 用 MRE 在 β<1 区间会爆炸（理由同 2.3），训练阶段建议改成：

```text
loss_life = v1  * |log(B1_hat / B1_true)|
          + v5  * |log(B5_hat / B5_true)|
          + v10 * |log(B10_hat / B10_true)|
```

log 比值天然有界于 [0, ∞)，对 B_true 接近 0 也稳定。注意 B_hat 可能因 γ_hat > t_min 而出负或近零，需要在前向加 ε clip。

4. **α=1 起步（纯参数 loss）**。先证明纯参数 loss 在 B-life 上能 work，再考虑 α<1。

### 8.2 M1-A

`loss_delta = |delta_hat - delta_label|` 是合理的训练 loss，但**必须配 early stopping on downstream metric**：

```text
early_stop_metric = mae_log_eta(MDM(delta_hat))   # MDM 套 AI δ 后的下游误差
```

否则 AI 会在 δ 上过拟合 label 噪声，下游反而变差。

### 8.3 M1-B

形式上和 M3 一样，但有一个隐含选择必须显式：是 fit 「目标 θ_true」还是 fit 「残差 θ_true - θ_base」？两者数学等价，但**数值条件数不同**。建议直接 fit 残差（在 log 空间或 scaled 空间），输出层激活前加上 `theta_base`，这样 AI 默认输出 0 就等同于不修正，初始化更安全。

## 9. 对失败样本和异常样本统计的建议

1. **三态 status**（success / outlier / failed），见 2.4。
2. **failure_reason 必须分类**，最少包括：

```text
failure_reason ∈ {
  convergence_fail,       # 优化未收敛
  numeric_overflow,       # NaN / Inf
  invalid_param,          # β<=0 / η<=0 / γ > t_min
  timeout,
  exception,
  not_attempted           # 例如 M1-B 依赖的 traditional 已失败
}
```

`failure_reason_distribution` 应该是这 6 类的频率表，不是自由文本。

3. **runtime 分别报 success/failed**：

```text
mean_runtime_ms_success
mean_runtime_ms_failed
p95_runtime_ms
```

AI 方法 runtime 方差极小，传统方法在失败样本上 runtime 可能爆炸，平均合在一起会误导。

4. **不要用「失败样本 = inf 误差」回填**。有些库会这样做来「惩罚失败」，但这会让 MAE 完全由失败率主导，本末倒置。坚持你当前的「success 才算误差，total 才算成功率」。
5. **outlier 阈值锁定**：写进 `/help/metrics` 后**不能为了好看而修改**。如果未来要调，必须重跑全部历史结果，并在文档里标 v1/v2。

## 10. 最终建议

**结论：方向正确，骨架可以保留，但不建议直接以当前草案进入 `/help/metrics` 和公共函数实现。**

进入实现前，至少完成以下 7 件事（按优先级）：

1. 把 status 从 2 态扩到 3 态（success / outlier / failed），定义并锁定 outlier 阈值。
2. 在主表加入 `*_common`（共同成功集）口径，写清楚为什么需要。
3. B-life 加 `B_p_scaled_error = |B_p_hat - B_p_true| / eta_true`，主表用 scaled，MRE 作参考列并加 `B_p_true > tau * eta_true` 保护。
4. M1-B 加入 `bias_*` 和 `std_*` 指标——这是 M1-B 唯一能被证伪的口径。
5. 明确 M1-B 的残差表示（β、η 乘性，γ 加性）。
6. 训练 loss 用 log 比例形式（B-life 部分）、加 Huber，权重用 baseline std 反向归一。
7. `failure_reason` 改成枚举，不接受自由文本。

完成这 7 件事后，建议先把 `/help/metrics` 文档写出来，**并先在 M1-A 上跑一次完整 dry-run**（不训练新模型，只用现有 M1-A 原型套新指标体系）。如果新指标能复现旧 M1-A 的结论方向、又能多揭示 1~2 个新的现象（例如「旧 M1-A 在 β<1 区间没改善」），说明指标体系有判别力，可以正式进入 V1。

可以**暂缓**的：CDF/KS、composite score、置信区间、ensemble、端到端可微 M1-A——这些都放到 V2。
