## 1. 总体判断

草案整体质量较高。三层分类（输入/结果/统计）清晰，γ 禁用普通 MRE 的判断正确，B-life 应用层指标的必要性论证充分，训练损失与最终评价分离的原则合理。**可以作为 V1 的基础框架进入实现阶段**，但有若干必须修改的问题和若干建议补充项需要先处理。

## 2. 必须修改的问题

### 2.1 B-life MRE 分母保护规则缺失（高风险）

**问题**：第 6.2 节定义了 `B1_life_mre = mean(abs(B1_hat - B1_true) / abs(B1_true))`，但没有任何分母保护。

**风险场景**：三参数 Weibull 中，当 γ 接近于 η 时：

```
B1_true = γ + η·[-ln(0.99)]^(1/β)
```

`-ln(0.99) ≈ 0.01005`，当 β 较大（如 β=5）时，`0.01005^(1/5) ≈ 0.398`，所以 `B1_true ≈ γ + 0.398·η`。如果 γ_true 本身很小而 η 也不大，B1_true 可能很小，导致 MRE 爆炸。更极端的情况：如果训练数据中存在 γ < 0 的样本（三参数 Weibull 允许），B1_true 可能接近 0 甚至为负，`abs(B1_true)` 保护不够。

**建议修改**：

```text
# 方案 A：加下限截断
B1_life_mre = mean( abs(B1_hat - B1_true) / max(abs(B1_true), epsilon) )

其中 epsilon = max(1e-6, 0.001 * mean(abs(B1_true)) in group)

# 方案 B（推荐）：同时报告 MAE 和 MRE，MRE 带截断标记
当 B1_true < threshold 时，该样本标记为 low_denominator，
MRE 统计时排除此类样本但记录其比例。
```

**适用范围**：此问题同样影响 `loss_life` 中的 B-life 相对误差项（第 10.1 节），训练时也需要保护。

### 2.2 `scaled_gamma_error` 的 η_true 分母未讨论极端情况

**问题**：`scaled_gamma_error = abs(gamma_hat - gamma_true) / eta_true`，当 η_true 很小时（如 η_true < 0.1），即使 γ 误差很小，scaled_gamma_error 也会很大。

**风险**：在参数空间中如果包含小 η 样本，该指标会被小 η 样本主导。

**建议**：在第 5.1 节补充说明：

```text
scaled_gamma_error 在 η_true < eta_threshold 的样本中应单独标记。
建议按 η_true 分档报告 scaled_gamma_error，
避免小 η 样本主导整体均值。
```

### 2.3 `outlier_ratio` 的异常规则 `gamma_hat >= min(sample)` 不够健壮

**问题**（第 7.3 节）：`min(sample)` 是样本统计量而非参数，小样本下波动大。且 `>=` 意味着只要 γ_hat 等于样本最小值就标记为异常，这过于严格。

**建议修改**：

```text
outlier 定义改为：
  beta_hat <= 0
  eta_hat <= 0
  gamma_hat > min(sample) + k * (max(sample) - min(sample))   # k 建议 0.05
  non_finite_output
  B1_life_hat < 0   # 新增：工程寿命为负也是异常
```

## 3. 建议补充的问题

### 3.1 缺少 β 的 MRE 适用范围讨论

β 是形状参数，理论上 β > 0。但 β 的典型范围是 [0.5, 10] 左右，MRE 分母 `abs(beta_true)` 在 β_true 接近 0.5 时不会太小。**当前 MRE_beta 定义没有问题**，但建议在文档中注明 β 的典型范围和 MRE 的适用前提。

### 3.2 缺少分档统计的明确要求

第 11 节提到按 `method/scheme/validation_type/n` 分组，但没有强制要求按参数空间分档。建议补充：

```text
必须支持按以下维度分档统计：
  - n 档：5, 7, 10, 15, 20, ...
  - gamma_true 档：0附近, 中等, 大偏移
  - beta_true 档：小(<1), 中(1-3), 大(>3)

禁止仅报告全量平均值而不分档。
```

这对后续发现 AI 方法的适用边界至关重要。

### 3.3 建议增加 `relative_B_life_error` 的加权版本

当前 B1/B5/B10 三个寿命指标权重相等，但在可靠性工程中，B1（99% 可靠度）通常比 B10 更重要。建议：

```text
V1 可以先等权，但文档中应注明 V2 可考虑：
weighted_life_error = w1*B1_mre + w5*B5_mre + w10*B10_mre
其中 w1 > w5 > w10
```

### 3.4 缺少方法间对比的统计检验

当前指标方案只有点估计（均值），没有置信区间或显著性检验。建议 V1 补充：

```text
每个指标报告：
  - mean
  - std
  - median
  - [5th, 95th] percentile

方法间对比：
  - 配对 t 检验或 Wilcoxon 检验（同一测试集上不同方法的结果是配对的）
```

这不是 V1 阻塞项，但应写入 V2 计划。

### 3.5 `failure_reason` 枚举建议补充

当前枚举缺少：

```text
singular_jacobian    # MLE 中 Fisher 信息矩阵奇异
negative_scale       # η 估计为负
boundary_solution    # 解落在参数空间边界
```

## 5. 对 M1-A 的建议

**δ 误差应作为过程诊断指标，不作为主指标。** 理由：

1. δ 的"正确值"本身就依赖于标签生成策略。如果标签是搜索最优 δ，那么 AI 学习的是搜索结果的近似，不是物理真理。
2. δ 预测准不等于 MDM 结果好——δ 误差和参数误差之间的映射是非线性的。
3. 存在 δ 误差相同但参数误差不同的情况（δ 误差在平坦区域 vs 敏感区域）。

**建议指标层次**：

```text
主指标：MDM_ai_delta vs MDM_search_delta 的参数层和应用层改善
过程诊断：delta_mae, delta_mre, label_quality_distribution
必须报告：MDM_fixed_delta (δ=0 或 δ=0.5) 作为最简基准
```

## 6. 对 M1-B 的建议

**优先修正参数残差，而非直接修正 B-life。** 理由：

1. 参数空间是 3 维（β, η, γ），B-life 空间是 3 维（B1, B5, B10），但参数到 B-life 的映射是非线性的。直接修正 B-life 意味着 AI 需要同时学习非线性映射和修正规律。
2. 参数残差的结构更简单（传统方法的偏差模式可能有解析形式），更容易学习。
3. 如果参数修正后 B-life 仍然不好，再加入 B-life 残差作为辅助损失。

**但有一个关键补充**：M1-B 必须报告修正后参数是否产生物理非法值。即：

```text
beta_corrected = beta_base + residual_beta_hat
必须检查 beta_corrected > 0
eta_corrected = eta_base + residual_eta_hat
必须检查 eta_corrected > 0
```

如果残差网络输出导致非法参数，需要截断或改用乘法修正：

```text
beta_corrected = beta_base * exp(residual_log_beta_hat)  # 保证正数
```

## 7. 对 M3 的建议

1. **输入表示必须在指标方案中明确记录**。当前草案第 4.2 节列出 `input_representation` 但没有定义。M3 的精度高度依赖于输入表示（原始样本 vs 排序样本 vs 统计特征 vs 混合），这个字段在指标审计时必须可查。

2. **必须区分"模型能力"和"数据质量"**。M3 在 ig（组内）表现好不代表泛化好。建议在 M3 指标报告中强制加入：

```text
ig_ip_gap  = mean(ig_metric) - mean(ip_metric)
ig_ex_gap  = mean(ig_metric) - mean(ex_metric)
```

差距过大说明过拟合或参数空间覆盖不足。

3. **M3 各输入方案之间的对比必须在同一测试集上进行**。草案已提到这一点，但需要再次强调：不同方案如果测试集不同，对比无意义。

## 8. 对训练损失函数的建议

1. **`loss_param` 中的 `abs(log(beta_hat) - log(beta_true))` 是 L1 损失（MAE 形式），不是 MSE**。这没问题，但需要明确：L1 对异常值更鲁棒，L2 对大误差更敏感。建议在文档中注明这是设计选择而非遗漏。

2. **`loss_life` 中的 B-life 相对误差同样需要分母保护**，与第 2.1 节同理。

3. **权重 `w_beta`, `w_eta`, `w_gamma`, `v1`, `v5`, `v10` 和 `alpha` 的选择策略需要记录**。建议：

```text
V1 默认等权：w_beta = w_eta = w_gamma = 1, alpha = 0.5
但必须记录选择了什么权重，并在结果中可查。
后续可以通过超参搜索调整。
```

4. **建议增加一个"非法输出惩罚项"**：

```text
loss_penalty = lambda * ReLU(-beta_hat) + lambda * ReLU(-eta_hat)
```

防止模型输出物理非法的参数值。这比事后截断更好，因为梯度可以回传。

---

## 9. 对失败样本和异常样本统计的建议

1. **当前方案"失败样本不参与参数误差、但参与成功率分母"是正确的**。这是标准做法，保证了成功率指标的诚实性。

2. **建议增加"有效精度"指标**：

```text
effective_accuracy(metric) = metric_value * success_rate
```

这个指标同时反映精度和可靠性。例如：方法 A 的 MAE_beta = 0.1 但 success_rate = 0.8，方法 B 的 MAE_beta = 0.15 但 success_rate = 0.99。单纯看 MAE 方法 A 更好，但 `effective_accuracy` 下方法 B 可能更好。

3. **`mean_runtime_ms` 应该分别报告成功和失败样本的运行时间**。失败样本的运行时间可能更长（超时）或更短（快速检测到非法输入），混合在一起会误导。
