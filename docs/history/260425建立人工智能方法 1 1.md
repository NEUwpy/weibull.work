  ---                                                                                                                                        
  Phase 1: 目的与动机                                                                                                                        
   
  从 MDM 源码看到，δ 的核心作用是：                                                                                                          
                                                      
  梯度曲线 ∇(γ) - δ = 0  →  交点就是最优 γ  →  进而得到 β, η

  δ 的本质：它是一个阈值，决定在梯度曲线的哪个位置"切割"来找到 γ。δ 选得不同，交点位置不同，最终 β, η, γ 全部不同。

  问题：没有理论公式告诉用户"这个样本该用 δ=0.1 还是 δ=0.3"，只能靠经验或反复试。

  AI 的角色：学习"样本长什么样 → 该用什么 δ"的映射，替代人工选择。

  这部分你觉得理解对吗？有没有要补充的？

  ---
  Phase 2: 关系定义

  建立的映射：
  输入: [t1, t2, ..., tn]  （排序后的失效时间）
  输出: δ*  （最优偏移量）

  "最优"的定义：当前用 MSE(β,η,γ)，即让 MDM 估计出的三个参数尽量接近真实值。

  但这里有一个根本问题需要讨论：

  "最优"是相对于"真实参数"而言的。实际使用中我们不知道真实参数——如果知道就不用估计了。所以这个模块的本质是：

  ▎ 在蒙特卡洛模拟中（我们知道真实参数），学习"样本 → 最优 δ"的规律，然后把这个规律应用到真实数据上。

  这有一个隐含假设：模拟中学到的规律可以推广到真实场景。这个假设是否成立，取决于模拟参数空间是否覆盖了真实应用场景。

  ---
  Phase 3: 神经网络设计

  当前方案是 MLP，但我想讨论几个关键问题：

  问题 1：输入应该是什么？

  ┌─────────────────┬─────────────────────────────────────────────────┬──────────────┬──────────────────────────┐
  │      方案       │                      输入                       │     维度     │          优缺点          │
  ├─────────────────┼─────────────────────────────────────────────────┼──────────────┼──────────────────────────┤
  │ A. 原始排序值   │ [t1, t2, ..., tn]                               │ n            │ 简单，但数值范围差异大   │
  ├─────────────────┼─────────────────────────────────────────────────┼──────────────┼──────────────────────────┤
  │ B. 标准化排序值 │ 同上，零均值单位方差                            │ n            │ 消除尺度影响，当前方案   │
  ├─────────────────┼─────────────────────────────────────────────────┼──────────────┼──────────────────────────┤
  │ C. 统计特征     │ [mean, std, cv, min, max, range, skewness, ...] │ 固定（如 8） │ 维度固定，但丢失分布细节 │
  ├─────────────────┼─────────────────────────────────────────────────┼──────────────┼──────────────────────────┤
  │ D. B + C        │ 排序值 + 统计特征                               │ n + k        │ 信息更丰富               │
  └─────────────────┴─────────────────────────────────────────────────┴──────────────┴──────────────────────────┘

  当前方案是 B。但有一个问题：当 n 不同时，输入维度不同，所以必须按 n 分别训练模型。如果用 C，就可以统一一个模型。

  问题 2：为什么用 MLP？

  ┌────────────────┬──────────────────────┬──────────────────────┬───────────────┐
  │      架构      │         优点         │         缺点         │   适用场景    │
  ├────────────────┼──────────────────────┼──────────────────────┼───────────────┤
  │ MLP            │ 简单、训练快         │ 不感知样本的排序结构 │ 通用          │
  ├────────────────┼──────────────────────┼──────────────────────┼───────────────┤
  │ 1D CNN         │ 感知局部模式         │ 小样本量优势不明显   │ 长序列        │
  ├────────────────┼──────────────────────┼──────────────────────┼───────────────┤
  │ 统计特征 + MLP │ 维度固定，可统一模型 │ 需要手工设计特征     │ 需要跨 n 泛化 │
  ├────────────────┼──────────────────────┼──────────────────────┼───────────────┤
  │ Transformer    │ 感知全局关系         │ 复杂，数据量要求大   │ 大数据集      │
  └────────────────┴──────────────────────┴──────────────────────┴───────────────┘

  当前数据量只有 598 条，MLP 是合理选择。但如果后续扩展参数空间，可能需要重新考虑。

  问题 3：按 n 分别训练 vs 统一模型

  - 分别训练：每个模型简单，但需要维护多个模型
  - 统一模型：需要处理变长输入（padding/统计特征），但只需一个模型

  当前选了分别训练，这是对的（数据量小，分别训练更稳定）。

  路线 2 收敛判据

  路线 2 的迭代过程：

  δ₀ = 0.5（固定初始值）
  MDM(δ₀) → (β̂₀, η̂₀, γ̂₀)
  神经网络(β̂₀, η̂₀, γ̂₀) → δ₁
  MDM(δ₁) → (β̂₁, η̂₁, γ̂₁)
  ...

  收敛可以从几个角度判：

  方案 A：δ 稳定
  |δ_{k+1} - δ_k| < ε₁
  简单直接。问题：δ 的量纲是 [0.01, 0.50]，ε₁ 设多少？建议 ε₁ = 0.001（δ 范围的 0.2%）。

  方案 B：参数稳定
  |β̂_{k+1} - β̂_k|/β̂_k < ε₂ 且 |η̂_{k+1} - η̂_k|/η̂_k < ε₂
  更本质——我们关心的是参数估计是否稳定，不是 δ 本身。但需要两个参数同时满足。

  方案 C：综合（推荐）
  停止条件（满足任一）：
  1. |δ_{k+1} - δ_k| < 0.001  （δ 不再变化）
  2. k ≥ 10  （最大迭代次数，防止死循环）
  3. MDM 返回 no_intersection  （算法失败，回退上一步结果）
  简单、鲁棒、有保护。

  我的建议：方案 C。理由：
  - 条件 1 是主要判据，δ 稳定了说明找到了"不动点"
  - 条件 2 是安全网，防止震荡不收敛
  - 条件 3 是容错，MDM 本身可能无解
