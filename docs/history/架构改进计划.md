## P0 — 静默 fallback 返回错误结果

**问题**: AI/PSO/SVR/ANN 等方法在后端全部 fallback 到 WMLE，但前端不知道，用户会以为得到了正确结果。

**文件**: `python/main.py:86-97`

```python
"ai": WMLE, "pso": WMLE, "svr": WMLE, "ann": WMLE,
"construct_stat": WMLE, "mve": WMLE, "lsf": WMLE,
```

**方案**: 未实现的方法返回 501，不静默 fallback。前端展示"该方法尚未实现"。

**改动范围**:
- `python/main.py`: 区分"已注册但未实现"和"已实现"方法
- 前端: 处理 501 响应，展示友好提示

## P1-A — 定义算法基类 + 统一返回值

**问题**: `_template.py` 定义了函数接口，但实际所有方法都是类。`run()` 签名和返回值不统一。

**文件**: `python/methods/_template.py`, `python/methods/*.py`

| 方法 | run() 签名 | 返回 tuple 长度 |
|------|-----------|----------------|
| MLE | `run(trace=False)` | 5 |
| MMLE | `run(trace=False, variant='I')` | 5 |
| WMLE | `run(trace=False)` | 5 |
| MDM | `run(trace=False, offset=None, ...)` | 5 |
| LRE | `run()` | 4 |
| LSE | `run()` | 4 |
| MM | `run()` | 4 |
| PWM | `run()` | 4 |
| MPS | `run()` | 4 |
| Bayesian | `run()` | 4 |
| GreyGM11 | `run()` | 4 |

**方案**:
1. 创建 `BaseMethod` 基类，定义统一的 `run()` 签名
2. 创建 `MethodResult` dataclass，替代裸 tuple
3. 逐步迁移各方法类继承 `BaseMethod`

**问题**: `page.tsx`（计算器）和 `methods/[methodId]/page.tsx`（方法详情）各自独立实现了几乎相同的计算逻辑。

**重复代码**:
- `handleCalculate()` — 构建请求体、调用 API、处理响应
- `handleBatchCalculate()` — 批量计算
- `handleToggle3P()` — 2P/3P 切换
- `calculateMedianRanks` + `calculateWeibullParameters` 调用

**文件**: `src/app/page.tsx:379-448`, `src/app/methods/[methodId]/page.tsx:310-384`

**方案**:
1. 创建 `src/hooks/useWeibullCalculation.ts`
2. 封装状态管理（data, result, fitMode, is3P, isCalculating）
3. 封装方法（calculate, batchCalculate, toggle3P, updateParams）
4. 两个页面组件改用 Hook
