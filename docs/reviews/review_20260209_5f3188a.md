## 二、当前架构问题诊断 🏗️

### 问题 1：大量方法是"空壳" — fallback 机制掩盖了真相

```python
# main.py 中的 method_map：
"ai": WMLE, "pso": WMLE, "svr": WMLE, "ann": WMLE,  # 全部假的
"construct_stat": WMLE, "mve": WMLE, "lsf": WMLE,    # 全部假的
"mmle": MLE,  # 应该是修正版，但直接用了 MLE
"wlse": LSE, "eiv": LSE,  # 应该有不同实现
"lm": PWM, "tlm": PWM,    # 应该有不同实现
```

25+ 方法中，真正独立实现的只有约 10 个（MLE, WMLE, MDM, LRE, LSE, MPS, MM, PWM, GM11, Bayesian），其余全部 fallback。用户选了 PSO 实际跑的是 WMLE，这是一个信任风险。

### 问题 2：后端缺乏统一的返回协议

- `run()` 方法返回的是裸 tuple `(beta, eta, gamma, r2, converged)`
- 有的返回 4 个值，有的返回 5 个，main.py 要用 `len(res)` 来猜
- `trace_data` 有时是 list，有时是 dict（MDM 直接覆盖了 `self.trace_data`）
- 没有统一的错误码和状态报告机制

### 问题 3：前后端计算职责边界有模糊地带

`src/lib/weibull.ts` 中有 `calculateWeibullParameters()`（线性回归实现），虽然文档说"仅用于绘图"，但它实际上是一个完整的参数估计实现，存在被误用的风险。

### 问题 4：缺乏自动化测试

没有看到任何测试文件（tests/、__tests__/、*.test.ts、pytest）。对于一个数值计算平台，这是最大的隐患——改一个算法可能悄悄破坏另一个。

### 问题 5：数据模型扩展性受限

当前只支持**完全样本（complete sample）**的失效时间数据。WeibullBase.__init__ 直接把数据当作全部失效：

```python
self.data = np.array(sorted([x for x in data if x > 0]))
```

没有删失（censoring）标记、没有区间数据支持，这限制了向可靠性评估扩展的能力。

## 🟢 第一层：夯实基础（近期，1-3 个月）

### 1.1 补齐方法实现 — 消灭 fallback

优先级排序（按学术价值和实现难度）：

| 优先级 | 方法 | 难度 | 理由 |
|--------|------|------|------|
| P0 | MMLE（修正极大似然） | ★★☆ | 和 MLE 差异明确，Cohen & Whitten 公式清晰 |
| P0 | WLSE（加权最小二乘） | ★★☆ | 在 LSE 基础上加权重即可 |
| P0 | EIV（变量误差法） | ★★★ | 需要 Total Least Squares，但有现成库 |
| P1 | LM / TLM（L-矩/修剪L-矩） | ★★★ | 和 PWM 有本质区别，需要独立实现 |
| P1 | MVE / LSF | ★★★ | 构造统计量法，学术性强 |
| P2 | PSO / ANN / SVR | ★★★★ | AI 方法，正好衔接你的创新方向 |

### 1.2 统一后端协议

### 1.3 添加数值测试套件

```
python/tests/
├── test_mle.py          # 用已知参数的模拟数据验证
├── test_mdm.py
```

每个方法至少需要：

## 🟡 第二层：功能扩展（中期，3-6 个月）

### 2.1 扩展到可靠性评估体系

这是从"参数估计工具"升级为"可靠性分析平台"的关键一步。

需要新增的核心能力：

**新增模块：可靠性评估 (Reliability Assessment)**

```
├── 可靠度计算 R(t) = 1 - F(t)
│   ├── 点估计：给定时间 t，计算 R(t)
│   ├── 区间估计：R(t) 的置信区间（Fisher 信息矩阵 / Bootstrap）
│   └── 可靠寿命：给定 R，反求 t（如 B10 寿命）
├── 失效率分析 h(t) = f(t)/R(t)
│   ├── 浴盆曲线可视化
│   └── 失效率趋势判断（DFR/CFR/IFR）
├── MTBF / MTTF 计算
├── 删失数据处理
│   ├── Type-I 定时截尾
│   ├── Type-II 定数截尾
│   ├── 随机删失
│   └── Kaplan-Meier 估计
└── 多分布对比
    ├── 对数正态 vs Weibull vs 指数
    ├── AIC/BIC 模型选择
    └── 拟合优度检验（K-S, A-D, χ²）
```

**数据模型升级（这是前提条件）：**

```python
class ReliabilityData:
    """支持删失数据的统一数据模型"""
    times: np.ndarray          # 观测时间
    status: np.ndarray         # 1=失效, 0=删失
    censoring_type: str        # "none", "type1", "type2", "random", "interval"
    interval_bounds: tuple     # 区间删失的上下界（可选）
```

**前端新增页面建议：**

```
/reliability          → 可靠性评估主页
/reliability/life     → 可靠寿命计算器（输入 R → 输出 t）
/reliability/compare  → 多分布对比工具
/reliability/bathtub  → 浴盆曲线分析
```

### 2.2 方法对比与基准测试模块

这是你平台的独特价值——不只是用一个方法算，而是系统性对比所有方法：

**新增功能：方法竞技场 (Method Arena)**

```
├── 一键全方法计算：同一数据，25+ 方法同时跑
├── 结果排行榜：按 R², 偏差, 计算时间排序
├── Monte Carlo 模拟器：
│   ├── 设定真实参数 (β_true, η_true, γ_true)
│   ├── 生成 N 组模拟样本
│   ├── 每组用所有方法估计
│   └── 统计偏差(Bias)、均方根误差(RMSE)、覆盖率
└── 可视化：箱线图对比、偏差热力图
```

这个模块本身就是一个学术研究工具，可以直接用于论文中的方法对比实验。

## 🔴 第三层：AI 创新突破（中长期，6-12 个月）

这是你提到的最有价值的方向。我把它细化为三个子方向：

### 3.1 智能优化算法优化求解过程

核心思想：用元启发式算法替代传统数值优化（Nelder-Mead、L-BFGS-B），解决多峰、非凸问题。

**AI 优化层 (AI Optimization Layer)**

```
├── PSO（粒子群优化）
│   └── 场景：MLE 的似然函数多峰时，全局搜索最优解
├── DE（差分进化）
│   └── 场景：三参数同时优化，避免局部最优
├── GA（遗传算法）
│   └── 场景：离散化搜索空间中的组合优化
├── SA（模拟退火）
│   └── 场景：MDM 的 γ 搜索，跳出局部最优
└── 混合策略
    └── PSO 全局搜索 → Nelder-Mead 局部精化
```

**架构设计建议：**

```python
# 不是新建"AI方法"，而是作为现有方法的"优化器后端"
class OptimizationBackend:
    """可插拔的优化器"""
    SCIPY = "scipy"          # 默认：Nelder-Mead, L-BFGS-B
    PSO = "pso"              # 粒子群
    DE = "de"                # 差分进化
    HYBRID = "hybrid"        # PSO + Nelder-Mead

class MLE(WeibullBase):
    def run(self, optimizer="scipy", trace=False):
        if optimizer == "pso":
            result = self._optimize_pso(objective_func)
        elif optimizer == "hybrid":
            rough = self._optimize_pso(objective_func)
            result = self._optimize_scipy(objective_func, x0=rough)
        ...
```

这样用户可以在前端选择："用 MLE 方法 + PSO 优化器"，而不是把 PSO 当成一个独立的估计方法。

### 3.2 神经网络建立参数映射关系

这是你举的 MDM 例子的泛化——用 NN 学习"数据特征 → 最优超参数"的映射。

**AI 映射层 (AI Mapping Layer)**

**场景 1：MDM 的最优 offset 预测**
```
├── 输入特征：样本量 n, 样本均值, 样本方差, 偏度, 峰度, min/max
├── 输出：最优 offset 值
├── 训练数据：Monte Carlo 模拟 10000 组，每组穷举 offset 找最优
└── 模型：轻量 MLP (3层, 64-32-1)
```

**场景 2：方法推荐器**
```
├── 输入特征：同上 + 数据类型(完全/删失)
├── 输出：各方法的预期 RMSE 排名
├── 训练数据：大规模模拟对比实验
└── 模型：多输出回归 或 排序学习
```

**场景 3：初始值预测器**
```
├── 输入特征：样本统计量
├── 输出：(β₀, η₀, γ₀) 初始猜测
├── 价值：加速收敛，避免迭代发散
└── 模型：MLP 回归
```

**场景 4：置信区间快速估计**
```
├── 传统方法：Bootstrap 需要 1000+ 次重采样，很慢
├── AI 方法：训练 NN 直接预测置信区间宽度
└── 价值：实时交互体验
```

**架构建议：**

```
python/
├── methods/          # 传统方法（现有）
├── ai_models/        # 新增：AI 模型层
│   ├── offset_predictor/
│   │   ├── model.pt          # 训练好的 PyTorch 模型
│   │   ├── train.py          # 训练脚本
│   │   ├── predict.py        # 推理接口
│   │   └── generate_data.py  # Monte Carlo 数据生成
│   ├── method_recommender/
│   │   ├── model.pt
│   │   └── ...
│   └── initial_value_predictor/
│       └── ...
└── main.py           # API 中集成 AI 推理
```

### 3.3 新方法创新化快速验证平台

这是最高层次的愿景——把平台变成一个可靠性方法的实验台：

**创新验证平台 (Innovation Sandbox)**

核心理念：研究者提出新方法 → 平台自动评估 → 与现有方法对比

**工作流：**

1. 研究者上传 Python 实现（遵循 WeibullBase 接口）
2. 平台自动运行标准化测试套件：
   - 10 组标准案例数据
   - 1000 组 Monte Carlo 模拟（多种真实参数组合）
   - 边界条件测试（小样本、删失、β<1）
   - 计算效率基准
3. 自动生成评估报告：
   - 偏差(Bias)、RMSE、覆盖率
   - 与 MLE/MDM/WMLE 等基准方法的对比图
   - 优势场景识别（在哪些条件下新方法更优）
   - 可复现的实验配置
4. 一键集成到平台方法库

这个方向的学术价值极高——相当于为 Weibull 参数估计领域建立了一个 "benchmark suite"，类似于机器学习领域的 ImageNet 或 GLUE。

## 六、一句话总结

你的平台骨架极好（架构清晰、模块分明、可视化出色），但肌肉还不够（真实实现的方法不足、缺测试、数据模型受限）。近期应该先补肌肉（消灭 fallback、加测试、支持删失数据），然后再长翅膀（可靠性评估 + AI 增强）。AI 方向的设计思路非常好，关键是不要把 AI 当成独立方法，而是作为现有方法的增强层——智能优化器、参数映射器、方法推荐器——这样既有创新性，又能和现有 25+ 方法体系无缝融合。
