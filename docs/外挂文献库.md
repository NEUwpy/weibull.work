# 外挂文献库

软件负责解析、展示、筛选和问答取材，资料保存在独立文件库。未设置`WEIBULL_LIBRARY_ROOT`时，继续使用仓内`src/content`、`public`及`src/data/references.json`；设置后仅使用指定文献库，不与仓内内容拼接。算法说明、案例、提示词与研究结果仍按原位置管理。

## 格式

```text
literature/
├── library.json
├── content/
│   ├── 182-046-pdf原文.md
│   └── 182-046-pdf翻译.md
├── assets/
│   └── 182-046-图片/images/figure.jpg
├── references.json
└── export-manifest.json     首次导出的文件哈希清单
```

`library.json`固定为`{"schema_version":1}`。正文沿用[现有格式](../src/content/README.md)：Markdown加YAML表头，`title`必填，`tags`为字符串数组；新资料使用UTF-8。相同编号有译文时优先展示译文，只提供原文也可读。论文编号与`/library/<编号>`不变。

配图沿用`![说明](/182-046-图片/images/figure.jpg)`；软件将此网址指向所选库的`assets`，支持空格、中文及嵌套路径。只提供指定文献图片目录内的PNG/JPEG/GIF/WebP/SVG/AVIF/PDF，不公开整个挂载目录。PDF可作为配套文件放在该编号资源目录并使用普通链接打开；本轮未新增PDF阅读器。

`references.json`为来源编号到参考文献序号/目标编号的映射，例如`{"182-046":{"1":"182-088"}}`；没有映射时写`{}`。正文、配图和引用表均运行时读取；列表在请求时生成，导入新资料后刷新页面即可。已打开的正文可刷新页面查看修改。

## 初次导出与核验

在软件根运行，目标父目录须已存在，目标文献库目录须尚不存在；工具不会覆盖已有库，不修改源文件。

```powershell
node scripts/library-data.mjs export --source-root D:\weibull --destination D:\weibull-data\literature
node scripts/library-data.mjs check --root D:\weibull-data\literature --verify-export
```

`export`只复制编号正文、`<编号>-图片`目录和引用映射，不复制算法说明、案例、提示词、环境变量或科研材料。`--verify-export`逐个校验首次导出清单；之后有意编辑原文献时，旧清单会报告差异，不能将其当作当前库版本清单。新增资料可以不覆盖原资料地加入，并单独保存批次清单。文献库自身须备份；Git克隆软件不能恢复外挂资料。

## 新增资料

将待导入的`<编号>-pdf原文.md`、`<编号>-pdf翻译.md`和`<编号>-图片/`放在同一批次目录。例如`D:\incoming-papers`，然后运行：

```powershell
node scripts/library-data.mjs import --source-dir D:\incoming-papers --root D:\weibull-data\literature
node scripts/library-data.mjs check --root D:\weibull-data\literature
```

相同字节的重复文件跳过；任一同名不同内容冲突会在复制前终止整批，避免覆盖旧资料。本命令不自动合并引用映射，引用关系确认后编辑`references.json`再检查。上传文献时应先确认当前所选库；原`upload-to-weibull`技能默认写入软件仓，并不会自动识别外挂配置。外挂资料的新导入使用上面的独立目标工具，避免误写回软件仓。

## 启用与回退

本机可在启动进程前设置环境变量，或在本地忽略的`.env.local`添加一行，再启动/重启前端。不要设置为`NEXT_PUBLIC_`变量，不把本机路径写进构建配置。

```powershell
$env:WEIBULL_LIBRARY_ROOT = 'D:\weibull-data\literature'
npm run dev
```

配置必须是绝对路径，指定库不存在或缺格式文件时明确报错，不悄悄回退到旧库。回退时取消该环境变量或删除本地配置行并重启；本轮保留原仓内资料。已运行的其他服务不因磁盘新增库自动切换。`npm run build`不要求外部库在构建机存在；生产进程启动时选择挂载目录。

NAS使用独立的可选Compose文件，先把已核验库复制到NAS目录，在NAS配置`WEIBULL_LIBRARY_HOST_PATH`为该目录，再使用：

```bash
docker compose -f docker-compose.yml -f docker-compose.library.yml up -d --build
```

外挂卷为只读；需要更新资料时由宿主机导入，不由Web服务写入。默认Compose行为保持不变。本轮没有连接或部署NAS。挂载的是服务器上的目录，本机D盘路径不会自动出现在NAS，也不会自动同步。

## 数据边界

文献库与计算数据可同放在`weibull-data`根下，但分别配置、分别备份。科研论文草稿及程序继续由科研Git维护；正式实验CSV/汇总/manifest与冻结模型按课题记录。网站现场MC持久化、历史实验查询和模型外挂另行实施，本轮不改动其现有数据、结果或算法。
