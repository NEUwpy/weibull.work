# 部署与维护指南

## 技术路线

```
用户访问 weibull.work / api.weibull.work
              ↓
       Cloudflare CDN
              ↓
      Cloudflare Tunnel (cloudflared)
              ↓
    ┌─────────┴─────────┐
    ↓                   ↓
前端容器              后端容器
Next.js:3000         FastAPI:8001
```

**关键点：**
- 绿联 NAS 运行 Docker，无公网 IP
- Cloudflare Tunnel 提供外网访问 + HTTPS
- GitHub 托管代码，NAS 通过 git pull 更新

## 部署步骤

### 1. Cloudflare 配置

#### 1.1 域名托管
1. 登录 [Cloudflare Dashboard](https://dash.cloudflare.com)
2. 添加站点 `weibull.work`
3. 到域名注册商（阿里云/腾讯云等）修改 NS 为 Cloudflare 提供的地址：
   - `demi.ns.cloudflare.com`
   - `toby.ns.cloudflare.com`

#### 1.2 创建 Tunnel
1. 进入 **Zero Trust** 控制台（左侧菜单盾牌图标）
2. **Networks** → **Tunnels** → **Create a tunnel**
3. 选择 **Cloudflared** 连接方式
4. 命名为 `weibull`
5. 选择 **Token** 认证方式，保存 Token

#### 1.3 配置 Public Hostname（关键！）

**必须正确配置此步骤，否则会出现 530 错误**

1. 在 Tunnel 详情页，点击 **Public Hostname** 标签
2. 点击 **Add a public hostname**
3. 添加两条记录：

| Subdomain | Domain | Path | Type | URL |
|-----------|--------|------|------|-----|
| (留空) | weibull.work | (留空) | HTTP | frontend:3000 |
| api | weibull.work | (留空) | HTTP | backend:8001 |

**注意：**
- Type 必须选 **HTTP**（不是 HTTPS）
- URL 填容器名+端口，不带 `http://` 前缀
- Cloudflare 会自动创建对应的 DNS 记录

#### 1.4 验证 DNS 记录

配置完成后，去 **Cloudflare DNS** 页面检查，应该自动生成：

| Type | Name | Target | Proxy Status |
|------|------|--------|--------------|
| CNAME | @ | `[tunnel-id].cfargotunnel.co` | Proxied (橙色云朵) |
| CNAME | api | `[tunnel-id].cfargotunnel.co` | Proxied (橙色云朵) |

**重要：** Proxy Status 必须是 **Proxied**（橙色云朵），不能是 DNS only（灰色云朵）

### 2. NAS 准备

1. 启用 SSH（端口 22）
2. 安装 Docker 和 Docker Compose
3. 能访问外网（git pull 需要）

### 3. 部署到 NAS

```bash
# SSH 登录（从本地开发机）
ssh weipengyu@192.168.31.148

# 克隆项目
cd /share
git clone https://github.com/NEUwpy/weibull.work.git weibull
cd weibull

# 启动（首次约 5 分钟）
sudo docker-compose up -d --build

# 验证容器状态
sudo docker-compose ps
```

### 4. 验证部署

- https://weibull.work → 前端页面
- https://api.weibull.work/docs → API 文档（Swagger UI）

## 日常维护

### 快速命令（从本地执行）

```bash
# SSH 登录 NAS
ssh weipengyu@192.168.31.148

# 查看所有容器状态
sudo docker ps -a

# 查看日志
sudo docker-compose logs -f

# 更新部署
cd /share/weibull && git pull && sudo docker-compose up -d --build
```

### 更新流程

```bash
# 1. 本地开发完成后推送到 GitHub
git add .
git commit -m "描述修改内容"
git push

# 2. SSH 登录 NAS 更新
ssh weipengyu@192.168.31.148
cd /share/weibull
git pull
sudo docker-compose up -d --build
```

### 常用命令

| 命令 | 作用 |
|------|------|
| `sudo docker-compose ps` | 查看容器状态 |
| `sudo docker-compose logs -f` | 查看所有日志 |
| `sudo docker-compose logs -f cloudflared` | 查看 Tunnel 日志 |
| `sudo docker-compose logs -f frontend` | 查看前端日志 |
| `sudo docker-compose logs -f backend` | 查看后端日志 |
| `sudo docker-compose restart` | 重启所有服务 |
| `sudo docker-compose down` | 停止所有服务 |

### 只更新前端/后端

```bash
sudo docker-compose up -d --build frontend  # 只重建前端
sudo docker-compose up -d --build backend   # 只重建后端
```

## 故障排查

### 常见错误

| 错误代码 | 原因 | 解决方法 |
|----------|------|----------|
| **1016** | DNS 无法解析 | 检查 DNS 记录 Target 是否正确 |
| **530** | Tunnel 无法连接到源 | 检查 Public Hostname 配置 |
| **502** | 源服务未运行 | 检查 frontend/backend 容器状态 |

### 排查步骤

```bash
# 1. 检查容器是否运行
sudo docker ps -a

# 2. 检查 Tunnel 连接状态
sudo docker logs weibull-cloudflared --tail 50

# 3. 检查 Tunnel 配置是否正确加载
sudo docker logs weibull-cloudflared 2>&1 | grep -i "config"

# 4. 测试本地服务
curl -sI http://localhost:3000
curl -sI http://localhost:8001/docs

# 5. 检查 Docker 网络
sudo docker network ls
sudo docker network inspect weibull_weibull-network
```

### 从本地诊断 DNS

```bash
# 测试 DNS 解析
nslookup weibull.work

# 测试网站访问
curl -sI https://weibull.work

# 测试 API
curl -sI https://api.weibull.work/docs
```

### Tunnel 未连接

如果 Tunnel 容器运行但无法访问：

1. 检查 Token 是否正确（在 docker-compose.yml 中）
2. 检查 Public Hostname 配置
3. 重启 cloudflared 容器：
   ```bash
   sudo docker-compose restart cloudflared
   sudo docker logs weibull-cloudflared -f
   ```

### 前端/后端容器问题

```bash
# 查看容器日志
sudo docker logs weibull-frontend --tail 100
sudo docker logs weibull-backend --tail 100

# 重建容器
sudo docker-compose up -d --build frontend
sudo docker-compose up -d --build backend
```
